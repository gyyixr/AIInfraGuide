## 1. 能给位置编号，不等于模型会利用远处信息

把配置中的最大长度从8K改成128K，只改变一个输入约束。

模型可能没有见过这些位置、kernel可能走fallback、数据也可能没有真实长依赖。

所以长上下文训练必须同时回答四个问题。

| 层次 | 验收问题 |
|---|---|
| 配置长度 | tokenizer、模型和API是否允许输入 |
| 系统长度 | 目标shape能否完成前反向 |
| 训练长度 | 实际训练中出现过多少长样本 |
| 有效长度 | 远处证据是否真正改善任务表现 |

本篇从位置编码连接到训练课程。

CP和RingAttention解决跨卡计算与存储，不能替代位置泛化或数据学习。

## 2. RoPE先看一个二维平面

把一个head向量的通道两两配对。

每对通道构成二维向量，位置决定旋转角度。

对于位置p和频率$\theta$：

$$
R(p\theta)=
\begin{bmatrix}
\cos(p\theta)&-\sin(p\theta)\\
\sin(p\theta)&\cos(p\theta)
\end{bmatrix}.
$$

若原向量为$(x_0,x_1)$，旋转后：

$$
x'_0=x_0\cos(p\theta)-x_1\sin(p\theta),
$$

$$
x'_1=x_0\sin(p\theta)+x_1\cos(p\theta).
$$

旋转保持二维范数。

它把位置信息编码到方向，而不是直接给向量增加一个位置embedding。

### 2.1 多频率

常见RoPE频率形式为：

$$
\theta_i=b^{-2i/d},\quad i=0,\ldots,d/2-1.
$$

d表示参与旋转的维度，b是base。

不同通道对的频率不同，形成不同尺度的位置变化。

实现可能只旋转head的一部分维度，也可能采用不同配对顺序。

因此`rotary_percent`与interleaved规则也属于模型配置。

## 3. 相对位置性质的逐步推导

query位于m，key位于n，原向量分别为q和k。

旋转后的内积为：

$$
(R(m\theta)q)^T(R(n\theta)k).
$$

使用矩阵转置规则：

$$
=q^TR(m\theta)^TR(n\theta)k.
$$

旋转矩阵满足$R(a)^T=R(-a)$以及$R(a)R(b)=R(a+b)$。

所以：

$$
=q^TR((n-m)\theta)k.
$$

位置以相对差n-m进入该项。

这并不表示整个模型只依赖相对位置；边界、mask、输入内容及其他结构仍会影响结果。

## 4. 完整手算：旋转与平移

取：

```text
q = [1,0]
k = [1,0]
theta = π/4
m = 1
n = 3
```

query旋转为：

$$
q'=[\sqrt2/2,\sqrt2/2].
$$

key旋转为：

$$
k'=[-\sqrt2/2,\sqrt2/2].
$$

内积为$-1/2+1/2=0$。

相对位置公式也给出：

$$
q^TR(\pi/2)k=0.
$$

若两者位置都加10，差值仍为2，内积仍为0。

这就是共同平移不改变这对RoPE内积的含义。

### 4.1 长位置为什么仍可能出问题

虽然公式对任意整数位置定义良好，模型只在有限位置与数据分布上训练。

训练外的相位组合、attention logits与可区分性可能落入未学习区域。

“数学函数有定义”与“模型在该输入上有效”是不同命题。

## 5. Position Interpolation

假设旧训练长度为L，新长度为rL。

简单位置插值把新位置p映射为p/r。

等价地，所有RoPE频率都除以r：

$$
R((p/r)\theta_i)=R(p(\theta_i/r)).
$$

它把更长位置范围压回旧尺度。

但相邻token的相位差也缩小r倍。

因此局部区分能力与长范围覆盖之间存在权衡。

### 5.1 接着上面的手算

令r=2，相对位置差2变成1。

新的相对角度为$\pi/4$，内积为：

$$
\cos(\pi/4)=\sqrt2/2\approx0.7071.
$$

同一对内容、相同物理距离，位置插值改变了attention打分。

所以不能把插值当成只扩容而完全不改变原模型函数的操作。

## 6. 改base与统一位置缩放不同

取d=4、b=10000，两个频率为：

```text
theta0 = 1
theta1 = 0.01
```

若统一位置插值r=4，等效频率变成：

```text
[0.25, 0.0025]
```

若仅把base改为160000，则：

```text
theta0 = 1
theta1 = 1/sqrt(160000) = 0.0025
```

第二个频率相同，第一个频率不同。

因此“改base”和“所有position除以4”不是同一个变换。

### 6.1 不直接把这个例子称作完整NTK实现

NTK-aware、dynamic scaling等名称在不同实现中包含不同公式与边界处理。

上例只解释base变化如何产生频率相关缩放。

要复现具体方法，需固定论文公式、代码版本、训练长度和目标倍率。

不能只记录`rope_scaling=true`。

## 7. 为什么要按频率区分处理

某频率在旧训练长度L内转过的圈数为：

$$
N_i=\frac{L\theta_i}{2\pi}.
$$

高频通道可能已经见过许多周期，主要影响局部位置辨别。

低频通道在旧长度内可能只走过一小段相位，向外扩展更容易进入新区域。

这提供了分频处理的直觉。

YaRN等方案结合不同频率区域的插值策略与attention尺度调整。

本文不把教学用的线性混合式冒充YaRN完整算法；复现应按原论文与固定实现。

[YaRN原始论文](https://arxiv.org/abs/2309.00071)用于理解这种取舍，其结果仍需在新模型上验证。

## 8. 方法谱系：改变的对象是什么

| 方法方向 | 主要改变 | 仍需验证 |
|---|---|---|
| Position Interpolation | 统一位置尺度 | 局部分辨率与短任务 |
| 频率相关缩放 | 各通道频率 | 具体公式、base与动态边界 |
| YaRN | 分频插值及attention尺度 | 训练倍率、温度与数值 |
| PoSE | 训练时分段或跳跃位置 | 真实长依赖是否学到 |
| LongRoPE类 | 非均匀插值搜索 | 搜索成本与任务外推 |
| 混合位置层 | 不同层采用不同位置策略 | 架构与训练是否兼容 |

这些方法不自动降低dense attention的二次计算量。

位置策略负责表示，稀疏结构负责改变计算边集合，CP负责分布式执行。

三者可以组合，但需要分别做消融。

## 9. 位置覆盖与依赖覆盖

把128K个随机或无关token拼到一起，可以让kernel运行在128K。

使用很大的position IDs可以让模型接触远位置相位。

但任务答案若始终只依赖最后100个token，模型未必学到跨128K利用信息。

定义两种长度：

```text
输入长度：整个序列的token数
依赖距离：影响正确答案的证据与预测位置之间的距离
```

长上下文训练应记录两者的联合分布。

### 9.1 长数据例子

代码仓库任务可以要求同时理解远处接口定义、调用点和测试。

长文档任务可以要求合并跨章节的实体和时间线。

多文档任务可以包含互相冲突的证据，要求比较后回答。

单needle任务只要求找到一个显式字符串，难度与多证据推理不同。

## 10. 课程设计：从短到长不只是seq_len列表

一个训练阶段至少记录：

```text
checkpoint起点
长度桶及有效token占比
position recipe与版本
数据依赖类型
有效token预算
学习率和schedule
optimizer状态是否续用
CP与microbatch配置
短任务回归标准
```

下表是教学计划模板，不是某模型的推荐超参数。

| 阶段 | 长度桶 | 核心验证 |
|---|---|---|
| 基线 | 8K | 固定短任务与数值基线 |
| 扩展一 | 8K、32K | 位置变换是否损伤短任务 |
| 扩展二 | 8K、32K、128K | 长依赖与CP正确性 |
| 目标阶段 | 按任务需要加入更长桶 | 有效长度与长期成本 |

每次升级长度都重新检查attention backend、显存峰值与global有效token计数。

## 11. 长token占比小，计算占比仍可能很大

对于固定模型和dense attention，attention core每token成本大致与序列长度S成正比。

设短桶8K，长桶128K，长度比为16。

长桶只占10%有效token时，attention core计算占比约为：

$$
\frac{0.1\times16}{0.9\times1+0.1\times16}=0.64.
$$

即64%。

这没有计线性层，所以不是总训练FLOPs的精确占比。

但足以说明按token比例设计课程仍需结合长度成本。

### 11.1 样本比例更加容易误导

若两桶样本数相同，长桶token本身就多16倍。

attention core单样本计算又多约256倍。

因此“每10个batch插一个长batch”必须明确batch里样本数与有效token。

## 12. 与CP、packing和RNG的交界

CP切分后应使用对应全局位置，而不是每rank都从0开始编号。

文档独立packing则可能按文档重置position，这与CP rank边界无关。

两种边界不能混为一谈。

重计算需要恢复正确dropout RNG；长序列也可能改变随机调用数量。

若更改位置recipe后从旧checkpoint续训，应把recipe写入恢复配置并做固定batch对照。

只保存权重不足以复现位置变换。

## 13. 可运行的RoPE数值演示

```python
import math

def rotate(x, angle):
    c, s = math.cos(angle), math.sin(angle)
    return (x[0] * c - x[1] * s, x[0] * s + x[1] * c)

def dot(a, b):
    return sum(x*y for x, y in zip(a, b))

q = k = (1.0, 0.0)
theta = math.pi / 4
m, n = 1, 3
original = dot(rotate(q, m*theta), rotate(k, n*theta))
shifted = dot(rotate(q, (m+10)*theta), rotate(k, (n+10)*theta))
interpolated = dot(rotate(q, m*theta/2), rotate(k, n*theta/2))
assert abs(original) < 1e-12
assert abs(original - shifted) < 1e-12
assert abs(interpolated - math.sqrt(0.5)) < 1e-12
print(original, shifted, interpolated)
print("long attention cost share", 0.1*16/(0.9+0.1*16))
```

它验证旋转恒等式与教学成本比例，不验证真实长上下文能力。

真实实验需保留原始checkpoint、固定任务和相同推理设置。

## 14. 排障：是哪一层的“长”失败了

| 现象 | 第一处检查 |
|---|---|
| 输入长度直接被截断 | tokenizer、模板和API限制 |
| 位置增加后NaN | RoPE计算dtype、logit范围、recipe |
| 只有跨CP边界回答错 | global position与mask |
| loss正常但远处信息无效 | 依赖距离训练与任务捷径 |
| 长任务提升短任务下降 | 短样本配比、位置缩放和学习率 |
| 128K吞吐骤降 | dense二次项、backend fallback、CP通信 |

先确定失败层次，再调整位置base。

如果根因是attention fallback，修改RoPE参数不能解决吞吐问题。

## 15. 自测与详细答案

### 题1：RoPE为什么包含相对位置？

旋转矩阵满足转置等于反向旋转，两个位置旋转的乘积变成差值旋转。

因此内积中的位置项由n-m决定。

这只是该内积结构的性质，不是整个模型的全部行为。

### 题2：位置插值为什么可能损伤短任务？

所有位置间距的相位差都被缩小。

原模型用于区分邻近位置的打分模式会改变。

需要短任务回归和混合长度训练验证。

### 题3：增加base是否等价于所有位置除以同一个r？

不等价，base通过维度指数改变不同频率。

统一插值对所有频率乘相同系数。

d=4的手算已显示高频项可以不同。

### 题4：用短序列加很大position ID能完全代替长训练吗？

它可以增加位置相位覆盖，但没有自动增加真实长距离信息交互。

attention计算范围、干扰项和依赖结构仍不同。

应独立评估真实长任务。

### 题5：长token占比10%为什么可能消耗64%的attention计算？

128K相对8K每token attention core成本约16倍。

按加权计算量归一化得到0.1乘16除以0.9加1.6。

线性层与其他开销还需另计。

### 题6：CP rank本地序列从0编号是否正确？

通常不能按rank随意重置。

应保留同一逻辑序列的全局位置；只有模型定义的文档边界重置才有相应语义。

全局位置、mask和labels要联合验证。
