## 1. 反向次数不等于参数更新次数

显存装不下一个大 batch 时，可以把它拆成多个 microbatch，逐次计算并累加梯度，最后只更新一次参数。关键在于这些梯度必须对应同一个目标函数、同一份参数，且归一化权重正确。

把每个 microbatch 都 `optimizer.step()` 一次，并不能普遍得到相同结果，因为后续梯度来自更新后的参数，Adam 的动量和步数也不同。

本节先给出精确成立的条件，再讨论大模型中的 token mask、DDP、梯度裁剪和恢复状态。

### 1.1 三个计数器

| 计数器 | 何时增加 | 典型用途 |
|---|---|---|
| micro-step | 每处理一个 microbatch | 激活峰值、累积边界 |
| optimizer step | 实际应用一次参数更新 | Adam bias correction、学习率调度 |
| seen samples/tokens | 消费有效数据时 | 数据进度、训练预算 |

例如每轮累积 4 个 microbatch，处理 400 个 microbatch 后只执行 100 次 optimizer step。若学习率调度器错按 400 次前进，实际学习率轨迹就不同。

## 2. 有效 batch 中应该乘哪种并行度

等大 microbatch 时，设 $b$ 是每个 DP 副本每次的样本数，$D$ 是数据并行度，$K$ 是累积次数：

$$
B_{global}=bDK.
$$

TP 和 PP 的多个 rank 协同处理同一份样本，不能再乘入独立样本数。CP 沿同一序列拆分，也不是额外抽取更多样本。

举例：16 张卡，TP=2、PP=2、DP=4，每个 DP 副本的 microbatch=2，累积 8 次：

$$
B_{global}=2\times4\times8=64.
$$

若误用总 world size=16，会得到 256，相差四倍。对 MoE，dense DP 与 expert DP 的组含义还可能不同，应按数据复制关系推导，详见第 11.1 节。

### 2.1 样本数与 token 数也不同

8 条短回答与 8 条长回答具有相同样本数，但有效 token 数不同。选择“按样本平均”还是“按有效 token 平均”决定了目标，不是日志显示格式的区别。

以下主要研究全局有效元素均值：

$$
L=\frac{\sum_{d=1}^{D}\sum_{k=1}^{K}\sum_t
m_{dkt}\ell_{dkt}}{N},
\qquad N=\sum_{dkt}m_{dkt}.
$$

$m$ 是有效元素 mask，可以表示回答 token、非 padding 样本或其他明确定义的训练单元。

## 3. 等大 batch 的常见写法为什么能工作

若每个 rank 的每个 microbatch 都包含相同数量 $n$ 个有效元素，局部 loss 已按 $n$ 求均值，则：

$$
L=\frac1{DK}\sum_{d,k}L_{dk}^{mean}.
$$

普通 DDP 默认把各 rank 的梯度平均，因此每次 backward 使用 `local_mean / K`，累积 $K$ 次后即可对应全局目标。

```python
optimizer.zero_grad(set_to_none=True)
for microbatch in microbatches:
    loss = local_mean_loss(microbatch) / accumulation_steps
    loss.backward()
optimizer.step()
```

这段只展示数学缩放，没有完整处理通信、尾组和 mask。不要在有效元素数不同的场景照搬 `/ accumulation_steps` 后认为目标自动正确。

## 4. 不等长数据：局部均值的均值为什么错

两 rank 的有效 loss 分别为 `[1]` 和 `[3,3,3]`：

$$
L_{wrong}=\frac{1+(3+3+3)/3}{2}=2,
$$

而全局元素均值为：

$$
L_{global}=\frac{1+3+3+3}{4}=2.5.
$$

第一个 rank 的一个元素被赋予总权重 1/2，第二个 rank 的每个元素权重只有 1/6。正确目标中四个元素的权重都应为 1/4。

梯度也会按这些错误权重组合，不能通过仅修正日志平均值弥补参数更新偏差。

### 4.1 从 DDP 平均推导缩放系数

记第 $d,k$ 个 microbatch 的有效 loss 总和为 $S_{dk}$。希望最终梯度为：

$$
g=\frac1N\sum_{d,k}\nabla S_{dk}.
$$

DDP 对 $D$ 个 rank 的梯度取平均，因此每个 rank 应对以下局部目标反向：

$$
\widetilde L_{dk}=\frac{D}{N}S_{dk}.
$$

于是：

$$
\frac1D\sum_d\sum_k\nabla\widetilde L_{dk}
=\frac1N\sum_{d,k}\nabla S_{dk}.
$$

这里 $N$ 是**整次 optimizer step、整个 DP 组**的有效元素数，不是当前 microbatch 的数量。若训练库已做某些缩放、通信 hook 改了归约语义，需重新推导，避免再乘或再除一次。

### 4.2 两 rank、两次累积的数例

| rank | microbatch 0 有效数 | microbatch 1 有效数 | 总数 |
|---|---:|---:|---:|
| 0 | 2 | 1 | 3 |
| 1 | 3 | 2 | 5 |
| 全局 | 5 | 3 | 8 |

因此每个 microbatch 使用 `loss_sum * 2 / 8`。DDP 最后再除以 2，得到全部 8 个元素的均值梯度。

若某个 rank 某次 mask 全零，仍需维持一致的训练与通信流程；一个与模型计算图连接的零 loss 可以贡献零梯度，但不能让该 rank 无声跳过其他 rank 正在参与的 collective。若全局有效数为零，则应由所有 rank 协调跳过整个更新。

## 5. no_sync 的范围必须包含 forward

在同一批累积数据中，每次 backward 都 AllReduce 是正确但可能昂贵的。普通 DDP 可在前 $K-1$ 次使用 `no_sync()`，最后一次反向才同步累积梯度。

```python
from contextlib import nullcontext

optimizer.zero_grad(set_to_none=True)
for k, batch in enumerate(microbatches):
    context = model.no_sync() if k < len(microbatches) - 1 else nullcontext()
    with context:  # forward 和 backward 都在上下文中
        losses = per_element_loss(model(batch["x"]), batch["y"])
        loss_sum = losses[batch["mask"]].sum()
        scaled_loss = loss_sum * dp_world_size / global_valid_count
        scaled_loss.backward()
optimizer.step()
```

所有 rank 必须对齐最终同步时刻。一个 rank 提前走到 optimizer step，另一个还在 `no_sync()` 中，可能导致挂起或错误更新。

以上针对普通 DDP。FSDP 的参数驻留和梯度分片策略不同，`no_sync` 可能使完整梯度驻留、增加峰值；FSDP2 的同步控制 API 也不同。不能只看方法名称相似就跨框架照搬。

## 6. 一个标量例子：累积与分步更新

设模型为 $\hat y=wx$，损失 $\ell=(wx-y)^2/2$。两条数据为 $(x,y)=(1,0),(2,0)$，初始 $w=1$。

同一份权重下，两条梯度分别为 $g_1=1$、$g_2=4$。全 batch 均值梯度为 $2.5$，学习率 0.1：

$$
w_{new}=1-0.1\times2.5=0.75.
$$

梯度累积时各 loss 除以 2，依次得到梯度贡献 0.5 和 2，最后只 step 一次，同样得到 0.75。

如果每个样本都更新一次，即便每次也把 loss 除以 2：

1. 第一条使 $w=1-0.1\times0.5=0.95$。
2. 第二条梯度为 $4\times0.95/2=1.9$，最终 $w=0.76$。

结果不同，因为第二条梯度在 0.95 处计算。若用 AdamW，还多了动量、bias correction 和 weight decay 次数的差异。

## 7. 裁剪、缩放和权重衰减的位置

### 7.1 累积后再计算全局 norm

假设两个梯度贡献为 $g_1=(3,0)$、$g_2=(0,4)$，合计 $g=(3,4)$，norm=5。阈值设为 2：

$$
g_{clip}=g\frac25=(1.2,1.6).
$$

如果每个 microbatch 先各自裁剪，得到 `(2,0)` 和 `(0,2)`，合计 `(2,2)`，方向和 norm 都不同。

因此常见目标是：完成全部累积和所需归约，再对最终梯度做一次全局 norm clipping。分片梯度需对平方和做相应跨组归约；不能把每片各自的 norm 当作整个模型 norm。

### 7.2 FP16 loss scaling 的顺序

使用 FP16 GradScaler 的典型逻辑为：

```text
清梯度 → 多 microbatch 的 scaled backward
→ 完成梯度同步 → unscale（一次）
→ global norm clip → scaler.step → scaler.update
```

若优化器更新因溢出被跳过，scheduler 和 step 计数如何前进需要显式约定。不要裁剪仍带 loss scale 的梯度，否则阈值等效改变。

BF16 的指数范围减少了 FP16 类溢出压力，但有效位数较少；是否使用 scaler、FP32 梯度累积和 master weights，要看具体设计，详见第 8.1 节。

### 7.3 AdamW 只更新一次

一次 optimizer step 的 decoupled weight decay 含有类似 $(1-\eta\lambda)w$ 的项。对同一大 batch 拆成 $K$ 次 step，会应用多次 decay，因子变成相应乘积，不能只按 loss 除以 $K$ 就补偿回来。

Adam 的一阶、二阶状态和 `step` 也应与实际 optimizer 更新次数一致。有效 batch 变大后，线性缩放学习率只是某些设置中的经验规则，必须用固定任务和训练预算验证。

## 8. 梯度累积不总等价于真正大 batch

成立条件至少包括：

- 参数在累积窗口内不更新。
- loss 可按所定义的样本或 token 权重分解。
- 归约、缩放、裁剪、正则化的顺序一致。
- 没有依赖整个 batch 统计量而被切分改变的算子。

BatchNorm 的统计量会随 microbatch 划分而变化；对比学习的跨样本负例、某些全 batch 正则或排序目标也不能只靠累积参数梯度重现。Dropout 随机数分配和浮点累加顺序可能产生数值差异，即便目标在数学上等价。

`labs/distributed/ddp_lab.py` 使用两个真实 CPU/Gloo 进程和 float64 线性模型，正是上面 3/5 个有效元素的例子。它同时计算单进程全局目标作为 oracle。

| 检查 | 结果 |
|---|---:|
| 正确缩放的最大梯度误差 | $1.11\times10^{-16}$ |
| 错误局部均值平均的梯度偏差 | 约 $0.0620833$ |

## 10. 自测与参考答案

**1. TP=4、DP=2、microbatch=3、累积=5，有效样本 batch 是多少？** $3\times2\times5=30$，TP 不增加独立样本数。

**2. 最后一个累积窗口只有 2 个 microbatch，却按配置 4 去除，会怎样？** 等大情况下梯度被缩小一半；应使用实际窗口和目标分母，并让所有 rank 对齐边界。

**3. 为什么正确缩放要乘 DP world size？** 普通 DDP 随后会平均梯度；局部 loss 的 $D/N$ 恰好抵消该 $1/D$，留下全局元素均值的 $1/N$。

**4. checkpoint 恰好保存于累积一半，仅模型和 Adam 状态够吗？** 若要精确从窗口中间继续，还缺已累积梯度、micro-step、数据游标、分母和随机状态。常见更简单策略是在完整 optimizer step 边界保存，或明确重放整个窗口。
