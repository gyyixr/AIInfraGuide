## 📖 本章概述

长序列的难点不只是“token 多了”。同一个样本的 token 必须相互注意，局部切分后仍要得到与完整 Attention 一致的结果；与此同时，算子计算、激活保存、KV 通信和因果负载都在增长。

本章把三个层次分开：**FlashAttention 改变单卡 Attention 的中间存储方式**；**上下文并行改变多卡上的序列布局与通信**；**长序列训练工程保证位置、标签、mask、随机数和 loss 归约仍然正确**。

原始 Attention 可以物化平方大小的分数矩阵，现代 fused attention 通常避免它；因此不能把“Attention 计算随序列平方增长”直接替换成“所有实现的激活显存也必然平方增长”。

## 2. 先固定记号

- $B$：一个数据并行副本处理的序列数。
- $S$：全局序列长度，CP 切分之前的长度。
- $H_q,H_{kv}$：Query 与 KV head 数。
- $d$：每个 head 的维度，常见隐藏宽度为 $H_qd$。
- $C$：context parallel degree。
- $w$：每个通信元素的字节数。

不要将 $S/C$ 当成模型的最大上下文长度，也不要把 $C$ 个 rank 当成 $C$ 份独立训练样本；它们可能正在协作处理同一条序列。

## 3. 从张量布局辨认并行方式

| 方法 | Attention 前后主要布局 | 需要交换什么 |
|---|---|---|
| Megatron TP 配套 SP | 非 Attention 等区域的序列激活分片，与 TP 配合 | TP 组中的 gather/scatter 或等价变换 |
| Ring 风格 CP | 每 rank 保持局部 Q，逐步获得不同 KV 块 | KV 块及反向所需梯度信息 |
| AllGather 风格 CP | 局部 Q + 聚合的完整 KV | KV AllGather，反向配套归约 |
| Ulysses 风格 | 序列分片 → 每 rank 完整序列的一部分 heads → 序列分片 | 前后 All-to-All 布局转换 |

“Sequence Parallel”在不同项目中含义不同。本文说 SP 时特指第 6 章的 Megatron TP 配套方案；Ulysses 论文也使用 sequence parallelism 一词，因此应比较张量布局，而不是只比较缩写。

## 4. 三个必须修正的直觉

**第一，FlashAttention 不会把精确 dense attention 的计算改成线性。** 它减少分数矩阵的物化和 HBM 往返；全连接 QK/PV 的计算量仍随 $S^2$ 增长。

**第二，Ulysses 的通信并非在固定设备数下与序列长度无关。** 传输张量含有序列维，字节量会随 $S$ 增长。论文讨论的是序列长度和设备数按比例增长时，特定每 rank 通信量的弱缩放性质。

**第三，把 KV 分成多个块后，各块独立 softmax 的输出不能简单平均。** 每块有自己的归一化常数，必须用全局等价的 online softmax 或 log-sum-exp 合并。

## 5. CP 与已有并行维度怎样组合

在一个明确采用正交 dense 布局的例子中：

$$
N_{GPU}=D\times P\times T\times C,
$$

分别表示 DP、PP、TP、CP。这个式子只描述该布局；MoE 的 EP 与数据并行子维度存在实现相关关系，不能在所有系统里再机械乘上 EP。

CP 切输入和部分激活，并不单独切掉每个 rank 的全部参数。若同一参数在 CP 成员间复制，参数梯度还要合并对应序列分片的贡献；具体通信由后端的参数/梯度分组负责。

更大的 CP 也不是总更快：局部计算变短、通信和调度相对成本增大，短序列可能失去收益。应按实际长度分布和拓扑测量。

## 6. 本章实验与证据边界

仓库 `labs/distributed/mechanics_lab.py` 含 online softmax 分块合并的数值检查。它可以验证：

- 分块大小改变时，结果仍与全局 softmax 一致。
- 分数很大时，减去 running maximum 仍能稳定求值。
- 简单平均块内结果通常得到错误答案。

该脚本是单进程数学模拟，不是 GPU RingAttention kernel，也不验证 NCCL 环传、通信重叠、长序列 backward 或生产吞吐。真实多卡验证路径放在第 9.2 节。

## 7. 学习验收

1. 给定 $B,S,H_q,H_{kv},d$，分别计算朴素 score、QKV 和输出的字节数。
2. 画出 Ulysses 两次布局变换，说明为何 GQA 的 KV heads 也会限制分片。
3. 给两个 score/value 块，手算其全局 softmax 结果，并指出局部平均的错误。
4. 说明 causal mask、全局 position ID 和跨分片 next-token label 如何保持正确。
5. 区分单进程分块等价、真实多卡前向等价、backward 等价与性能证据。

**参考答案方向**：9.1 给出完整张量账本和布局；9.2 给出环传表与三个逐步验算例。跨 rank 结果正确不仅依赖通信完成，还依赖“传的是同一逻辑序列、同一位置和同一目标”。
