## 1. 一条通过的needle测试能证明什么

在10万token文本中插入一句“密码是1234”，然后要求模型找出密码。

通过说明模型在这个模板、位置和推理设置下能够检索显式信息。

它没有证明模型能联合多个远距证据、处理冲突、理解代码依赖或完成长推理。

如果问题原文与证据有高度词汇重合，任务还可能主要依赖表面匹配。

因此有效上下文应由一组明确任务定义，而不是由最大输入长度定义。

## 2. 把“有效长度”写成验收函数

设模型在任务族j、长度S、证据位置p、依赖距离d上的得分为：

$$
A_j(S,p,d).
$$

设各任务最低要求为$\tau_j$。

可以把有效长度定义为在约定测试分布与置信要求下满足所有关键门槛的最大S。

这是一种工程定义，不是所有论文共用的唯一标准。

必须同时公布：

```text
任务集合与版本
采样分布
长度与位置范围
成功阈值
统计不确定性
推理精度、RoPE、kernel与解码设置
```

只公布一个长度数字会丢失这些条件。

## 3. 评测矩阵的六个维度

| 维度 | 为什么影响结果 |
|---|---|
| 输入长度 | 干扰规模、成本与截断风险 |
| 证据位置 | 起始、中间、末尾可能表现不同 |
| 依赖距离 | 从证据到答案位置的跨度 |
| 证据数量 | 单检索与多步聚合不同 |
| 词汇重合 | 显式匹配与潜在关联不同 |
| 输出长度 | 长生成可能积累额外错误 |

再按领域区分代码、文档、日志、对话和agent轨迹。

不同领域不能仅靠同一个synthetic模板代表。

## 4. 基准如何互补

| 基准方向 | 主要问题 | 仍不足以单独说明 |
|---|---|---|
| RULER | 检索与组合任务随长度变化 | 全部真实业务能力 |
| HELMET | 多种真实应用与可比较评测 | 特定企业私有工作负载 |
| NoLiMa | 减少显式词汇重合后的关联 | 所有多跳推理 |
| LongBench v2 | 长文档复杂理解与推理 | 训练数据无污染的自动保证 |
| InfiniteBench | 超长任务组合 | 任意模型配置均可公平直接比较 |

[RULER论文](https://arxiv.org/abs/2404.06654)明确指出简单needle检索只覆盖浅层长上下文能力。

本篇不引用某模型的最新排行榜分数，避免把不同版本与设置混在一起。

## 5. 四种必要对照

### 5.1 Full context对oracle evidence

oracle只提供人工确认的必要证据。

若oracle也失败，可能是推理或输出任务本身困难。

若oracle成功而完整上下文失败，才更支持干扰、检索或长距离利用的问题。

### 5.2 Full context对RAG

RAG先检索少量片段再生成。

比较时要同时记录检索召回率、输入token、延迟与任务成功率。

不能把RAG漏检全部归因于生成模型。

### 5.3 原顺序对位置扰动

保持证据内容不变，将其移动到不同位置。

如果结果随位置大幅变化，说明有效利用并不均匀。

移动时应防止意外改变上下文语义，例如时间线顺序。

### 5.4 长任务对短任务回归

长度扩展可能损伤短上下文能力。

因此同时保留旧模型短任务基线与相同推理设置。

只看长任务提升无法评估整体迁移是否值得。

## 6. 完整手算：诊断一个长度断崖

假设某任务在三个设置下各测100题：

| 设置 | 正确题数 |
|---|---:|
| 8K完整上下文 | 90 |
| 128K完整上下文 | 60 |
| 128K对应oracle证据 | 88 |

长上下文相对短上下文下降30个百分点。

oracle与长完整上下文相差28个百分点。

这支持“长输入中查找或利用证据存在问题”的候选解释。

但不能仅凭这组均值排除题目难度、模板变化或评测随机性。

应尽量使用同一题的配对设置，并记录逐题结果。

### 6.1 为什么配对更有用

假设60题在两种设置都正确，28题只有oracle正确，12题都错。

这比只知道60%和88%提供更多信息。

如果另有很多题只在完整上下文正确，就说明上下文也提供了额外支持。

逐题迁移矩阵帮助拆分检索与推理因素。

## 7. 小样本不确定性

100题答对80题，点估计为0.8。

简单二项标准误差约为：

$$
SE=\sqrt{0.8\times0.2/100}=0.04.
$$

粗略正态区间为$0.8\pm1.96\times0.04$，即约[0.7216,0.8784]。

但接近0/1或样本量小时，简单正态区间表现不好。

可以使用Wilson区间或适合任务结构的bootstrap。

### 7.1 Wilson公式

设样本量n、比例$\hat p$、z=1.96：

$$
c=\frac{\hat p+z^2/(2n)}{1+z^2/n},
$$

$$
h=\frac{z\sqrt{\hat p(1-\hat p)/n+z^2/(4n^2)}}{1+z^2/n}.
$$

区间为$[c-h,c+h]$。

它仍假设合适的独立二项观察。

如果同一个文档生成很多高度相关问题，应按文档或任务簇处理不确定性。

## 8. 稀疏attention改变了哪些边

dense causal attention允许query i查看所有j不大于i的key。

稀疏attention只保留某个边集合$\mathcal E$。

$$
y_i=\sum_{j\in\mathcal E_i}
\frac{e^{q_i^Tk_j/\sqrt d}}{\sum_{u\in\mathcal E_i}e^{q_i^Tk_u/\sqrt d}}v_j.
$$

softmax在被选边集合内重新归一化。

因此删边一般会改变输出，不是与dense数学等价的纯实现优化。

FlashAttention保留原边集合，稀疏attention改变边集合，两者应分清。

## 9. 常见稀疏模式

| 模式 | 优点 | 风险 |
|---|---|---|
| Sliding window | 连续访问、kernel规则 | 远距依赖需跨层传播 |
| Global tokens | 保留少量全局连接 | 全局token容量与瓶颈 |
| Dilated或random | 扩大覆盖范围 | 任务依赖未必匹配 |
| Block routing | 较规则的块级计算 | 路由漏选与块粒度浪费 |
| Token selection | 更细粒度选择 | 索引、gather与负载复杂 |
| 压缩加选择加局部 | 多尺度信息结合 | 分支计算与融合复杂 |

NSA、MoBA与DSA属于不同设计，不能把它们统一称作同一个top-k实现。

具体训练与分布式能力要按各自论文和代码核对。

## 10. 稀疏成本的完整手算

设序列长度$S=65536$。

每个query保留512个局部key，再选8个大小128的远端block。

若暂时忽略重叠与边界，则每query最多：

$$
512+8\times128=1536
$$

条边。

边数上界近似$65536\times1536=100,663,296$。

dense完整方阵边数为$65536^2=4,294,967,296$。

比值约42.67。

若与真正跳过上三角的dense causal比较，后者约一半，理论边数比约21.33。

### 10.1 为什么不能宣布快21倍

还需支付：

- 索引器或router计算。
- 选中block/token的gather。
- 非规则访存与tile填充。
- load balance与同步。
- backward与索引训练。
- CP环境下远端KV定位与通信。

此外真实选中边可能与局部窗口重叠，应按并集计数。

有效边减少不等于kernel时间同比下降。

## 11. 选边质量与系统吞吐要联合评测

可记录两组指标：

```text
质量：证据边召回、任务得分、长短回归、训练稳定
系统：实际pairs、索引时间、gather字节、kernel效率、通信长尾
```

如果稀疏方法把必要远程证据漏掉，增加训练吞吐未必降低time-to-quality。

如果选边质量好但每步索引成本巨大，也可能不适合目标长度。

对照应固定总训练预算或明确报告预算差异。

## 12. 滑窗的跨层传播直觉

单层窗口宽度w，只能直接连接有限邻域。

多层可以通过中间token逐步传播信息。

在非常简化的局部链模型中，L层的可达距离量级随Lw增长。

但“图上可达”不等于信息能无损保存和完成推理。

残差、归一化、容量和干扰都会影响实际利用。

因此滑窗模型仍需远距任务验证。

## 13. 混合递归层为何改变通信对象

考虑简单线性递归：

$$
h_t=ah_{t-1}+bx_t.
$$

它保留固定大小状态，不需要对每个历史token显式读取KV。

若按sequence分段，后一段可能只需要前一段的边界状态。

这与RingAttention交换KV blocks的通信对象不同。

真实SSM或线性attention的状态维度与训练scan更复杂，不能用标量递归替代完整实现。

### 13.1 完整手算

令a=0.5、b=1、h0=0，输入为[1,2,3]。

```text
h1 = 0.5*0 +1 =1
h2 = 0.5*1 +2 =2.5
h3 = 0.5*2.5+3=4.25
```

如果第一段处理前两个token，只需把边界h2=2.5交给第二段，就能算出h3。

但这说明的是该线性递归的状态充分性，不证明它具备dense attention相同的内容寻址能力。

## 14. Scan的组合规律

把一段递归写成仿射变换：

$$
h_{out}=Ah_{in}+b.
$$

先执行$(A_1,b_1)$再执行$(A_2,b_2)$，合成后为：

$$
(A_2A_1,\;A_2b_1+b_2).
$$

该组合具有结合性，可用于并行scan的设计。

真实模型可能有输入相关系数、矩阵状态和数值范围问题。

需要检查训练反向和分布式边界，而不只看推理状态大小。

## 15. 混合架构的比较口径

比较dense、稀疏、递归与混合模型时至少固定或报告：

| 维度 | 必须说明 |
|---|---|
| 数据 | 同样来源、tokenizer与有效token |
| 计算 | 同样FLOP预算或差异 |
| 参数 | 总参数、激活参数、状态大小 |
| 训练 | optimizer、schedule、长度课程 |
| 任务 | 长短能力与不同依赖结构 |
| 系统 | 硬件、kernel、精度、通信 |
| 服务 | prefill、decode、cache与延迟 |

只比较渐近复杂度会忽略常数和质量。

只比较单一检索任务会忽略推理与短任务能力。

## 16. CPU核对程序

```python
from math import sqrt

n, successes, z = 100, 80, 1.96
p = successes / n
denom = 1 + z*z/n
center = (p + z*z/(2*n)) / denom
half = z * sqrt(p*(1-p)/n + z*z/(4*n*n)) / denom
print("Wilson interval", center-half, center+half)

S, window, blocks, block_size = 65536, 512, 8, 128
sparse_upper = S * (window + blocks * block_size)
causal_dense = S * (S+1) // 2
print("pair ratio", causal_dense / sparse_upper)

h = 0.0
states = []
for x in [1, 2, 3]:
    h = 0.5*h + x
    states.append(h)
assert states == [1.0, 2.5, 4.25]
print(states)
```

这些是统计与算法关系检查，不包含模型推理、真实评测集或稀疏kernel测量。

## 17. 故障定位

| 现象 | 优先检查 |
|---|---|
| 所有超长题都快速失败 | 输入截断与输出预算 |
| 中间证据特别差 | 位置分布、RoPE与任务难度 |
| oracle也失败 | 基础推理、答案格式或评测器 |
| 稀疏后速度未升 | 索引、gather、tile和通信 |
| 稀疏检索正确但聚合失败 | 多证据召回与跨层信息路径 |
| 递归层跨rank结果错 | 边界state、scan组合顺序与dtype |

## 18. 自测与详细答案

### 题1：单needle通过是否证明有效长度达到1M？

只能证明该模板条件下的检索成功。

还需多证据、位置、低词汇重合和真实任务评测。

有效长度应带任务与阈值定义。

### 题2：oracle对照的作用是什么？

它减少检索与干扰因素，帮助判断是否基础推理就失败。

oracle成功而完整输入失败支持长输入利用问题，但仍需配对与控制变量。

### 题3：稀疏attention是否与dense精确等价？

一般不等价，因为删除边改变softmax归一化与可访问内容。

它需要质量与训练验证。

FlashAttention则主要改变执行和中间存储。

### 题4：边数减少21倍能推出加速21倍吗？

不能，索引、访存、负载不均、通信和backward会占成本。

实际执行pairs也可能因tile高于有效pairs。

应测端到端时间和质量。

### 题5：固定大小递归状态是否等于无限上下文记忆？

不等于，状态容量有限，信息可能被压缩或遗忘。

能持续处理输入只说明计算接口可延伸。

有效记忆仍需任务检验。

### 题6：100题80%准确率能精确区分另一模型82%吗？

通常不能仅凭点估计下结论。

应看置信区间、配对差异和更多样本。

同源题目相关性也要进入统计设计。
