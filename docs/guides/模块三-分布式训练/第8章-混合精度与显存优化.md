## 📖 本章概述

把模型分到多卡之后，每张卡仍然可能装不下。此时必须回答：哪些状态常驻、哪些激活为反向而保留、哪些通信 buffer 只短暂出现，以及数值精度能在哪些位置降低。

本章围绕两条完整链路展开：**从前向到优化器更新的数值链路**，以及**从张量创建到最后一次使用的显存生命周期**。前一条解释为什么“全模型转 BF16”不是完整的混合精度方案；后一条解释为什么少存几份激活不一定等于峰值显存同比下降。

|---|---|---|

| 8.2 激活重计算与显存生命周期 | 哪些中间值值得重算，峰值为何出现在意外位置 | 分段 checkpoint 推导、峰值账本、带 Dropout 的前向/梯度一致性实验 |

## 2. 六个精度问题不能合并成一个

| 层次 | 应记录的内容 | 容易混淆的说法 |
|---|---|---|
| 参数存储 | FP32 参数，还是 BF16 工作副本 | 参数是 BF16，所以所有计算都是 BF16 |
| 算子输入与输出 | Linear、归一化、softmax 各自 dtype | 打开 autocast，所有算子都自动降精度 |
| 算子内部归约 | GEMM/attention 中间累加精度 | 输出 BF16，内部一定逐项 BF16 相加 |
| 梯度累积 | 每个 microbatch 梯度与跨批 buffer 的 dtype | 前向 BF16，所以 `.grad` 必然 BF16 |
| 参数更新 | FP32 参数本体或独立 master weights | 每个混合精度方案都要额外一份 master |
| 优化器状态 | `exp_avg`、`exp_avg_sq` 的实际 dtype | Adam 自动把任意低精度参数的状态升到 FP32 |

第 8.1 节会分别展示 PyTorch autocast 路径和显式低精度参数路径，并给出 CPU 可运行检查。框架名称和配置值不能代替对实际张量的检查。

## 3. 先解释数值边界，再讨论速度

FP16 与 BF16 都占两个字节，但指数与有效位分配不同。FP16 的最大有限值是 65504；BF16 的指数范围接近 FP32，但尾数更粗，最大有限值也并非与 FP32 完全相同。

Loss scaling 主要保护低幅度梯度。FP32 参数更新和累积状态保护的是许多小量跨时间累加的过程。二者解决的数值问题不同，不能互相替代。

本章的 BF16 例子从权重 1 开始，每步减 0.001：直接写回 BF16 可以连续多步不动；若保留 FP32 更新轨迹，第二步转换出的 BF16 工作副本就会改变。这比只说“高精度更稳”更容易检查。

FP8 等方案还需要 scale、格式、算子支持和状态策略。低位宽不意味着整个训练显存减半，也不保证端到端吞吐翻倍；应分别测计算、通信和数据等待。

## 4. 梯度累积改变时间安排

在等大小微批、相同损失归约的假设下：

$$
B_{\mathrm{global}}=B_{\mathrm{micro}}\times K\times D.
$$

这里 $D$ 是处理不同样本的数据并行副本数，不能无条件替换成整个 `world_size`；TP、PP、CP 成员可能共同处理同一批样本。

每个微批 loss 除以 $K$ 只在微批权重一致时成立。长短序列的有效 token 数不同，必须先决定优化目标是样本平均还是 token 平均，再设置分母。

梯度累积主要降低同时驻留的激活量。参数、完整梯度 buffer 和 Adam 状态通常不会因为把大 batch 拆成小 batch 就按 $1/K$ 缩小。

## 5. 重计算的两个常见误解

**误解一：每个 Transformer Block 都做 checkpoint，就自动得到 $O(\sqrt L)$ 激活显存。** 每个 block 都保留输入时，边界输入数量仍随层数 $L$ 线性增长，只是大幅减少了 block 内部保存量。平方根关系来自特定的分段模型和最优段长，不能省略假设。

**误解二：完整重算只增加 33% 的前向计算。** 若原来前向成本是 $F$、反向近似 $2F$，新增一次前向是把总成本从 $3F$ 变成 $4F$，即总训练计算约增 33%，而前向工作量近似翻倍。

实际时间还受 early-stop、选择性保存、kernel、通信重叠和 batch 调整影响。第 8.2 节会把这些假设逐项写出来。

## 6. 显存优化按对象选择

| 显存对象 | 可用方向 | 不应期待的效果 |
|---|---|---|
| 参数、梯度、优化器状态 | 分片、精度策略、CPU offload | checkpoint 激活自动切掉 Adam 状态 |
| 为反向保留的激活 | 重计算、小 microbatch、SP/CP | `empty_cache()` 释放仍被引用的激活 |
| 临时工作区 | 算子/布局/分块选择 | 只看参数大小就预测峰值 |
| 预取与通信 buffer | 控制并发预取和 bucket | 单项最大值相加必定等于实际峰值 |
| 生成 KV cache | 推理调度或阶段释放 | 与训练激活 checkpoint 是同一对象 |

## 7. 学习验收

1. 写出一个训练配置的参数、梯度、主权重、两个 Adam 状态 dtype，不依赖默认值猜测。
2. 手算两个微批合并的梯度，再解释为什么 FP32 主权重能保留 BF16 看不见的更新。
3. 给定 $L$ 层、段长 $k$，推导简化 checkpoint 保存量为什么含 $L/k+k$。
4. 用完全相同的参数、输入和 RNG 状态比较有无 checkpoint 的输出与梯度。
5. 给一次 OOM 标出发生阶段，并区分 live tensors、allocator reserved 和进程总显存。

**参考答案方向**：第 1、2 项见 8.1 的数值链路；第 3、4 项见 8.2 的分段模型和代码；第 5 项必须依据时间线与实际内存观测，不能仅靠“模型参数量乘常数”。
