## 1. 为什么数据系统会改变训练目标

假设有两份文本：一篇10000 token的教材和一条100 token的论坛回复。

如果按文档等概率抽样，每次抽到教材和回复的概率各一半，但长期输入token中教材约占99%。

如果先把两者切成同长样本，再按样本等概率抽样，得到的是另一种抽样过程。

如果还把回复中的一半token设为无效标签，参与loss的分布又会变化。

所以“数据混合50:50”必须说明是文档、样本、原始token还是有效loss token。

本篇沿下面这条链解释这种变化。

```mermaid
flowchart LR
  A[原始对象] --> B[解析与规范化]
  B --> C[治理与质量过滤]
  C --> D[精确与近似去重]
  D --> E[污染检查与划分]
  E --> F[Tokenizer与索引]
  F --> G[混合采样]
  G --> H[实际消费统计]
```

每一箭头既是一段程序，也是一项版本化决策。

保存原始对象却没有保存处理器版本，不能完整复现训练语料。

保存混合配置却没有保存消费统计，也不能证明训练实际遵守配置。

## 2. 文档的身份应该怎样定义

### 2.1 三种ID各自回答不同问题

| 标识 | 示例含义 | 用途 |
|---|---|---|
| source object ID | 某来源的某次抓取对象 | 来源与时间追踪 |
| raw content hash | 原始字节的SHA-256 | 原始对象完整性 |
| normalized content hash | 规范化正文的哈希 | 精确去重与处理对照 |

同一URL可以在不同时间返回不同内容，因此URL不能独自充当不可变文档ID。

两个URL可能返回同一正文，因此对象ID不同也不意味着内容不同。

规范化哈希依赖规范化规则；删除空白、大小写折叠或Unicode转换都可能改变等价关系。

代码语料尤其不能盲目使用自然语言的规范化方法。

Python缩进、字符串内部空白、Unicode标识符都可能有语义。

### 2.2 一条最小谱系记录

下面是教学schema，不是某个框架的强制格式。

```json
{
  "document_id": "doc-000042",
  "raw_object_hash": "sha256:...",
  "source_snapshot": "web-crawl-2026-07",
  "parser_version": "extractor-v3",
  "normalizer_version": "norm-v2",
  "language": "zh",
  "content_type": "article",
  "quality_score": 0.84,
  "dedup_cluster": "cluster-91",
  "tokenizer_hash": "sha256:...",
  "token_count": 1840,
  "decision": "keep",
  "decision_reason": "quality_pass"
}
```

生产记录还应包含适用的数据使用依据、敏感信息处理结果和删除传播关联。

这里讨论工程可追溯性，不把某套字段当作法律合规充分条件。

对象、派生文档、token shard和训练样本之间应保留可查询映射。

对于删除或修正请求，映射用于找到受影响的后续产物。

它不会自动把已经训练进权重的信息移除；那是独立的模型处理问题。

## 3. 质量过滤：一个分类器会产生一种偏好

过滤器把候选分布$p_{raw}(x)$变成条件分布：

$$
p_{keep}(x)=\frac{p_{raw}(x)a(x)}{\mathbb E_{p_{raw}}[a(x)]},
$$

其中$a(x)$是接受概率，规则过滤时通常为0或1。

如果过滤器偏好格式完整的英文长文，保留结果就会偏向这种数据。

因此“高质量”必须连接到目标能力，不能只看一个全域分数。

### 3.1 分层检查

| 层次 | 检查例子 | 常见误伤 |
|---|---|---|
| 解析 | 正文比例、乱码、导航模板 | 表格、公式、代码块 |
| 基础规则 | 字符分布、重复行、n-gram重复 | 诗歌、词典、枚举表 |
| 内容分类 | 教育性、领域、推理密度 | 专业但语言简短的文本 |
| 来源先验 | 站点、文档类型、版本 | 小众来源与低资源语言 |
| 人工抽样 | 多语言、多长度、多分数桶 | 只看高分示例导致盲点 |

规则拒绝时保留理由，分类器拒绝时保留模型与阈值版本。

分数为0.8不代表正确概率一定为80%；校准需要单独验证。

对过滤后数据应按语言、来源、长度和领域重新统计。

### 3.2 过滤率不是效果指标

假设原始语料100B token，方案A保留60B，方案B保留30B。

不能因为B更严格就判断B更好，也不能因为A更多就判断A更好。

合理实验至少固定训练token预算、模型、优化器、tokenizer和评测协议。

同时报告过滤产生的成本与可用语料重复次数。

[FineWeb论文](https://arxiv.org/abs/2406.17557)系统比较了网页过滤与去重设计，其价值在于公开消融路径；论文结果不能替代新语言或新领域的验证。

## 4. Exact Dedup：确定相同，不猜相似

流程可以写成：

1. 按固定规则得到规范化字节串。
2. 计算内容哈希。
3. 按哈希分组。
4. 对候选重复组保留可审计的代表。
5. 必要时比较原内容，排除哈希碰撞或实现错误。

代表选择不能简单写成“第一个文件”。

输入遍历顺序变化会改变代表的来源、时间戳或质量标签。

应使用稳定优先级，例如质量、完整程度、来源优先级与ID排序。

### 4.1 小例子

规范化后有：

```text
A: 今天学习矩阵乘法
B: 今天学习矩阵乘法
C: 今天学习矩阵加法
```

A和B进入同一个精确重复簇，C不进入。

如果A是完整正文、B缺失原始来源信息，可以保留A作为代表并保留B的别名关系。

不要把“保留一份正文”误实现成“丢失其余来源记录”。

### 4.2 跨split优先级

先明确训练、验证和测试的隔离策略，再执行去重。

如果测试题和训练样本近似重复，保留两者会让评测偏高。

评测集本身若在迭代过程中反复参与筛选，也可能成为间接优化目标。

污染检测需要冻结版本并限制评测信息进入训练调参过程。

## 5. MinHash：为什么最小哈希能估计Jaccard

把文档转成token或字符shingle集合，例如连续3-gram。

集合表示忽略重复次数，所以它不能单独反映某段模板出现一百次的程度。

对集合$A,B$，定义：

$$
J(A,B)=\frac{|A\cap B|}{|A\cup B|}.
$$

考虑对整个元素宇宙做均匀随机排列。

$A\cup B$中排在最前的元素，等概率来自并集的任一成员。

只有这个元素同时属于两者时，A和B的最小排列元素才相同。

所以：

$$
\Pr[h_{min}(A)=h_{min}(B)]=J(A,B).
$$

用$k$个独立哈希得到匹配指示量$I_i$：

$$
\widehat J=\frac1k\sum_{i=1}^{k}I_i,
\qquad
\operatorname{Var}(\widehat J)=\frac{J(1-J)}{k}.
$$

实际哈希族是随机排列的近似；种子、算法、位宽都要固定。

### 5.1 完整手算

令：

```text
A = {a,b,c,d}
B = {b,c,d,e}
A∩B = {b,c,d}
A∪B = {a,b,c,d,e}
```

因此真实$J=3/5=0.6$。

为了便于手算，选4个排列：

| 排列顺序 | A的最小元素 | B的最小元素 | 是否相同 |
|---|---|---|---|
| a,b,c,d,e | a | b | 0 |
| c,e,a,b,d | c | c | 1 |
| e,d,c,b,a | d | e | 0 |
| b,d,a,e,c | b | b | 1 |

本次估计$\widehat J=2/4=0.5$，不等于真实值0.6并不意味着算法出错。

四个哈希的方差很大；在真实$J=0.6$时，标准差约为$\sqrt{0.24/4}=0.245$。

增加到256个理想独立哈希，标准差约为0.0306。

阈值附近的候选因此需要更精确的复核。

## 6. LSH：候选召回与最终判决分开

将长度$k=br$的签名分成$b$个band，每个band有$r$行。

两个文档在一个band完全匹配的概率近似为$J^r$。

至少一个band命中的概率为：

$$
P_{candidate}(J)=1-(1-J^r)^b.
$$

这个公式依赖哈希近似独立等假设。

LSH输出候选，不直接证明内容重复。

### 6.1 参数手算

取$b=8,r=4$，一共32个签名项。

当$J=0.8$时：

$$
P=1-(1-0.8^4)^8\approx0.9852.
$$

当$J=0.2$时：

$$
P=1-(1-0.2^4)^8\approx0.0127.
$$

高相似度大概率召回，低相似度仍可能成为候选。

band越多更易召回，但候选数和精确复核成本也会增加。

### 6.2 连通簇的陷阱

A与B相似、B与C相似，不保证A与C相似。

如果把候选边的连通分量直接视为等价类，链式传播可能删除过多文档。

需要按语料类型选择代表匹配、簇直径限制或分段复核策略。

数学题中的公共题干、代码中的许可证头部尤其容易制造巨型簇。

应先区别模板片段重复与正文主体重复。

## 7. 混合分布：从库存到训练概率

设数据源$i$有$n_i$个可用token，幂次采样定义：

$$
p_i=\frac{n_i^{\alpha}}{\sum_j n_j^{\alpha}},\quad0\leq\alpha\leq1.
$$

$\alpha=1$按库存token比例抽样。

$\alpha=0$给各数据源相同概率。

中间值使小源相对上采样，但不会自动保证小源质量高。

### 7.1 三源完整手算

假设库存分别为网页90B、代码9B、数学1B token。

当$\alpha=1$时：

```text
网页 90%，代码 9%，数学 1%
```

当$\alpha=0.5$时，先取平方根：

```text
sqrt(90) = 9.4868
sqrt(9)  = 3.0000
sqrt(1)  = 1.0000
总和      = 13.4868
```

得到约70.34%、22.24%、7.41%。

若总训练预算为300B有效token，目标消费量约为：

| 数据源 | 目标消费token | 相对库存的期望epoch |
|---|---:|---:|
| 网页 | 211.02B | 2.345 |
| 代码 | 66.73B | 7.415 |
| 数学 | 22.24B | 22.244 |

上采样把数学数据重复使用约22遍。

这可能有益，也可能导致过拟合；要监控独立验证集和样本重复暴露。

重复次数不是每个样本都恰好22次，随机采样仍有方差。

### 7.2 样本比例怎样变成token比例

若按样本抽取源$i$的概率为$q_i$，平均有效长度为$\bar\ell_i$，长期token比例为：

$$
p_i^{token}=\frac{q_i\bar\ell_i}{\sum_jq_j\bar\ell_j}.
$$

想实现目标token比例$p_i$，应令$q_i\propto p_i/\bar\ell_i$，并持续核对实际长度。

例如两源样本比例各50%，有效长度分别100与400，则token比例为20%和80%。

固定长度GPTDataset且mask密度一致时，样本比例才近似token比例。

### 7.3 不同loss权重是另一件事

若再给数据源设置loss权重$w_i$，优化目标变为加权期望。

采样概率和loss权重同时上调同一个源，可能产生双重放大。

记录应分开列出`sample_probability`与`loss_weight`。

## 8. 一个可运行的配比核对器

以下仅计算期望值，不读取真实语料，也不验证模型质量。

```python
from math import sqrt

names = ["web", "code", "math"]
stock = [90.0, 9.0, 1.0]  # 单位：十亿token
alpha = 0.5
budget = 300.0
weights = [n ** alpha for n in stock]
total = sum(weights)
probs = [w / total for w in weights]
assert abs(sum(probs) - 1.0) < 1e-12
for name, n, p in zip(names, stock, probs):
    consumed = budget * p
    epochs = consumed / n
    print(name, round(p, 6), round(consumed, 3), round(epochs, 3))

j = 0.8
candidate = 1 - (1 - j ** 4) ** 8
print("LSH candidate probability", round(candidate, 6))
```

第一组输出应接近前表；最后一个值约为0.9852。

生产混合调度还需要处理小源耗尽、阶段变化、坏样本隔离和恢复状态。

随机数种子应作为混合调度器状态的一部分持久化。

## 9. Tokenizer也属于数据版本

相同字节在不同tokenizer下可能得到不同token数和边界。

这会改变固定序列长度能覆盖的文档范围、各源token库存和训练FLOPs。

应记录词表、merges、normalizer、特殊token和模板的完整哈希。

训练续跑时仅比较`vocab_size`不够。

两个tokenizer可以拥有同样大小的词表，但ID到字符串的映射不同。

扩词表还会影响embedding、输出层、tied weights和optimizer状态shape。

因此扩词表属于模型与状态迁移，不能仅替换数据预处理文件。

## 10. 故障定位：配置正确但实际混合漂移

| 症状 | 检查点 | 纠正方向 |
|---|---|---|
| 小源比例持续降低 | 耗尽策略、异常重试、坏样本计数 | 明确补采或停止规则 |
| 文档比例正常但token比例错 | 平均有效长度、mask密度 | 按有效token重新统计 |
| 去重后某语言骤减 | shingle规则、模板簇、质量分类器 | 分语言抽样与阈值复核 |
| 评测突然跃升 | 训练评测跨split近重复 | 固定污染报告并复验 |
| resume后source分布改变 | mixture RNG、阶段游标、manifest | 恢复调度状态并重放样本ID |
| 同代码重跑产物不同 | 非稳定遍历、未固定seed、远端源变化 | 不可变输入与稳定排序 |

先抽查文档与样本身份，再修改采样权重。

否则可能用新的错误配比掩盖上游解析失败。

## 11. 自测与详细答案

### 题1：两个数据源都配置0.5，为什么token比例是1:4？

因为配置控制的是样本概率，而两源平均有效长度可能是1:4。

长期贡献与$q_i\bar\ell_i$成正比。

应检查实际loss_mask有效长度，不能只数输入tensor的元素。

### 题2：MinHash四个值有两个相同，能断定Jaccard为0.5吗？

只能说本次估计为0.5。

有限哈希有抽样误差，还依赖哈希族质量。

阈值附近应增加签名或对候选计算更精确的相似度。

### 题3：LSH命中后为什么仍需复核？

命中概率是相似度的函数，不是重复的逻辑判据。

低相似文档也有非零候选概率，公共模板还会制造大量候选。

复核应检查正文、分段重复和所属领域，再决定删文档或删片段。

### 题4：把数学配比从1%提高到10%一定增加多样性吗？

不一定，固定库存下它可能只增加同一批样本的重复曝光。

应计算预算乘配比除库存，得到期望epoch，并评估独立验证表现。

数据增强与来源扩展也需要独立的质量和污染检查。

### 题5：为什么不能只用URL保存来源？

URL对应内容会变化，同内容也可以出现在多个URL。

需要原始内容哈希、抓取版本与派生内容映射。

URL保留来源语境，哈希提供不可变身份，两者职责不同。

### 题6：改变tokenizer但不改变模型词表大小可以直接续训吗？

不能仅凭词表大小判断。

token ID语义、文档切分、embedding含义和数据游标都可能变化。

至少需要兼容性证明或明确的转换与重新初始化方案。
