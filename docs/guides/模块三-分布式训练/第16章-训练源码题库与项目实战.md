## 从理解到实现

读懂一段代码与能够验证它是不同能力。

本章用问题检查理解，用项目建立证据。

每道题不仅要求一个结论，还要求shape、group、数据量或状态边界。

每个项目不仅要求能运行，还要求参考实现、反例、失败定位与结果解释。

这让学习产物可以被其他工程师复核。

## 16.1 训练Infra源码追问与计算题

本篇包含40道主线题。

每题有完整答案、数值或逻辑推演，以及追问和适用边界。

题目按以下生命周期组织。

| 阶段 | 主要问题 |
|---|---|
| Rank与拓扑 | 坐标、group与dense/expert双视图 |
| 模型计算 | TP、SP、GQA、SwiGLU与vocab CE |
| 序列与流水线 | CP、online softmax、bubble与P2P |
| MoE | assignment、A2A、permute与router |
| 梯度更新 | main_grad、bucket、ranges、norm与skip |
| 数据恢复 | 三索引、packing、游标与RNG |
| 可靠性 | checkpoint提交、rerun与NVRx |
| 新能力与成本 | Hybrid、GTP、6PN与goodput |

建议先遮住答案，自己写一个最小例子。

如果只能背出术语而不能算出shape，先回对应专题补推导。

## 16.2 可复现训练项目与系统设计验收

第二篇定义8个项目。

每个项目包含输入输出、核心状态、正确性不变量、验收与失败定位。

| 项目 | 主要产物 |
|---|---|
| Rank Explorer | 可逆坐标、groups与物理映射 |
| Mini TP Transformer | forward、grad与update参考对照 |
| Pipeline Simulator | dependency、bubble与激活存活 |
| MoE Dispatcher | token身份闭环与variable-split A2A |
| Distributed Optimizer Toy | 连续ranges、moments与参数AG |
| Checkpoint Reshard Lab | metadata、恢复与失败拒绝 |
| 长上下文实验 | RoPE、packing、CP与有效能力矩阵 |
| Advisor与Canary | 候选、预测残差、RPO/RTO与goodput |

最后用12周路线把项目串起来。

没有多GPU时可以先完成CPU和Gloo层，不需要虚构硬件结果。

## 统一答题方法

第一步说明数学对象。

第二步列global/local shape。

第三步说明谁拥有状态。

第四步推导collective与缩放。

第五步定义完成条件与下一消费者。

第六步给出反例和验收。

这六步适用于TP linear，也适用于checkpoint与数据恢复。

## 统一项目方法

```mermaid
flowchart LR
  A[最小问题] --> B[可观察reference]
  B --> C[实现]
  C --> D[数值与性质检查]
  D --> E[边界与失败输入]
  E --> F[目标硬件测量]
  F --> G[报告与复盘]
```

先建立reference，避免只在复杂优化实现里寻找正确性。

先验证结果，再优化时序。

每次性能改动保持相同目标与工作量。

保存失败输入，使修复可以复验。

## 四级证据

| 等级 | 代表产物 |
|---|---|
| CPU原理 | 公式、索引、范围与状态机 |
| CPU/Gloo多进程 | group与集合通信语义 |
| 单节点GPU | kernel、显存与节点内通信 |
| 多节点长运行 | 网络、可靠性与长期goodput |

上一级证据不能自动推出下一级。

一个小向量reshard正确，不证明文件系统断电时仍原子提交。

一个Gloo All-Reduce正确，不证明GPU stream/event没有竞态。

一个短期benchmark更快，不证明达到目标质量更便宜。

## 自测与验收

**只比较loss够不够？** 不够，部分排列、缩放或optimizer错误可能被偶然输入掩盖。

**为什么要比较一次update？** 它把输入、反向、归约和optimizer状态闭合为可观察参数变化。

**为什么需要多步？** moments、scheduler、RNG与恢复问题通常需要历史状态才暴露。

**为什么保留失败方案？** 它记录原假设被什么证据反驳，防止下一次重复同样试错。

**缺少硬件怎么办？** 完成可验证层，明确未覆盖项和目标硬件验收步骤。

## 最终项目报告应包含

- 问题与baseline。
- 输入、配置、版本与环境。
- 数学和分布式不变量。
- reference与边界输入。
- 数值、性能和恢复结果。
- 失败方案、修复与残留限制。
- 结论可以推广到哪些条件。
