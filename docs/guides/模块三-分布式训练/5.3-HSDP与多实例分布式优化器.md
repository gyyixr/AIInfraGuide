## 1. 分片更多与跨机通信更少，不总能同时得到

全量FSDP可以在更多rank之间分摊状态。

但使用某层权重前的All-Gather也可能跨越慢网络。

如果节点内互联比节点间更快，可以把高频参数聚合留在较小inner组，在outer组保留复制或更低频的状态同步。

这就是混合分片的基本动机。

本篇把三种经常混称的方案分开：HSDP、HFSDP和普通DDP包装器下的多实例DistOpt。

它们都利用分层拓扑，却不拥有相同的参数生命周期。

## 2. 证据固定在哪个版本

源码基线为Megatron提交`48a887fecd01674346f724dcf44f417f455989f0`。

HSDP/HFSDP部分采用该提交仓库内`docs/user-guide/features/megatron_fsdp.md`的官方合约。

多实例DistOpt的RS→AR与等待方式直接对照`param_and_grad_buffer.py`。

这两种证据分别是固定官方文档和固定实现，不能写成所有FSDP后端的统一行为。

本轮没有执行M-FSDP或多GPU DistOpt。

## 3. 先定义两个坐标

设完整数据复制域有D个rank，分成I个outer实例，每个实例d个inner rank：

$$
D=I\times d,\qquad d=D/I.
$$

用坐标(o,i)表示outer编号与inner编号。

教学布局D=8、I=2、d=4：

```text
outer0: rank0 rank1 rank2 rank3
outer1: rank4 rank5 rank6 rank7
```

inner groups为`[0,1,2,3]`和`[4,5,6,7]`。

相同inner坐标对应的outer groups为`[0,4]`、`[1,5]`、`[2,6]`、`[3,7]`。

实际rank顺序、CP和expert复制域要按process groups确认，不能由主机名猜测。

## 4. 三种布局的状态表

| 机制 | 计算参数的常驻布局 | 梯度布局 | master与moments |
|---|---|---|---|
| HSDP | inner分片、outer复制 | inner分片、outer汇总 | inner分片、outer复制 |
| HFSDP | 常见计算周期内inner分片、outer复制视图 | inner分片，更新前进一步outer RS | inner×outer全分片 |
| 多实例DistOpt | 每DP rank可见完整TP/PP模型分片 | 完整grad buffer，消费inner shard | inner分片，outer重复I份 |

这里的“完整模型分片”仍可被TP/PP切小。

HSDP/HFSDP的参数在module/unit使用前有FSDP unshard。

普通DistOpt不因此变成每层unshard的ZeRO-3。

## 5. HSDP：inner FSDP、outer复制

在inner组内，参数、梯度和optimizer状态分片。

用到某个unit时，在inner组AG参数，计算后按策略reshard。

每个outer实例处理不同数据。

相同inner坐标上的grad shard还要跨outer归约，使更新综合所有数据贡献。

固定M-FSDP文档描述outer梯度AR位于更新前的最后backward阶段。

### 5.1 一次周期

```text
inner参数shard
  → inner AG当前unit
  → forward/backward
  → inner RS与梯度累积
  → 最后backward的outer AR
  → 每个outer副本更新相同optimizer shard
```

每个outer实例必须在更新前拥有相同起点的master与moments。

只同步梯度却让两份历史moment不同，仍会得到不同新权重。

## 6. HFSDP：在outer再切optimizer

HFSDP进一步把optimizer状态分散到全部D个rank。

计算期间使用的weight/grad仍以inner布局为主。

因此计算布局与更新布局之间需要转换。

固定官方文档描述：

1. 更新后或checkpoint加载后的首个forward，将全分片权重outer AG成inner分片视图。
2. 各microbatch依照inner FSDP执行unit级AG/RS。
3. 最后backward将累积grad outer RS为全分片更新状态。
4. 每rank只更新自己的全局shard。

outer通信集中于更新边界，避免每个unit都反复跨机聚合。

### 6.1 配置合约

冻结文档中inner策略为`optim_grads_params`，outer策略为`optim`。

HFSDP要求完整DP域的累计group，以便建立全分片状态。

expert与dense可以需要不同mesh。

不能只添加一个outer整数，而没有构造实际需要的group。

## 7. 完整数例一：Q=1B的状态账本

假设Q是TP/PP之后的逻辑参数量，Q=10亿。

计算参数BF16、梯度FP32、master与两个moments均FP32。

暂不计padding、临时unshard、激活与allocator。

完整复制状态为18Q字节。

### 7.1 HSDP，inner4、outer2

每rank常驻近似：

$$
M_{HSDP}=18Q/d=4.5GB.
$$

outer有两份完整optimizer状态集合。

### 7.2 HFSDP

weight+grad按inner分片，master+moments按全部D分片：

$$
M_{HFSDP}=6Q/d+12Q/D.
$$

代入d=4、D=8：

$$
1.5GB+1.5GB=3GB.
$$

### 7.3 全域FSDP与普通DistOpt

全域FSDP理想常驻下界为$18Q/8=2.25GB$。

单实例普通DistOpt为$6Q+12Q/8=7.5GB$。

两实例普通DistOpt为$6Q+12Q/4=9GB$。

| 策略 | 本例理论状态/每rank |
|---|---:|
| 全域FSDP | 2.25GB |
| HFSDP | 3GB |
| HSDP | 4.5GB |
| 全域DistOpt | 7.5GB |
| 两实例DistOpt | 9GB |

排序只比较这些状态项，不预测总峰值或速度。

## 8. 为什么实例数增大反而更占optimizer内存

固定D时，I增加使d=D/I减小。

普通DistOpt每rank的更新状态为：

$$
12Q/d=12QI/D.
$$

因此与I成正比。

整个D-rank复制域共有I套optimizer状态。

这项额外内存换来更小的inner通信组与分层归约机会。

如果优化目标是最小显存，不能不加分析就增加实例数。

## 9. 不同精度的理论表

冻结官方DistOpt口径包括：

| param/main-grad | 非分布optimizer | DistOpt每rank |
|---|---:|---:|
| FP16/FP16 | 20 bytes/param | $4+16/d$ |
| BF16/FP32 | 18 | $6+12/d$ |
| FP32/FP32 | 16 | $8+8/d$ |

FP16路径中的额外高精度梯度与master等状态需要按实现计入。

不能只把BF16公式中的2改成另一dtype字节就复用全部状态布局。

precision-aware optimizer可能让master/moments由TE等后端管理，需重新列对象账本。

这里的d始终是相应参数的intra-instance分片组大小。

## 10. 多实例DistOpt的两级梯度同步

冻结`start_grad_sync`先选择SUM或AVG。

DistOpt在`intra_distributed_optimizer_instance_group`执行RS。

I大于1时，再在`inter_distributed_optimizer_instance_group`对相同local range执行AR。

```mermaid
flowchart LR
  A[完整局部grad buffer] --> B[inner Reduce Scatter]
  B --> C[本inner坐标的grad shard]
  C --> D[outer All Reduce]
  D --> E[一致的有效grad shard]
  E --> F[本地optimizer更新]
  F --> G[inner参数All Gather]
```

outer AR交换的是RS之后的shard，不是再次交换完整grad buffer。

不同outer实例的同坐标shard必须表示同一逻辑参数范围。

## 11. 完整数例二：两实例8-rank归约

有8个参数元素，每rank对所有元素的局部梯度都等于rank+1。

rank0到7分别贡献1到8。

全局SUM为36，平均为4.5。

### 11.1 两级SUM路径

outer0的四rank先SUM，得到10，再RS成各inner坐标的两个元素。

outer1先得到26，再按同样布局RS。

相同inner坐标跨outer AR：$10+26=36$。

若目标为平均，再按完整数据贡献域除8，得到4.5。

### 11.2 两级AVG路径

inner AVG得到2.5与6.5。

outer AVG得到$(2.5+6.5)/2=4.5$。

已经AVG后不能再除8。

变长token目标还需要有效分母，不能仅按rank数量平均。

## 12. 两个可运行CPU oracle

```python
Q, D, instances = 1_000_000_000, 8, 2
d = D // instances
state = {
    "global_fsdp": 18*Q/D,
    "hfsdp": 6*Q/d + 12*Q/D,
    "hsdp": 18*Q/d,
    "global_distopt": 6*Q + 12*Q/D,
    "partial_distopt": 6*Q + 12*Q/d,
}
assert [state[k]/1e9 for k in state] == [2.25, 3.0, 4.5, 7.5, 9.0]
print({k:v/1e9 for k,v in state.items()})
```

```python
rows = [[float(rank+1)]*8 for rank in range(8)]
inner_sums = []
for start in [0, 4]:
    inner_sums.append([sum(rows[r][j] for r in range(start, start+4))
                       for j in range(8)])
shards = []
for inner_rank in range(4):
    lo, hi = inner_rank*2, (inner_rank+1)*2
    combined = [inner_sums[0][j]+inner_sums[1][j] for j in range(lo, hi)]
    shards.append([value/8 for value in combined])
assert all(shard == [4.5, 4.5] for shard in shards)
reconstructed = [value for shard in shards for value in shard]
assert reconstructed == [4.5]*8
print("globally averaged gradients", reconstructed)
```

这两个例子只验证账本与代数，不执行NCCL、stream或M-FSDP。

## 13. 两级通信的字节模型

令完整FP32 grad buffer大小为$S_g=4Q$字节。

理想ring的inner RS每rank单方向payload：

$$
V_{inner}=\frac{d-1}{d}S_g.
$$

outer AR处理大小$S_g/d$：

$$
V_{outer}=2\frac{I-1}{I}\frac{S_g}{d}.
$$

d4、I2、Q1B时，分别为3GB和1GB。

总payload4GB大于单个8-rank ring RS的3.5GB。

但其中3GB可能在更快的节点内互联，只有1GB经过较慢outer网络。

所以总字节增加并不自动表示时间增加。

### 13.1 时间边界

假设inner有效带宽300GB/s、outer25GB/s，仅带宽项约10ms+40ms。

这不是实测，也不能与假定所有全域流量都走慢网的模型直接宣称必然加速。

真实全域NCCL也可能采用分层算法，overlap和拓扑会改变关键路径。

应测相同global batch、相同dtype与真实路由。

## 14. 没有async Work句柄，不等于没有overlap

冻结多实例overlap路径使用专用communication stream。

它先等待compute stream的梯度依赖，再按顺序提交inner RS与outer AR。

这里`async_op`只在单实例overlap路径取True。

多实例路径仍可通过独立CUDA stream与计算重叠。

`finish_grad_sync`让当前stream等待communication stream，然后才允许optimizer读取。

不能看到`async_op=False`就断言通信一定阻塞了整个GPU计算。

### 14.1 反方向也成立

即使返回Work handle，也不能在未等待时消费reduced grad。

等待必须出现在实际消费者所在stream，不能只在无关stream上执行。

参数AG的消费同样由forward pre-hook或相应依赖控制。

## 15. M-FSDP unit与普通per-parameter DTensor

固定官方文档将M-FSDP unit的一组参数放入连续通信buffer。

整个unit可均匀分片，但单个参数在不同rank上的local片段可能不等长，甚至为空。

这与“每个参数都沿dim0平均切开”是不同布局。

调用假定每rank等长的per-parameter collective可能等待不存在的数据。

应使用对应uneven DTensor辅助或unit级协议。

### 15.1 连续与局部性是两种约束

连续buffer减少copy与collective数量。

但量化block若被shard边界切开，还需跨rank统计scale。

固定文档说明dim0 locality可以通过LCM相关padding保持整行不被切开。

这种padding会增加内存和通信；不是免费获得两种性质。

## 16. Checkpoint与拓扑变化

HSDP中的outer副本不应被错误当成不同模型参数永久保存。

HFSDP保存与加载需要识别全分片更新视图。

partial DistOpt的内部bucket布局与实例数也可能影响可重分片格式。

不要仅凭“都是8张卡”判断新旧optimizer状态兼容。

至少核对：

```text
逻辑参数key与shape
inner/outer组大小
optimizer sharding format
bucket/padding布局
moment与master身份
RNG与数据副本映射
```

模型tensor可重分片，不代表所有随机流和训练轨迹逐位连续。

## 19. 自测与详细答案

### 题1：HSDP与partial DistOpt是否同一布局？

不是，HSDP参数在inner组分片并按unit使用前聚合。

普通DistOpt保留完整计算参数与grad buffer，主要分片更新状态。

### 题2：D固定时I增加，为什么master显存增加？

d=D/I变小，每rank需持有12Q/d更新状态。

这是用状态复制换更小通信域的代价。

### 题3：HFSDP节省哪一部分？

在inner FSDP基础上进一步把optimizer状态分到outer。

weight/grad计算视图仍有inner层次，边界转换需要outer AG/RS。

### 题4：两级SUM之后除d够吗？

若两级汇总覆盖D个等权数据贡献，应该使用完整目标的归一化。

仅除d会把结果放大I倍；AVG路径则不能再重复除。

### 题5：多实例async_op=False为何仍能overlap？

固定实现把通信提交到独立communication stream。

它靠stream依赖与最终wait_stream保证顺序，而非只靠Python Work句柄。

### 题6：unit分片均匀是否表示每个参数local shape相同？

不是，连续unit区间可能切开不同参数。

单个参数可不等长或为空，必须使用兼容的collective与元数据。
