RingAttention 的直觉是：每个 rank 把自己的 query 留在原地，让不同位置的 key/value 轮流经过。困难在于经过一个块时只能看到部分 key，但最终必须得到完整 Attention 的同一个归一化结果。

本节先把通信和数学拆开验证，再把两者连接起来。所有手算都以精确 dense attention、无 dropout 为起点；需要加入因果 mask、dropout、GQA 或反向时，逐项补上相应契约。

## 1. 四个 rank 怎样看到全部 KV

设全局序列分成四块：$Q_r,K_r,V_r$，其中 $r=0,1,2,3$。每个 rank 向编号加一的邻居发送 KV，从编号减一的邻居接收，编号按模 4 回绕。

| 计算轮次 | rank 0 使用 | rank 1 使用 | rank 2 使用 | rank 3 使用 |
|---:|---|---|---|---|
| 0 | $Q_0$ 配 $KV_0$ | $Q_1$ 配 $KV_1$ | $Q_2$ 配 $KV_2$ | $Q_3$ 配 $KV_3$ |
| 1 | $Q_0$ 配 $KV_3$ | $Q_1$ 配 $KV_0$ | $Q_2$ 配 $KV_1$ | $Q_3$ 配 $KV_2$ |
| 2 | $Q_0$ 配 $KV_2$ | $Q_1$ 配 $KV_3$ | $Q_2$ 配 $KV_0$ | $Q_3$ 配 $KV_1$ |
| 3 | $Q_0$ 配 $KV_1$ | $Q_1$ 配 $KV_2$ | $Q_2$ 配 $KV_3$ | $Q_3$ 配 $KV_0$ |

四轮计算、三次逻辑交换后，每个 rank 的 query 看过了全部四个 KV 块。前向无需为了“环闭合”再额外把最后一个块送回原主；反向阶段有自己的数据安排。

这是一种完整双向注意力的逻辑调度表。因果模式可以跳过无效的 query/key 块，但必须保留原始全局位置和一致通信协议。

## 2. 为什么块内 softmax 不能平均

对一行 query，令经过缩放的分数为 $s_j=q^Tk_j/\sqrt d$，值为 $v_j$：

$$
o=\frac{\sum_j e^{s_j}v_j}{\sum_j e^{s_j}}.
$$

如果把 keys 分成 A、B 两块，各自计算得到：

$$
o_A=\frac{u_A}{l_A},\qquad o_B=\frac{u_B}{l_B},
$$

正确合并必须考虑两块各自的权重总量，不是 $(o_A+o_B)/2$。两块包含相同数量的 token 也不意味着它们的 softmax 概率质量相同。

### 2.1 一个不需要计算器的例子

令分数为 $[\log1,\log2,\log3,\log4]$，对应值为 $[10,20,30,40]$。全局指数权重是 $[1,2,3,4]$，所以：

$$
o=\frac{1\times10+2\times20+3\times30+4\times40}{1+2+3+4}=30.
$$

前两项组成 A，后两项组成 B：

$$
o_A=\frac{10+40}{3}=\frac{50}{3},\qquad
o_B=\frac{90+160}{7}=\frac{250}{7}.
$$

简单平均约为 26.190476，明显不等于 30。只有按两块质量 3 与 7 加权才正确。

## 3. Online softmax 保存三个量

直接保存 $e^{s_j}$ 会遇到很大分数造成的溢出。对已经处理过的 keys，保持：

$$
m=\max_j s_j,
\qquad l=\sum_j e^{s_j-m},
\qquad u=\sum_j e^{s_j-m}v_j.
$$

其中 $m,l$ 对每个 query row/head 各一个，$u$ 与输出 value 向量同宽。最终 $o=u/l$。

现在来了新块，块内统计为 $(m_b,l_b,u_b)$。新的最大值与缩放系数：

$$
m'=\max(m,m_b),\quad
\alpha=e^{m-m'},\quad \beta=e^{m_b-m'}.
$$

合并：

$$
l'=\alpha l+\beta l_b,
\qquad
u'=\alpha u+\beta u_b.
$$

**旧分母与旧输出累积必须一起缩放。** 只更新最大值却不缩放 $u$，或者只对 $l$ 缩放，都会悄悄改变结果。

### 3.1 接着把上例手算完

A 块最大值 $m_A=\log2$：

$$
l_A=\tfrac12+1=1.5,\qquad
u_A=\tfrac12\times10+1\times20=25.
$$

B 块最大值 $m_B=\log4$：

$$
l_B=\tfrac34+1=1.75,\qquad
u_B=\tfrac34\times30+40=62.5.
$$

新最大值 $m'=\log4$，所以 $\alpha=1/2,\beta=1$：

$$
l'=0.5\times1.5+1.75=2.5,
\qquad
u'=0.5\times25+62.5=75,
\qquad o=75/2.5=30.
$$

这说明每块可以只输出自己的统计量，不必把全部 score 搬到同一个 rank；前提是这些统计量对应同一逻辑 query 与完整一致的 mask。

## 4. 完整 CPU 数值实验

下面按一行 query、标量 value 演示；向量 value 只需将 $u$ 扩展为向量，所有分量共用同一 $m,l$。

```python
import math

def block_state(scores, values):
    pairs = [(s, v) for s, v in zip(scores, values) if s != -math.inf]
    if not pairs:
        return None  # 此块对当前 query 全部被 mask
    m = max(s for s, _ in pairs)
    weights = [math.exp(s - m) for s, _ in pairs]
    l = math.fsum(weights)
    u = math.fsum(w * v for w, (_, v) in zip(weights, pairs))
    return m, l, u

def merge(left, right):
    if left is None:
        return right
    if right is None:
        return left
    m1, l1, u1 = left
    m2, l2, u2 = right
    m = max(m1, m2)
    a, b = math.exp(m1 - m), math.exp(m2 - m)
    return m, a * l1 + b * l2, a * u1 + b * u2

def blocked_attention(scores, values, block_size):
    if len(scores) != len(values) or block_size < 1:
        raise ValueError("shape 或 block_size 不合法")
    state = None
    for begin in range(0, len(scores), block_size):
        state = merge(state, block_state(scores[begin:begin+block_size],
                                         values[begin:begin+block_size]))
    if state is None:
        raise ValueError("整行没有有效 key，应按调用方的 padding 语义处理")
    return state[2] / state[1]

scores = [1000, 1001, 998, 1002]
values = [1, 2, 3, 4]
expected = blocked_attention(scores, values, 4)
for block in [1, 2, 3, 4]:
    assert abs(blocked_attention(scores, values, block) - expected) < 1e-12
assert abs(expected - 3.237556871078246) < 1e-12
print(expected)
```

大分数不会直接进入 `exp(1000)`，因为指数计算前减去了所在统计块的最大值。仓库 `labs/distributed/mechanics_lab.py` 也保留相应分块一致性和错误局部平均的检查。

这证明的是浮点容差内的前向分块等价。它还没有任何真实 rank、通信、GPU kernel、dropout 或 backward，必须准确描述验证层次。

## 5. 全 mask 块为何需要特别处理

因果 Attention 中，某个未来 KV 块对当前 query 行可能完全无效。这时不能机械计算：

$$
m_b=-\infty,\qquad e^{s_j-m_b}=e^{-\infty-(-\infty)},
$$

因为后一个表达式会出现未定义的 `NaN`。

数学上空块对归一化和输出贡献为零，可以跳过它。完整一行没有有效 key 时，要由接口定义输出零、忽略该 query 或报错；不能让随意的 `0/0` 流进训练。

有些 fused kernel 已处理这些边界，但在自行实现块合并或 mask 时仍需加入对应测试。

## 6. 通信重叠需要满足什么条件

逻辑上的双缓冲循环可以写成：

```text
当前缓冲含 KV_j
    → 提交 KV_j 向邻居发送、下一块接收进空闲缓冲
    → 用 Q_local 和 KV_j 做当前块 Attention
    → 等待接收完成，确认消费者可访问下一缓冲
    → 交换当前/下一缓冲角色
```

这只是设计伪代码，不对应某个框架的可直接调用 API。真实实现必须保证：发送 buffer 在发送完成前不被覆盖；接收 buffer 在接收完成前不被读取；前一轮计算尚未结束时，相关内存也不能被下一轮通信复用。

通信 API 在 host 返回、操作进入 stream、设备真正完成、其他 stream 可以消费，是不同事件。NCCL Work 或 CUDA event 的使用要与所选 API 的语义一致。

### 6.1 一个有单位的隐藏条件

令每个序列块长 $q=S/C$，假设 dense 非因果块计算，effective 算力为 $F_{eff}$，单向有效带宽为 $BW$：

$$
T_{compute}\approx\frac{4Bq^2H_qd}{F_{eff}},
\qquad
T_{wire}\approx\frac{2BqH_{kv}dw}{BW}.
$$

二者比值近似：

$$
\frac{T_{compute}}{T_{wire}}
\approx\frac{2qH_q BW}{H_{kv}wF_{eff}}.
$$

这只比较主计算与裸传输，未计通信延迟、kernel launch、重排、协议及资源竞争。$T_{compute}\ge T_{wire}$ 是尝试隐藏通信的有利条件，不是充分保证。

### 6.2 用第 9.1 节配置估算

取 $B=1,H_q=32,H_{kv}=8,d=128,w=2$；假设实测有效算力能到 200 TFLOP/s，有效单向带宽 25 GB/s：

| 局部块长 | 块矩阵乘 FLOPs | KV 字节 | 估算计算 | 估算传输 |
|---:|---:|---:|---:|---:|
| 8192 | 约 1.100 TFLOPs | 32 MiB | 5.50 ms | 1.34 ms |
| 1024 | 约 17.18 GFLOPs | 4 MiB | 0.086 ms | 0.168 ms |

块长减少八倍，计算减少六十四倍，通信仅减少八倍。把 CP 开得更大，可能让原本可隐藏的通信变成关键路径。

200 TFLOP/s 与 25 GB/s 是本表的假设输入，不是本机测量。实际必须用目标形状的 kernel 和网络路径测得有效值，不能把宣传峰值直接代入后承诺吞吐。

## 7. 因果负载为什么不均衡

将序列连续分四块，按全局先后编号 0—3。早期 query 能看到的 key 少，晚期 query 能看到的 key 多。

忽略块边界的少量差异，以一个完整 query/key 块的工作为单位：

| rank 的 query 块 | 过去完整块 | 自己的三角块 | 近似总工作 |
|---|---:|---:|---:|
| 0 | 0 | 0.5 | 0.5 |
| 1 | 1 | 0.5 | 1.5 |
| 2 | 2 | 0.5 | 2.5 |
| 3 | 3 | 0.5 | 3.5 |

同样 token 数不等于同样计算量。同步点最终由最慢 rank 决定，早期 rank 的空闲可能无法仅靠“再开一个异步 stream”消除。

### 7.1 Zigzag 的基本构造

把序列进一步分为 $2C=8$ 个等长小块，rank $r$ 持有块 $r$ 和块 $7-r$：

```text
rank 0: [0, 7]
rank 1: [1, 6]
rank 2: [2, 5]
rank 3: [3, 4]
```

第 $j$ 块的近似因果工作为 $j+0.5$，每个 rank 成对相加都是 8 个小块工作单位。通过把早、晚 query 组合，可以平衡计算。

代价是数据变成非连续逻辑片段；位置、标签、mask、输出顺序和通信调度必须一起维护，不能只把输入 tensor 随机切成两块。

## 8. Backward 怎样回到正确 owner

对于完整单 head Attention，记 $P=\operatorname{softmax}(S)$、$O=PV$。已知 $dO$：

$$
dV=P^TdO,\qquad dP=dOV^T.
$$

Softmax 梯度逐行计算：

$$
dS=P\odot\left(dP-\sum_jP_jdP_j\right),
$$

再有：

$$
dQ=\frac{dSK}{\sqrt d},\qquad
dK=\frac{dS^TQ}{\sqrt d}.
$$

每个 query owner 可以累积本地 $dQ$；但同一个 KV 块可能被多个 query owner 使用，所以它的 $dK,dV$ 必须汇总所有相关贡献，再回到正确的 KV owner。

不能让每个 rank 只保留“本地 query 对本地 KV”的梯度。那样前向可能通过全局 KV 得到正确输出，backward 却漏掉跨块依赖。

### 8.1 前向统计量为什么重要

反向重算某个 score 块时，需要全局等价的 softmax 归一化。常见实现保留每行 log-sum-exp：

$$
\operatorname{LSE}=m+\log l,
\qquad P_j=e^{s_j-\operatorname{LSE}}.
$$

无 dropout 时，行归约 $\sum_jP_jdP_j$ 也等于 $dO\cdot O$。这里的 $O$ 必须是完整 Attention 输出；使用某个局部块输出会改变导数。

反向可能重传 KV、传梯度或采用融合环传，不同实现的通信量不同。不能把前向 $C-1$ 次 KV 交换简单乘二，就当作通用训练通信公式。

## 9. Dropout 与跨分片可复现性

严格比较不同 CP degree 时，attention dropout mask 应对应同一逻辑坐标，例如 `(sample, head, global_query, global_key)`。如果只让每个 rank 使用同一个 seed 后按自己的局部执行顺序取随机数，改变分块或跳块顺序就可能得到不同 mask。

有些实现使用 counter-based RNG 与全局偏移处理这个问题；具体映射需要看 kernel 和框架实现。

因此建议正确性验证按层次推进：先关闭 dropout，比较前向与梯度；再打开随机操作，验证所承诺的是逐值复现还是统计等价。不能把合理的 RNG 差异与真正的 mask 错误混在一起。

## 10. 从数学例子走到真实多卡

| 阶段 | 工作负载 | 验收证据 |
|---|---|---|
| 单进程标量 | 本节 score/value 小例子 | 每块统计与最终结果可手算 |
| 单进程矩阵 | 多 query/head、float64、无 dropout | 与完整 softmax 的输出/梯度比较 |
| 两 rank 通信 | 小序列、固定 token、无重叠 | KV owner、轮次、输出顺序一致 |
| 两 rank backward | 固定 $dO$ | $dQ,dK,dV$ 与全局 oracle 对齐 |
| 因果/变长 | 非整除边界、packed docs、padding | mask、position、label 与 loss 对齐 |
| 通信重叠 | 开启双缓冲及异步 | 结果不变，trace 显示实际重叠 |
| 性能扫描 | 固定模型与全局有效 token | 吞吐、峰值、网络流量与慢 rank 分布 |

仓库当前的 mechanics lab 覆盖第一层数学机制；CPU/Gloo DDP 实验验证的是数据并行同步，不能替代这张表中的 RingAttention 多卡阶段。

## 11. 常见故障的定位顺序

| 症状 | 先看什么 |
|---|---|
| 分块数改变，输出明显改变 | 是否错误平均局部 softmax、遗漏旧累积缩放 |
| 只有最早几行 NaN | 全 mask 块与 `-inf - -inf` |
| 前向正确、梯度不同 | 全局 LSE/O、远端 dK/dV 累积、转置与缩放 |
| CP=1 正常、CP>1 质量下降 | 全局 position、分片边界标签、packed mask |
| 关闭 overlap 后错误消失 | buffer 复用、stream/event 依赖、在途发送 |
| CP 增大后更慢 | 局部块计算/传输比、因果负载、协议延迟 |

先保留固定输入的完整小 oracle，再加复杂功能。直接用训练 reward 或大模型 loss 判断底层 RingAttention 正确性，定位成本通常更高。

## 12. 自测与参考答案

**1. 两个块 token 数相同，可以平均它们的输出吗？** 不可以。块概率质量取决于分数，必须带归一化统计量合并。

**2. running max 变大时，只缩放旧分母有什么问题？** 旧分子仍处于原指数尺度，最终比值错误；$l$ 和 $u$ 必须一起缩放。

**3. 为什么前向完整环传后，不需要强制多发一次才能结束？** query 已看过全部 KV。是否返回原主取决于后续所有权和 buffer 协议，不是前向数学的额外要求。

**4. 一个 KV 块的 dK 应汇总哪些 query 的贡献？** 汇总所有在 attention mask 下能够看到该 KV 的 query。非因果 attention 中通常跨多个 query 块；连续分块的因果 attention 中，最后一个 rank 的 KV 不会被更早的 query 看到，因此它的 dK 可以只来自本 rank，不能无条件要求每个 KV 块都接收所有 rank 的非零贡献。

**5. 更大 CP 能无限隐藏通信吗？** 不能。块计算随局部块长平方减小，KV 传输近似线性减小，短块更容易暴露通信与启动延迟。
