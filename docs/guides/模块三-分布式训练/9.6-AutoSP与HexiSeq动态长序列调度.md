## 1. 两篇论文解决不同的自动化问题

第9.4节解释长度分桶和动态mesh的一般思想。

本篇进一步区分两个研究对象。

AutoSP关注如何把序列并行和长上下文重计算变成编译器变换。

HexiSeq关注如何将一条长序列及attention heads分配给不同能力的GPU和非均匀网络。

两者都涉及布局与通信，但不能统一描述成“按样本长度动态增加CP”。

HexiSeq的异构工作分配尤其不同于对长短不一样本做batch调度。

## 3. AutoSP采用的SP含义

AutoSP主要把Ulysses式sequence↔head变换放进PyTorch编译流程。

它不是专指Megatron TP组内的非attention激活SP。

基本数据流：

```text
局部sequence、完整heads
  → QKV projection
  → All-to-All
  → 完整sequence、局部heads
  → attention
  → All-to-All
  → 局部sequence、完整hidden
```

线性层可以逐token计算，attention需要取得与本head相关的全局上下文。

因此只有某些边界需要重分布。

## 4. 为什么选择Torch-IR做布局变换

较高层图仍保留linear和attention等可识别结构。

下降到更细的ATen图后，一个高层操作可能变成多个matmul、reshape和permute。

此时仅看张量维度，更难判断某个轴代表sequence还是head。

AutoSP先在Torch-IR分析输入和attention输出shape，再进行语义改写。

这使通信插入、buffer大小变化和手工索引调整可以围绕层边界组织。

### 4.1 不只是插入两个All-to-All

还需要同时处理：

- sequence分片后的中间buffer shape。
- attention内部完整sequence与head分片shape。
- position/token相关索引。
- mask和手工切片的语义。
- 新通信节点的反向算子。

只改输入shape，原图中硬编码的S仍可能造成错误。

## 5. 论文Listing 2的阅读顺序

论文的变换过程可以按三个集合理解：

| 集合 | 决策 |
|---|---|
| RESIZE_BUFS | 哪些buffer需要按SP布局修改 |
| INDEX_OPS | 哪些手工索引需要重新计算 |
| ATTN_OPS | attention边界在哪里插入通信 |

论文说明这些集合由对手写Transformer FX图的分析人工整理。

因此“自动化”不是任意未知模型、custom operator与动态控制流都自动支持。

新结构需要证明图识别与变换规则仍然覆盖其语义。

### 5.1 Forward变换与backward

在forward图插入通信节点后，需要为它们注册相应梯度算子。

sequence→head的反向必须恢复正确token与head归属。

自动微分不能凭节点名字猜出分布式all-to-all的逆布局。

## 6. 完整数例一：两个rank的Ulysses布局

取B=2、S=8、heads=4、head_dim=4，SP=2。

每rank输入hidden为`[2,4,16]`。

Q投影后可看成`[2,4,4,4]`。

第一次A2A后变为`[2,8,2,4]`。

每rank张量元素数前后都是128，但各轴含义改变。

attention输出按相反布局重分布，回到局部sequence。

### 6.1 为什么只检查numel不够

`[2,4,4,4]`与`[2,8,2,4]`有同样numel。

错误reshape也可能得到这些shape，却没有真正交换其他rank的数据。

应给每个元素携带全局token/head身份，验证owner转换。

## 7. 可执行oracle一：数据身份守恒

```python
S, heads, ranks = 4, 2, 2
# 元素用(token_id, head_id)表示，不做真实attention。
sequence_shards = [
    [(token, head) for token in range(r*2, (r+1)*2) for head in range(heads)]
    for r in range(ranks)
]
head_shards = [
    [item for shard in sequence_shards for item in shard if item[1] == dst]
    for dst in range(ranks)
]
assert head_shards[0] == [(0,0),(1,0),(2,0),(3,0)]
assert head_shards[1] == [(0,1),(1,1),(2,1),(3,1)]
restored = [
    sorted(item for shard in head_shards for item in shard if item[0]//2 == dst)
    for dst in range(ranks)
]
assert restored == sequence_shards
print("head shards", head_shards)
```

该程序验证所有权转换，不模拟NCCL、通信反向或编译器图。

真实测试还要比较forward、dX、dW及一次更新。

## 8. 普通activation checkpoint为什么可能重做通信

如果一个重计算区间包含projection、A2A与attention，反向重新执行区间时可能再次执行A2A。

保存更少激活的代价就不仅是重复GEMM，还包括通信与同步。

对长上下文，这些额外数据移动可能破坏原有overlap。

因此编译器的保存/重算决策应认识序列布局和通信边界。

不能把单GPU上有效的checkpoint切块原样套到分布式图。

## 9. SAC与最小割：保存哪些节点

论文讨论的自动AC把forward与backward组合成joint graph。

节点分裂为in/out，之间放代表保存成本的有限容量边。

数据依赖边使用不可切断的大容量。

min-cut选择需要保留、能够让backward重建依赖的一组中间值。

普通保守策略会把某些重算昂贵操作限制为必须保存其结果或后继状态。

AutoSP的SAC允许attention之外某些matmul进入可重算集合，以适应长序列成本结构。

### 9.1 这里“便宜”是相对整步

对固定模型，线性部分随S增长，dense attention随S平方增长。

因此：

$$
\frac{aS}{aS+bS^2}=\frac{a}{a+bS}.
$$

随着S增长，额外重做部分线性计算的相对占比下降。

这解释为何可以用重算换较大激活节省。

但真实速度仍由kernel、通信与临界路径决定，不等于代价为零。

## 10. 一个重计算成本手算

使用归一化单位，线性forward成本为8S，attention为$S^2$。

假设基本训练成本近似三倍forward，额外只重算一次线性部分。

额外占比：

$$
\rho=\frac{8S}{3(8S+S^2)}.
$$

| S | 线性forward | attention forward | 额外重算占基本训练 |
|---:|---:|---:|---:|
| 4 | 32 | 16 | 22.22% |
| 16 | 128 | 256 | 11.11% |
| 64 | 512 | 4096 | 3.70% |

这是解释趋势的自建模型，系数不是AutoSP实测。

如果采用稀疏attention或递归层，attention不再按同样平方项增长，SAC收益需要重新建模。

## 11. AutoSP实验的可推广边界

论文实验使用PyTorch2.7，NVIDIA路径CUDA12.8、AMD路径ROCm6.4，并集成到DeepSpeed背景中。

设备包括A100/GH200与MI250的具体实验配置。

报告主要衡量最大可训练长度及短窗口迭代时间。

不能把这些结果写成所有当前PyTorch版本、任意模型或长期训练质量已经验证。

新编译器版本的IR、guard和AC策略改变后，规则需要重新核对。

## 12. HexiSeq：异构的是设备与链路

相同sequence/head份额给H100与A100，并不意味着相同执行时间。

显存较小设备还可能先OOM。

不同节点的A2A链路与跨节点ring链路也不均匀。

HexiSeq把A2A分组、组间sequence长度、组内token切片与head分配共同纳入计划。

它不是单纯给较快rank增加microbatch样本数。

## 13. Logical schedule与runtime分开

计划描述：

```text
A2A group成员
各组负责的sequence区间
各rank A2A前的token片段
各rank负责的head范围
每条通信边的split table
KV交换的head-range子任务
```

runtime依据计划建立process groups、ragged A2A与KV交换。

不同head范围不再适合假设所有rank用同一大小buffer和同一环任务。

对非连续head片段，论文描述先打包成连续传输buffer。

## 14. Ragged A2A的具体形状

在一个A2A组内，source i有$s_i$个token，destination j负责$h_j$个heads。

忽略batch与head_dim时，i发给j的元素数与$s_i h_j$成正比。

完整QKV单向字节可记为：

$$
V_{i\to j}=3B s_i h_j d_h b.
$$

这是一段QKV重分布的口径。

反向或输出回传可能搬不同tensor，不能把每一腿都无条件当成同样三倍QKV。

## 15. 完整数例二：非均匀tokens与heads

一个两rank A2A组共有8个token、4个heads。

rank0在重分布前持2个token，rank1持6个。

重分布后分别负责1个与3个heads。

以token-head元素计，发送矩阵为：

$$
M=\begin{bmatrix}2&6\\6&18\end{bmatrix}.
$$

行和为8与24，等于各source的token数乘全部4heads。

列和为8与24，等于完整8token乘目标head数。

没有丢失或复制额外逻辑元素。

### 15.1 计算能力匹配

若两rank对该shape的有效算力比例为1:3，attention工作又与head数成正比，1:3分配可以使计算时间相近。

均匀2:2分配会让慢rank成为瓶颈。

但更快设备必须有足够显存，且多接收数据不会制造更大的通信尾部。

## 16. 可执行oracle二：split守恒与容量过滤

```python
sequences = [2, 6]
heads = [1, 3]
compute = [1, 3]
mat = [[s*h for h in heads] for s in sequences]
assert mat == [[2,6],[6,18]]
assert [sum(row) for row in mat] == [8,24]
assert [sum(mat[i][j] for i in range(2)) for j in range(2)] == [8,24]

# 仅以head工作量/有效算力比较一个attention任务。
equal = max(2/c for c in compute)
weighted = max(h/c for h,c in zip(heads, compute))
assert equal == 2 and weighted == 1

# 候选需先通过内存约束，不能只选最快预测。
plans = [("fast_but_oom", 0.8, [12,24]),
         ("weighted", 1.0, [10,20]),
         ("equal", 2.0, [10,18])]
capacity = [12,20]
feasible = [p for p in plans if all(m<=cap for m,cap in zip(p[2],capacity))]
assert min(feasible, key=lambda p:p[1])[0] == "weighted"
print(mat, equal, weighted, [p[0] for p in feasible])
```

该oracle只覆盖一个A2A组。

多组CP/HP计划还必须按head-range子环证明每个query获得对应全部KV区间，不能只检查总head数。

## 17. Sub-ring交换必须保持数学身份

某个query head需要的是同一head的各KV sequence片段。

如果不同rank负责不同head范围，通信计划需要把这些范围分解成一致的子任务。

每个子任务应携带或确定：

```text
head_start / head_count
KV source sequence range
local query range
causal或document mask语义
数据buffer与完成事件
```

batched异步P2P可以并发提交任务，但不会自动修复范围错配。

计算与通信重叠前先检查逻辑覆盖。

## 18. 三阶段调度器

论文调度过程依次缩小候选空间。

第一阶段按带宽图构造A2A分组候选，保留较好的分区。

第二阶段把各组看作超节点，用算力比例、平方根比例及内存上限等种子生成sequence分配。

第三阶段以坐标下降微调token与整数head份额，只接受满足容量且预测延迟下降的移动。

最后返回搜索到的最低成本可行候选。

这是有限候选与局部改进过程，不是对任意集群证明全局最优。

## 19. 性能模型应看关键路径

可把一个block拆成non-attention、A2A和多个ring步骤：

$$
T_{block}\approx\max_d T_{nonattn,d}
+\max_g T_{A2A,g}+\sum_tT_{ring,t}.
$$

remote ring步骤中可用：

$$
T_{ring,t}\approx\max_d\max(T_{compute,d,t},T_{comm,d,t}).
$$

局部步骤没有对应远端通信。

这种模型假设一定程度的重叠，真实资源争用与排队可能使预测偏差增大。

### 19.1 内存模型

除了固定模型状态，还要计A2A前的局部sequence激活，以及本组sequence与本rank heads决定的KV staging。

更长局部sequence与更多heads都会消耗内存，但影响的对象不同。

不能只按GPU显存大小比例分token而忽略head与通信buffer。

## 20. 实机与模拟必须分开

HexiSeq v1的直接实机范围包括最多16张混合H100/A100、3B—13B模型和最高256K的配置。

32—128卡、70B以及最高1024K属于其模拟研究范围。

论文给出模拟模型与实机对照，并不把模拟自动升级为实机证据。

因此综述中的“3B—70B、最高1M”应拆开写适用层次。

本篇没有复现实机或模拟器。

## 21. 两种方法如何接入现有训练系统

AutoSP接入时优先检查图捕获范围、识别集合、新collective反向和AC边界。

HexiSeq接入时优先检查计划生成、非均匀split、head身份、group创建和缓存。

两者共同需要检查：

- 参数梯度覆盖了全部数据贡献且没有重复。
- loss mask和有效token分母正确。
- RNG与重计算行为相容。
- checkpoint能恢复输入游标与必要计划身份。
- 新shape/plan引起的compile与graph cache成本被记录。

论文不等于当前Megatron已经提供同名可用开关。

## 22. 排障与验收

| 症状 | 优先检查 |
|---|---|
| 编译后shape合法但输出错 |token/head轴身份与手工索引 |
| forward对、backward错 |通信梯度算子与逆布局 |
| SAC省显存却大幅变慢 |是否重算A2A、关注kernel/通信占比 |
| 异构快卡仍等待 |head/token份额、最慢链路与容量约束 |
| ragged A2A hang |逐src-dst split是否匹配 |
| 模拟快、实机慢 |拥塞、launch、非线性GEMM效率与模型残差 |

先验证小确定输入，再扩展shape与设备数量。

## 23. 自测与详细答案

### 题1：AutoSP是否自动处理任意未知attention代码？

论文变换依赖识别出的算子与人工整理集合。

新custom operator需要验证图语义与变换覆盖，不能由自动化名称推断支持。

### 题2：为什么在长上下文中重算matmul可能相对便宜？

固定模型的线性部分随S增长，而dense attention主要随S平方增长。

相对占比下降不等于绝对成本为零，也不保证稀疏模型仍满足相同比例。

### 题3：相同numel能证明A2A正确吗？

不能，token与head身份可能错配。

应检查每个逻辑元素的源和目的，并验证反向逆变换。

### 题4：HexiSeq是在优化长短样本batch吗？

重点是把一条长上下文的sequence/head任务分配给异构设备和链路。

这与变长样本打包是互补问题。

### 题5：坐标下降返回的最佳计划是否有全局最优保证？

不能由该启发式搜索过程直接保证。

它只比较被生成和细化的可行候选，且依赖成本模型准确性。

### 题6：论文写支持70B与1M，是否说明16卡实机跑过该组合？

不能，需分开其直接测量与模拟范围。

v1的大规模70B/1024K结果属于模拟部分。
