## 本章要解决的问题

一个模型服务器能生成文本，还不等于生产平台能够稳定服务真实用户。
生产系统需要定义身份、能力、配额、排队、输出、取消和恢复。
这些约束最终要落到 GPU、KV 和网络资源上。
本章沿请求生命周期把它们连起来。

本章小节编号统一为 9.x。
原导读路径保留，详细教学进入三篇独立正文。

## 1. 认证、授权与配额

认证确定调用者身份。
授权确定可访问的模型、工具、adapter 和数据域。
配额限制请求、token、并发、KV 和内部资源成本。

客户端传来的 tenant 字段不是可信身份。
API 兼容也不等于已经实现完整多租户隔离。
具体引擎的认证开关和内部端点需按安装版本核对。
生产入口应有明确的 TLS、身份校验、能力授权和网络边界。

## 2. 多层背压

```text
Gateway: connection / size / RPM
Router: health / deadline / KV / tenant
Engine: waiting / running / token / block budget
Writer: bounded bytes / write timeout / cancel
```

只限 RPM 会忽略长请求的资源差异。
只限 engine 并发可能挡不住 CPU 和连接层过载。
慢客户端也会占用共享 buffer 与 KV。
每一层都需有界队列和向上游传播的结果。

## 3. 流式语义

请求需要 event 序号、finish reason、错误和 usage。
协议重连不等于生成状态恢复。
未输出 token 前可以在幂等与兼容约束下重试。
已经输出后，透明重跑可能造成重复、分叉和重复计费。

```text
logical request
  → attempt 1
  → attempt 2 only under explicit retry rules
```

如需 resume，应明确 accepted tokens、模型身份、采样状态和工具副作用。
不承诺无法证明的 exactly-once。

## 4. 路由先过滤，再评分

先过滤模型能力、安全域、健康和硬容量。
再比较 queue、compute、transfer、network 与缓存节省。
缓存命中率高的副本不一定最快。
Router hint 可以最终一致，worker 必须实际验证 KV。

Prefix-aware 路由还应有负载上限和随机化，避免热点副本被持续追逐。
记录 predicted hit 与 actual reusable tokens，才能解释失效。

## 5. 扩缩容需要启动提前量

模型启动包含镜像、权重、解析、H2D、通信组、JIT、graph 与 warm-up。
新 GPU 分配成功不等于已具备服务能力。
响应式扩容期间仍可能积累大量队列。
因此需要预测、warm pool 和有界准入。

扩缩信号至少包括 queue age、waiting tokens、KV pressure 与 SLO。
GPU utilization 可以辅助判断，但不能单独代表有效服务能力。
同一模型的 service rate 随长度、OSL 和缓存而变化。

## 6. 三类探针

| 类型 | 语义 |
|---|---|
| startup | 给慢加载足够启动窗口 |
| readiness | 当前可否接新请求 |
| liveness | 是否需要重启恢复 |

长启动误配 liveness 会产生反复重启。
缩容则先摘流、drain，再停止 worker group。
stream 结束和 GPU/transport drain 仍需分别跟踪。

## 7. 故障处理的五个问题

1. 如何发现？
2. 如何限制影响范围？
3. 如何恢复？
4. 如何保证输出与内存正确？
5. 用户和计费看到什么？

OOM、collective hang、fail-slow、KV transfer failure 和网络断开各有不同答案。
“失败就重试”会放大过载，并可能破坏流式语义。
多 rank 失败应按实际计算组协调隔离与恢复。

## 8. 容量与故障域

如果每副本可交付 10 req/s，峰值是 80 req/s，则至少需 8 个可用副本。
要容忍一副本失败，需要至少 9 个。
若同节点放两个副本并要求容忍整节点失败，则至少 10 个。

冗余比例需要结合 placement 和故障域计算。
平均服务率还必须配合每 rank 显存与最长合法请求检查。
不能只按 QPS 估算 GPU 数。

## 9. 本章验收任务

- 用两个 token bucket 实现原子准入判定。
- 算慢客户端 buffer 填满时间。
- 比较高缓存长队列与低缓存短队列的 ETA。
- 算冷启动期间 backlog 与扩容后的排空时间。
- 模拟部分 stream 后禁止透明重试。
- 为 OOM、rank failure 和 KV ack 丢失写验收条件。

正文代码均为 CPU 教学模型，不操作真实生产服务。
硬件与多节点故障验证需要独立的受控环境。
