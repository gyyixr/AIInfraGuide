## 5. DeepSeek专题的来源另行登记

DeepSeek模块不是三份材料的简单合并，而是继续查阅官方研究、模型卡、开放参考实现和项目仓库。

阅读[开放权重、代码与论文边界](./模块七-DeepSeek开放技术详解/1.2-开源代码开放权重与论文披露边界.md)后，再进入架构、训练、推理、算子通信、存储和Agent生态。

各项目具有独立SHA与支持矩阵。尤其注意：

- 旧版DeepEP/NVSHMEM教程与新版接口不能混用。
- FlashMLA的模型、GPU与缓存格式随版本变化。
- DeepInfer公开核心、模型参考实现和完整生产服务不是同一交付物。
- Ascend接口同名不保证与CUDA分支功能完全相同。
- 3FS、小型CPU状态机和真实存储集群恢复属于不同验证层次。

固定仓库记录在`docs/expansion-2026/deepseek-source-snapshots.json`；模型与论文证据在`deepseek-architecture-sources.json`。具体限制仍应以文章对应版本为准。

## 6. 五层证据怎样阅读

| 证据层 | 可以说明 | 不能直接推出 |
|---|---|---|
| 公式与手算 | 明确假设下的代数、数量与状态关系 | 实际kernel速度 |
| CPU oracle | 给定输入的索引、梯度或状态断言 | GPU stream、NCCL与网络行为 |
| CPU/Gloo或普通PyTorch GPU | 对应后端上的有限输入正确性 | 专用DeepSeek kernel、完整LLM训练 |
| 官方固定源码/文档/论文 | 该版本的实现、公开合约或作者实验结果 | 本机已复现、其他版本同样成立 |
| 目标硬件与系统实验 | 记录条件下的数值、质量与性能 | 无条件跨模型、跨拓扑推广 |

每篇中的“教学模型”“源码静态核对”“未执行GPU”等说明都是结论的一部分。

## 8. 如何查版本冲突

先确认文章引用的是固定commit、正式tag、版本化文档还是滚动latest页面。

再检查依赖、硬件、训练/推理模式、shape与precision recipe。

如果两个来源描述不同，保留各自范围并回到对应实现和测试，不能只选发布时间较新的那句话。

例如MCore的MTP训练测试意图与某版本功能页限制，可以同时作为需要复核的证据；不能直接把训练路径结论推广到speculative inference。

当前框架源码的新入口也可能与旧材料不同，见[TorchTitan](./模块三-分布式训练/17.1-TorchTitan与原生PyTorch训练生态.md)、[MaxText](./模块三-分布式训练/17.2-MaxText与JAX的分片和训练系统.md)和[开放框架比较](./模块三-分布式训练/17.3-开放训练框架选型与集成契约.md)。

## 9. 覆盖审计如何帮助继续学习

覆盖矩阵保留尚浅或未执行的部分，帮助选择下一项研究，而不是把所有链接都标成完成。

例如部分具名可靠性论文、完整μP参数化迁移、全部高级TE/MoE组合，以及源报告全量题目映射，仍应按审计的具体条目判断。

找到缺口后，先补原始来源和最小可证伪例子，再补版本化实现，最后做目标环境实验。

阅读到本文时，可以先选[进阶导航](./训练推理与DeepSeek进阶学习导航.md)中的一条路线，完成一个有输入、断言、输出和边界的闭环。
