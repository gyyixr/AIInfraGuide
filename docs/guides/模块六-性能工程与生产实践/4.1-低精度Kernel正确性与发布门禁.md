## 正确性不是一个 allclose 调用

算子数值接近，不一定保持mask、position或输出协议。
Forward正确，也不代表训练backward正确。
单次执行正确，更不证明异步并发下buffer不会被提前复用。
因此发布门禁需要分层，而不是使用一个全局误差阈值。

本节用纯Python验证量化误差和RMSNorm导数。
这不能替代目标GPU的race、sanitizer或低精度指令验证。
模型质量和训练收敛仍需真实任务评测。

## 1. 四层正确性

| 层 | 核心问题 |
|---|---|
| 语义 | shape、mask、position、边界、别名 |
| 数值 | dtype、累加、scale、误差与异常值 |
| 生命周期 | stream/event、地址、异步回收 |
| 系统质量 | 训练梯度/收敛、推理任务/协议 |

任何一层失败都不能用其他层的平均分补偿。
错head映射不能通过放宽atol接受。
提前stop得到更短延迟，不是有效优化。
重复执行外部工具调用也不是数值误差。

## 2. Reference 的等级

第一层是易理解的数学或高精度CPU实现。
第二层是可信框架实现，覆盖真实shape与设备。
第三层是端到端模型/训练reference。

```text
mathematical reference
  → tensor/operator reference
  → optimized kernel
  → model/step/service integration
```

高精度reference也要确认语义。
例如RMSNorm的epsilon位置、weight是w还是1+w，可能随模型变体不同。
不要因为名字相同就假设公式相同。

## 3. 误差指标与阈值

绝对误差：

$$
e_{abs}=|y-\hat y|.
$$

相对误差：

$$
e_{rel}=\frac{|y-\hat y|}{\max(|y|,\epsilon_{floor})}.
$$

接近零时相对误差可能被放大，需合理floor或联合atol/rtol。
还可记录max、mean、RMS、cosine和任务级指标。
不能只报告平均误差，让少数严重错误消失。

### 3.1 阈值要来自路径

FP32、BF16、FP16、FP8与整数反量化的可接受误差不同。
累加长度、条件数、reduction次序和scale也影响误差。
训练梯度可能比forward更敏感。
应按dtype、shape与业务定义预算，并保留最差样本。

## 4. 对称量化的手算

取对称整数范围 $[-7,7]$，scale为：

$$
s=\max|x|/7,\qquad q=clip(round(x/s),-7,7).
$$

反量化 $\hat x=sq$。
对 $x=[-1,-0.2,0.1,1]$，$s=1/7$。
量化约得到 `[-7,-1,1,7]`，恢复 `[-1,-1/7,1/7,1]`。
中间两项有舍入误差，最大约0.05714。

这个教学范围没有覆盖所有4-bit实际编码约定。
真实格式可能有非对称零点、不同clamp范围和group scales。
必须核对checkpoint与kernel的共同契约。

### 4.1 Group size 的取舍

更小group可以更贴近局部幅值，减轻outlier对scale的支配。
代价是更多scale/metadata和处理成本。
更大group压缩metadata，却可能让小值分辨率变差。
最终应同时测质量、内存和实际kernel，而不只MSE。

## 5. RMSNorm 的 forward 与 backward

令：

$$
r=\sqrt{\frac1N\sum_i x_i^2+\epsilon},
\qquad y_i=w_ix_i/r.
$$

若上游梯度为 $g_i$，则：

$$
\frac{\partial L}{\partial x_i}
=\frac{g_iw_i}{r}
-\frac{x_i}{Nr^3}\sum_jg_jw_jx_j.
$$

权重梯度为：

$$
\frac{\partial L}{\partial w_i}=g_ix_i/r.
$$

这个推导假设上述标准RMSNorm公式。
Residual融合、不同weight参数化或其他norm变体需要重新展开链式法则。
训练优化不能只验证forward输出。

## 6. 可运行的量化与有限差分检查

```python
import math

x = [-1.0,-0.2,0.1,1.0]
scale = max(abs(v) for v in x)/7
q = [max(-7,min(7,round(v/scale))) for v in x]
recovered = [v*scale for v in q]
max_error = max(abs(a-b) for a,b in zip(x,recovered))
assert q == [-7,-1,1,7]
assert max_error <= scale/2 + 1e-12
print("quant max error",max_error)

values = [0.2,-0.4,0.7]
weights = [1.0,0.8,1.2]
upstream = [0.3,-0.2,0.5]
eps = 1e-5

def loss(v):
    r = math.sqrt(sum(a*a for a in v)/len(v)+eps)
    return sum(g*w*a/r for g,w,a in zip(upstream,weights,v))

n = len(values)
r = math.sqrt(sum(a*a for a in values)/n+eps)
dot = sum(g*w*a for g,w,a in zip(upstream,weights,values))
analytic = [g*w/r-a*dot/(n*r**3)
            for g,w,a in zip(upstream,weights,values)]
h = 1e-6
numeric = []
for i in range(n):
    plus,minus = values.copy(),values.copy()
    plus[i] += h
    minus[i] -= h
    numeric.append((loss(plus)-loss(minus))/(2*h))
assert max(abs(a-b) for a,b in zip(analytic,numeric)) < 1e-8
print("RMSNorm analytic",analytic,"finite_difference",numeric)
```

有限差分的h需要在截断误差与舍入误差之间权衡。
它适合小规模平滑reference，不应直接用极低精度计算做严苛差分验证。
GPU backward还需检查并行reduction、写冲突与dtype路径。

## 7. 边界矩阵

| 维度 | 例子 |
|---|---|
| Shape | 1、非2次幂、非tile整除、空合法输入 |
| Layout | contiguous、stride、transpose、offset |
| 数值 | 全零、极大极小、outlier、NaN/Inf |
| Mask | 全mask、partial tail、causal边界 |
| Aliasing | in-place、共享prefix、重叠view |
| 并发 | 多stream、重复replay、取消 |
| 模型 | 长context、不同head映射、adapter |

不是所有kernel都必须支持所有输入。
但不支持的输入应明确拒绝或进入已验证fallback。
不能让未定义行为悄悄进入生产。

## 8. 低精度的六项记录

```text
storage dtype
compute input dtype
actual multiplication instruction
accumulation dtype
scale/zero-point layout
selected kernel and fallback
```

这些项决定数值和性能，不能压缩成一个“FP8=True”。
新架构可能支持不同格式与块缩放指令，旧架构可能走转换或不支持。
模型文件名称不等于运行时实际执行路径。
所有质量结果应绑定这六项与artifact。

## 9. 异步正确性不能只靠数值随机测试

一个buffer在普通顺序下正确，多stream重叠后可能被提前覆盖。
Kernel调用返回通常不代表GPU访问结束。
Graph重放还依赖长期地址和资源身份。
因此需把producer、consumer与最后completion写清楚。

```text
allocate
  → producer writes
  → ready event
  → consumer reads
  → last-use event
  → retire/free
```

故障注入应覆盖cancel、异常、timeout和快速复用相同地址。
内存守恒、ref非负和owner一致性是独立验收项。
一万个随机数值case通过，不代表一个生命周期竞态已经消除。

## 10. 多 rank 正确性分层

训练可使用四点探针：

```text
pre-reduce gradient checksum
  → post-reduce local shard
  → post-optimizer owned param shard
  → post-gather full compute parameter
```

第一个点就不同，查输入/RNG/forward/backward。
规约后才不同，查group、count、dtype、缩放和range。
更新后才不同，查optimizer state与master参数。
Gather后才不同，查ownership与地址映射。

这个方法来自Megatron固定报告的状态闭环。
它不是保证不同规约顺序逐bit一致的承诺。
应区分数值容忍、同拓扑确定性与跨拓扑可恢复语义。

## 11. 模型质量与训练稳定性

推理按任务、语言、context、reasoning、工具与结构化输出分群。
训练按loss、梯度统计、异常值、有效token与验证质量观测。
低精度改动可能在长时间积累后才出现退化。
短单步allclose不能替代缩比训练或长期服务评估。

如果模型输出长度明显改变，应检查是否提前stop或质量变化。
如果训练吞吐增加却跳过更多异常step，应报告有效进度。
质量与工作量变化必须与性能结论一起解释。

## 12. 发布门禁的顺序

| 阶段 | 必须通过 |
|---|---|
| Operator | reference、边界、目标架构 |
| Runtime | graph、并发、生命周期、fallback |
| Model | 任务质量或梯度/收敛 |
| Performance | 真实分布、原始样本、峰值内存 |
| Failure | cancel、OOM、通信/加载失败 |
| Rollout | canary、观测、完整版本回滚 |

不满足correctness的候选不进入性能排名。
性能测量可与部分质量评估并行组织，但上线需要全部关键门禁。
不能用“平均快了很多”豁免错误输出。

## 13. 一项常见失败优化

把FP32 reduction改成BF16累加，kernel更快但长向量误差明显增加。
短shape测试可能通过，长shape与outlier失败。
如果训练梯度因此改变，问题可能在多个step后才显现。

可选回退是保留FP32累加，只优化加载、融合或分块。
也可以限定短shape使用快路径，但必须有明确dispatch guard。
不要把更大atol当作默认修复。
先问误差是否符合语义与业务预算。

## 14. 六道追问与答案

### Q1：allclose通过为什么不代表整个kernel正确？

可能没覆盖mask、aliasing、边界或并发。
平均误差也可能掩盖局部严重错误。
需要语义、数值和生命周期分别验证。

### Q2：为什么训练还要验证backward？

Forward相同不保证保存状态、导数和reduction正确。
融合可能改变需要保留的中间值。
用小reference与有限差分定位，再测真实训练路径。

### Q3：相对误差为什么在零附近不好解释？

分母很小会放大微小绝对误差。
应结合absolute error、floor与任务语义。
不能只给一个最大relative error。

### Q4：量化group更小是否一定更好？

数值分辨率可能改善，但scale/metadata和kernel成本增加。
最终需看质量、容量和实际速度。
MSE不是唯一目标。

### Q5：Sanitizer通过能否证明没有KV逻辑污染？

不一定。
旧writer写进已复用但合法地址，可能不表现为普通越界。
需要generation、owner与取消竞态测试。

### Q6：不同拓扑输出不逐bit相同是否一定错误？

浮点规约顺序可以改变低位结果。
应按数值预算和质量/收敛检查。
结构性错误与允许的舍入差异必须分开。

## 15. 来源与边界

### BF16 小更新的数值直觉

在数值1附近，BF16有效尾数只有有限精度，相邻可表示数的间隔约为 $2^{-7}=0.0078125$。
若每步理想参数更新为0.001，直接在该精度上逐步加减可能多次被舍入掉。
保留更高精度master/accumulation可以累积这些小更新，再转换为计算参数。
这解释了为什么BF16指数范围较大，不等于可以忽略optimizer状态精度。

但具体框架是否保存FP32 master、moment与gradient，由optimizer路径和配置决定。
Precision-aware路径可能采用不同所有权与dtype。
不能只根据模型权重dtype推断全部训练状态。

### 误差报告应保留最差输入

一份失败样本至少保存shape、stride、dtype、seed和实际输入分布特征。
若存在敏感数据，可保存可重建的合成最小复现。
记录首个偏离的中间张量，比只保留最终模型错误文本更有定位价值。
对于分布式情况，再加rank、group、collective序号和阶段。

回归用例应锁住根因，而不是简单把当前实现输出当golden。
如果reference本身依赖同一错误路径，测试通过没有独立意义。
因此需要数学小例子、框架reference与端到端质量交叉验证。

推理宝典QUANT-001—015、KERN-025/026、CODE相关reference要求。
训练综述3.5、7、8.2；Megatron报告模块C mixed precision与四点状态探针。
该报告固定48a887f的普通optimizer条件不推广到所有precision-aware路径。

- [PyTorch numerical accuracy](https://docs.pytorch.org/docs/stable/notes/numerical_accuracy.html)：浮点与后端数值边界。
- [CUDA Compute Sanitizer](https://docs.nvidia.com/compute-sanitizer/ComputeSanitizer/index.html)：设备内存与同步检查入口。
- [PyTorch CUDA semantics 2.15](https://docs.pytorch.org/docs/2.15/notes/cuda.html)：异步访问与graph生命周期。

CPU误差与导数例子只证明所写公式和代码一致。
真实低精度kernel、模型质量和训练稳定性仍需对应设备与任务验证。
