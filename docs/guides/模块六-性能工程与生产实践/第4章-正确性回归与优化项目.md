## 本章定位

以数值reference、梯度、异步资源和模型质量保护性能优化，组织可复核综合实验。
本章将公式、状态机、CPU算例和官方资料结合起来。
它不把理论上界、源码静态证据和硬件实测混成一个结论。

## 1. 正确性有多个层次

语义包括shape、mask、position、aliasing与停止条件。
数值包括dtype、累加、scale与异常值。
生命周期包括stream/event、graph地址和异步回收。
系统层还包括训练梯度/收敛、推理任务质量与协议。

## 2. Reference 与误差预算

从可手算的数学小例子到框架reference，再到模型/step。
Forward通过不证明backward正确。
平均误差不证明最大误差与长上下文合格。
低精度阈值需绑定dtype、shape、任务，而不是统一放宽atol。

```text
semantic contract
  → mathematical reference
  → operator tests
  → runtime/concurrency tests
  → model or training quality
  → performance and rollout
```

## 3. 多 rank 状态探针

训练可比较pre-reduce梯度、post-reduce shard、post-update参数与post-gather参数。
第一个偏离点帮助区分数据、通信、optimizer与range mapping。
推理可比较输入token、slot、KV有效长度、accepted输出与stream。
不同拓扑的低位差异与结构性错误需要分开。

## 4. 六项综合实验

RMSNorm/residual比较训练与推理forward/backward。
Shape specialization与Graph buckets比较冷/热生命周期成本。
梯度bucket与overlap比较visible comm和compute slowdown。
NUMA/IO/checkpoint实验观察数据与通信争用。
低精度实验联合质量、时间与容量。
Fail-slow实验追踪最早分歧与恢复的有效工作损失。

每项都先固定合同，再做消融和配对测量。
失败尝试与无收益区域也是正式产物。
没有硬件时交付CPU模型与待测矩阵，不能编造设备收益。

## 5. 动手任务

- 手算对称量化与scale误差。
- 用有限差分核对RMSNorm输入梯度。
- 设计shape/stride/mask/并发边界矩阵。
- 用合成账本比较单项与组合优化收益。
- 画多rank checksum探针。
- 写一个包含回退条件的实验报告。

## 6. 学习验收

能解释allclose未覆盖哪些风险。
能区分模型权重dtype与optimizer/master状态dtype。
能说明为什么两个speedup不能机械相乘。
能交付原始数据、实际dispatch、统计口径和可复跑步骤。

## 7. 建议的证据台账

| 类型 | 保存内容 |
|---|---|
| 版本 | framework commit、依赖与artifact |
| 工作量 | shape/trace/seed、有效与执行口径 |
| 资源 | peak memory、bytes、inflight状态 |
| 时间 | wall/device边界与关键路径 |
| 质量 | reference、任务或训练护栏 |
| 统计 | 重复、配对、分群与原始样本 |
| 边界 | 失败、fallback与未验证硬件 |

每篇都有至少一个完整手算或可运行CPU小例子。
这些代码只验证所写模型，不自动验证真实GPU、网络或存储。
进一步实验应保持同样的时间与数据口径。

## 8. 参考资料与版本规则

本模块整合推理面试宝典的PERF/KERN/DIST/PROD/PROJECT部分。
训练综述补充跨训练的算子、通信、数据与可靠性视角。
Megatron报告补充schedule、optimizer ownership、overlap与公式口径。

Megatron参考源码冻结为48a887fecd01674346f724dcf44f417f455989f0。
Stable0.19是另一层证据，不因包字符串相近就视为同一实现。

动态官方文档用于方法与API边界，安装环境仍需独立核验。

## 9. 阅读后的下一步

先列出哪些输入必须支持，哪些应明确拒绝或fallback。
为关键语义准备独立reference，避免把当前实现输出直接当golden。
训练增加backward与状态探针，推理增加stream与KV生命周期。
把性能统计和质量阈值写在实验开始之前。
最后给出完整artifact/runtime回滚条件。

选择一个真实瓶颈，写出可证伪假设与最小实验。
先确认有效工作和正确性，再衡量关键路径变化。
出现与预测不同的结果时，保留失败并修正模型。
完成时交付可复跑数据、条件与回退，而不是孤立的最佳数字。
