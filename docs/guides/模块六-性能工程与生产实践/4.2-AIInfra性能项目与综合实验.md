## 性能项目的产物应是一条能被复核的因果链

本模块已经建立FLOPs/bytes、统计、微架构、编译、网络与IO模型。
本节将它们组合成可分阶段完成的实验。
与推理项目路线不同，这里重点是跨训练与推理的机制归因。
每项实验都需要证明为什么变快，以及什么时候不值得启用。

没有目标GPU时先运行CPU成本模型。
有单GPU后补kernel和runtime证据，有集群后再补通信与fail-slow。
各证据层分开，不以模拟替代设备测量。

## 1. 统一实验合同

```text
Objective: 最终优化哪项有效工作
Baseline: 硬件/版本/模型/shape/trace
Hypothesis: 预计减少哪项资源或等待
Intervention: 只改变哪些主要变量
Guardrails: 正确性/质量/容量/可靠性
Measurement: 时间边界、采样单位、重复与统计
Ablation: 如何拆出机制和交互
Rollback: 怎样恢复可比较基线
```

先写合同，再运行扫描。
这样可以避免看到结果后改变聚合方式或删除失败shape。
所有图表与结论应能回到原始样本。

## 2. 实验 A：同一 RMSNorm 的训练与推理路径

### 假设

Residual融合减少中间HBM读写与launch。
训练还要保留backward所需数据，可能改变activation峰值和反向性能。
因此forward speedup不能直接等于训练step speedup。

### 对照与消融

| 版本 | Forward融合 | Backward优化 | Graph |
|---|---|---|---|
| A0 | 否 | 否 | 否 |
| A1 | 是 | 否 | 否 |
| A2 | 是 | 是 | 否 |
| A3 | 是 | 是 | 是 |

训练测forward+backward+完整step。
推理测相同shape的forward与真实调用频率。
记录寄存器、spill、HBM流量和峰值内存。

### 验收与回退

用4.1的导数reference与边界矩阵验证。
出现spill或长shape退化时，用dispatch guard保留原路径。
最终给出按shape和训练/推理分开的收益表。
不把一个小矩阵的最佳数字推广全模型。

## 3. 实验 B：shape specialization 与 graph buckets

### 假设

有限bucket减少compile/capture次数和host提交成本。
Padding与graph pools可能增加计算和显存。
寻找整体生命周期成本最小的bucket集合。

### 负载

使用真实或明确合成的shape频率，而不是等权随机尺寸。
训练包含变长packing和microbatch变化。
推理包含prefill/decode、burst与低频长context。

### 对照

```text
eager baseline
static specialization per shape
dynamic shapes
coarse buckets
fine buckets
hot buckets + long-tail eager
```

记录cold time、steady time、变体数、padding、graph hit与峰值内存。
分开统计codegen和CUDA Graph收益。
使用guards/recompile日志解释失败原因。

### 验收与回退

每个bucket验证有效长度、mask和static buffer身份。
对未覆盖shape回到已验证eager或动态路径。
按预计生命周期调用次数计算编译回本，而非只看warm单次速度。

## 4. 实验 C：梯度 bucket 与通信重叠

### 假设

较小bucket可以更早发送，隐藏更多梯度同步。
但更多collective会增加固定延迟和SM/HBM争用。
最佳点由ready时间、消息分布和实际拓扑共同决定。

### 固定条件

固定global batch、有效target tokens、精度、模型与rank groups。
保存Megatron/框架commit、NCCL、GPU/NIC拓扑。
关闭其他新特性建立正确性基线，再逐项打开overlap。

### 观测

```text
bucket ready timestamp
collective start/end
last exposed communication
concurrent GEMM slowdown
step time and target tokens/s
peak/inflight memory
```

用大、小、中bucket至少三档，按ABBA或随机化顺序重复。
检查所有rank的collective顺序和梯度数值。

### 验收与回退

若visible comm下降但compute slowdown更大，判定该点失败。
如果资源或数值异常，可关闭overlap回到串行同步。
不能用“时间线有重叠”替代step收益证据。

## 5. 实验 D：NUMA、IO 与 checkpoint 干扰

### 假设

数据CPU处理或远端NUMA流量造成GPU空隙。
有限prefetch和正确buffer复用可隐藏输入开销。
Checkpoint并发可能重新占满同一主机/网络路径。

### 对照

| 变量 | 档位 |
|---|---|
| workers | 少/中/多 |
| prefetch | 1/2/4批 |
| 数据路径 | remote/local cache |
| NUMA | 默认/基于实际拓扑的策略 |
| checkpoint | 无/并发/隔离路径 |

改变绑定属于真实实验操作，应在明确环境授权下进行。
本教程的CPU算例不会修改系统亲和性。

### 验收与回退

记录data-wait p99、CPU/RSS/pinned、page faults、IO、H2D与step。
恢复时检查数据游标与packing状态，不只检查模型参数。
内存或尾部恶化时降低prefetch/workers，而不是无限增大队列。

## 6. 实验 E：低精度的端到端收益与质量约束

### 假设

降低权重或activation字节可减少带宽/通信成本。
转换、scale处理、fallback和误差可能抵消收益。
训练与推理的质量约束分别验证。

### 设计

先固定BF16/FP32 reference，再一次改变一个低精度层次。
记录storage、compute、accumulation、scale、kernel与硬件支持。
对真实shape分布测forward/backward、通信字节和峰值。

### 验收与回退

训练至少做缩比稳定性与目标验证质量，推理按任务/语言/context分群。
出现某层或某shape不合格时，采用明确高精度fallback或回滚artifact。
不要通过放宽全部误差阈值掩盖结构错误。
最终报告质量—时间—内存三维可行域。

## 7. 实验 F：尾部 rank 与失败恢复成本

### 假设

同步系统由最慢rank决定关键路径，平均利用率会掩盖fail-slow。
对照组中注入受控延迟，可以验证定位与隔离方法。
这应先在模拟或隔离集成环境完成。

### 机制

每层/collective记录各rank到达和结束时间。
关联CPU、频率、温度、NIC与专家负载。
区分工作分布不均、硬件慢和网络慢。

### 验收

能在全局超时前定位最早异常阶段。
恢复后检查参数/数据/请求代际与资源守恒。
记录故障导致的lost useful work与恢复wall time。

### 回退

不要自动驱逐所有最慢rank，先判断是否属于合法长样本或热点专家。
有证据的失效域再隔离，并按框架支持方式重建组。
性能恢复不能以错误输出或不一致状态为代价。

## 8. 可运行的优化预算与消融账本

下面数据为合成结果，只演示如何解释收益。

```python
baseline = {"compute":80,"visible_comm":30,"host":10}
variants = {
    "bucket_only": {"compute":80,"visible_comm":20,"host":12},
    "overlap": {"compute":95,"visible_comm":10,"host":10},
    "kernel_only": {"compute":70,"visible_comm":30,"host":10},
    "combined": {"compute":84,"visible_comm":10,"host":12},
}
old = sum(baseline.values())
assert old == 120
for name,parts in variants.items():
    total = sum(parts.values())
    print(name,"total_ms",total,"speedup",old/total)

assert sum(variants["overlap"].values()) == 115
assert sum(variants["combined"].values()) == 106

# 预测可以独立相乘的收益，可能与真实组合不同。
independent_prediction = (
    old/sum(variants["overlap"].values())
    * old/sum(variants["kernel_only"].values())
)
actual_combined = old/sum(variants["combined"].values())
print("independent_product",independent_prediction)
print("measured_combination_model",actual_combined)
assert abs(independent_prediction-actual_combined) > 1e-3

rank_ms = [18,19,18,45]
assert max(rank_ms) == 45
assert sum(rank_ms)/len(rank_ms) == 25
print("critical_rank",rank_ms.index(max(rank_ms)),"step_lower_bound",max(rank_ms))
```

账本里的visible_comm已经是不可隐藏部分，不能再扣一次overlap。
真实trace中阶段可能还有复杂依赖，应使用关键路径图核验。
合成“measured combination model”只表示表内给定值，不是硬件测量。

## 9. 实验报告的固定结构

1. 业务或训练目标与约束。
2. 环境、artifact、版本和workload。
3. 基线关键路径与资源模型。
4. 假设、改动与备选方案。
5. Correctness/质量/生命周期证据。
6. 分shape/分群的原始A/B与统计。
7. 消融、反例、失败尝试。
8. 成本、上线条件与回退。

结果先报告有效工作和完整wall time。
微架构数据随后解释机制。
把公式假设与实测字段分开，缺项写未测。
不要用估算数字填充profile表格。

## 10. 三种证据层的升级

| 层 | 能证明 | 不能证明 |
|---|---|---|
| CPU模型 | 算术、状态、调度假设 | GPU/NIC实际性能 |
| 单GPU | 目标架构kernel与局部runtime | 多节点拓扑与collective尾部 |
| 集群 | 实际网络/分组/故障域 | 所有规模与所有负载 |

每层都应保留可重复输入与环境。
从一层升级到下一层时，比较模型预测误差。
误差不是要掩盖的缺点，而是下一轮建模的线索。

## 11. 评审时最该问的八个问题

- 是否处理了相同有效工作？
- Correctness与质量有没有变？
- 变化是否位于关键路径？
- 中间计数器是否支持机制解释？
- 编译、warm-up和内存成本是否计入？
- 统计单位是否独立，顺序是否公平？
- 有哪些退化shape与故障边界？
- 怎样在目标环境回滚？

如果这些问题没有答案，先补证据再扩大优化范围。
不要用更复杂的架构替代对原瓶颈的理解。

## 12. 六道追问与答案

### Q1：为什么优化收益不能直接相乘？

两个改动可能消除同一开销，或改变彼此的资源瓶颈。
Fusion减少launch后，graph的可优化比例也变小。
需要组合实验和消融。

### Q2：CPU模拟最大的价值是什么？

快速验证单位、状态不变量、调度与成本假设。
它可以排除明显不合理方案。
但不能证明硬件带宽、并发或memory ordering。

### Q3：训练项目怎样防止“少算提速”？

保持有效target tokens、数学batch、loss mask和更新语义可比。
检查跳步、padding、recompute口径。
最终结合质量门槛和wall time。

### Q4：推理项目怎样防止“少服务提速”？

保留失败、拒绝、超时、OSL和质量统计。
按相同cohort和SLO计算goodput。
不能删除长尾请求后比较延迟。

### Q5：一个失败优化怎样写成有价值的结果？

展示预测、反证数据、根因和保留的工具或认识。
例如overlap降低通信尾部，却使GEMM变慢更多。
说明不适用条件比隐藏失败更有工程价值。

### Q6：何时结束调优？

当目标已满足、收益低于噪声或维护成本，且主要风险已验证。
不要为了更漂亮的局部数字无限扩范围。
交付可运行结果、边界和回退即可。

## 13. 来源与能力映射

### 最小交付的停止条件

每项实验至少有一个能复跑的基线、一条被验证或被证伪的机制，以及一个失败边界。
若没有目标硬件，就交付CPU模型、待测矩阵与明确的设备假设。
若已有硬件结果，就同时保存环境、原始数据和实际dispatch。
实验结束时清楚列出哪些结论来自计算、静态源码、单GPU或集群。
这样下一位读者可以补齐剩余证据，而不必重新猜测实验口径。
未测的结果保持未测，不用乐观估计填补。
