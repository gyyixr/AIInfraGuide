## 本章定位

从有效工作、资源下界、关键路径与统计实验建立跨训练推理的性能判断。
本章将公式、状态机、CPU算例和官方资料结合起来。
它不把理论上界、源码静态证据和硬件实测混成一个结论。

## 学习路径

- [跨训练推理的 Roofline 与关键路径](./1.1-跨训练推理的Roofline与关键路径.md)。
- [统计测量、基准设计与性能归因](./1.2-统计测量基准设计与性能归因.md)。

若继续做GPU或集群实验，按正文矩阵冻结环境并保留原始数据。

## 1. 先统一工作量

训练的有效target tokens、模型公式FLOPs与实际执行FLOPs不同。
Padding、重算、低精度转换和稀疏路由可能改变实际工作。
推理也要区分候选、接受输出与满足SLO的交付。
报告不能在两个配置间悄悄更换分子。

## 2. Roofline 的资源边界

算术强度是FLOPs除以所建模内存层的实际字节。
HBM、L2、shared与逻辑tensor大小不能混用。
理论峰值要绑定dtype、指令模式与设备条件。
资源上界可以排除不可能收益，但不是精确性能预测。

```text
work definition
  → FLOPs / bytes
  → resource lower bounds
  → dependency graph
  → measured critical path
```

## 3. 关键路径比时长求和更重要

并发kernel、通信和数据处理的持续时间不能机械相加。
训练bucket ready决定通信何时开始，最慢rank决定同步尾部。
推理排队和CPU可能比GPU执行更重要。
重叠还可能让计算变慢，需同时测visible comm与compute slowdown。

## 4. 统计与归因

固定artifact、硬件、workload和时间边界。
使用成对、随机化或交错实验降低顺序偏差。
保留独立运行单位、重复次数和原始样本。
置信区间不能弥补没有覆盖真实shape与故障。

调参集与最终验证集分开。
同时修改fusion、graph和batch时，需要消融解释交互。
平均speedup、总时间比值与按业务分布加权具有不同含义。
聚合口径应在看结果前确定。

## 5. 动手任务

- 手算M=1与M=4096 GEMM的FLOPs和理想流量。
- 用依赖图计算重叠后的最长路径。
- 比较通信隐藏与计算slowdown。
- 复算配对bootstrap的合成区间。
- 构造平均speedup误导总时间的反例。
- 为一个真实优化写假设、反证与消融矩阵。

## 6. 学习验收

能说清MFU分母是否包含通信、bubble与data wait。
能区分训练step更快与time-to-quality更短。
能解释统计显著性与工程价值的不同。
能指出实验中哪些变量已固定，哪些仍不确定。

## 7. 建议的证据台账

| 类型 | 保存内容 |
|---|---|
| 版本 | framework commit、依赖与artifact |
| 工作量 | shape/trace/seed、有效与执行口径 |
| 资源 | peak memory、bytes、inflight状态 |
| 时间 | wall/device边界与关键路径 |
| 质量 | reference、任务或训练护栏 |
| 统计 | 重复、配对、分群与原始样本 |
| 边界 | 失败、fallback与未验证硬件 |

每篇都有至少一个完整手算或可运行CPU小例子。
这些代码只验证所写模型，不自动验证真实GPU、网络或存储。
进一步实验应保持同样的时间与数据口径。

## 9. 阅读后的下一步

开始实验前，用一页纸回答：

- 分子是有效token、model FLOPs还是executed FLOPs？
- 分母是否含编译、排队、通信与排空？
- 哪个阶段位于最长依赖路径？
- 哪些样本属于独立重复，哪些只是同一轮内相关测量？
- 哪个结果会推翻当前假设？

这些答案决定后续profile和统计是否可解释。

选择一个真实瓶颈，写出可证伪假设与最小实验。
先确认有效工作和正确性，再衡量关键路径变化。
出现与预测不同的结果时，保留失败并修正模型。
完成时交付可复跑数据、条件与回退，而不是孤立的最佳数字。
