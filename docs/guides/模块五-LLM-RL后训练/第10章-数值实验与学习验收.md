## 本章概述

前面九章介绍了算法与系统。本章把两者连接起来：先用几组可以手算的数字核对损失，再运行一个有真实采样、真实参数更新和显式策略版本的微型环境。

实验放在仓库 `labs/llm_rl/`，只需要 Python 3.10 或更高版本的标准库，不下载模型，不要求 CUDA。这样可以把注意力集中到“计算的对象是否正确”，而不是先花时间解决大模型依赖。

**实验边界**：训练对象是四个上下文、四个动作的分类策略表，每个回答只有一个 token。它能验证算法计算和状态流转；没有 Transformer、KV Cache、Ray、NCCL 或推理引擎，因此不能证明完整 LLM 训练已跑通，也不能用于推断大模型性能或泛化质量。

## 10.1 从手算到程序校验

专题 **10.1 后训练数值实验：从公式到断言** 依次核对：

| 检查项 | 输入 | 应观察的结果 |
|---|---|---|
| GRPO 组内标准化 | 奖励 `[0,0,1,1]` | 优势约 `[-1,-1,1,1]` |
| 零方差组 | 奖励完全相同 | 优势全部为零，没有 NaN |
| PPO 裁剪方向 | 正/负优势配合不同 ratio | 只截断已经朝有利方向过大的改动 |
| GAE | 三步奖励、四个 value、终止标记 | 逐步倒序计算结果与脚本一致 |
| DPO | 当前策略与参考策略相同 | 初始损失为 `ln(2)` |
| response mask | 含 padding 的数组 | padding 不改变损失分母或分子 |
| 解析梯度 | 固定采样 batch | 与中心有限差分相符 |

建议先遮住答案手算，再读函数。若结果不同，先查约定：标准差是否使用总体方差、KL 的方向、loss 的正负号，以及 sequence 平均还是 token 平均。

## 10.2 运行完整更新与恢复

专题 **10.2 最小 RL 闭环与框架迁移** 将一轮训练分为：

1. 从 rollout 策略版本 `k` 抽样，保存 old probability。
2. 环境根据固定规则判分，同一 prompt 内计算优势。
3. Actor 使用同一批轨迹做两轮优化，old probability 不变。
4. 更新完毕后发布版本 `k+1`，再复制给 rollout。
5. 保存权重、参考策略、配置、随机数状态和版本号。
6. 恢复后比较下一批样本和下一次更新，定位缺失状态。

这里的“复制权重”是 Python 数据复制。第 8 章介绍的分布式权重同步还包含参数分片转换、通信、缓存失效和版本确认，不能由本实验替代。

## 动手入口

在仓库根目录执行：

```bash
python3 -m unittest discover -s labs/llm_rl -p 'test_*.py' -v
python3 labs/llm_rl/rl_lab.py --steps 80 --output labs/llm_rl/results/latest.json
```

也可以使用 `npm run test:rl` 和 `npm run lab:rl`。第一条运行 9 项语义与数值检查，第二条打印计算结果并保存每步指标。

`labs/llm_rl/results/reference-run.json` 保留了本次 Python 3.12.3、seed=7 的参考运行。学习时对比具体数值，而不要把某一次随机实验的曲线当作算法普遍保证。

## 学习验收

- 不看实现，写出 rollout、old、current、reference 四者的关系。
- 能解释为什么初始 ratio 为 1，policy loss 却仍可能有非零梯度。
- 能找出产生奖励、计算优势、应用梯度、发布权重的实际代码。
- 能说明单 token 实验中哪些平均方式退化为同一种，哪些长序列问题尚未覆盖。
- 能断言恢复训练后的参数与连续训练完全相同，并列出成立条件。

**参考答案要点**：采样快照冻结；当前 actor 持续变化；参考策略固定用于约束；采样概率必须跟随轨迹保存。函数值为零不代表导数为零。单 token 时不存在响应长度差异，但真实模型必须处理 token shift、padding、EOS 和工具 observation。完整恢复还依赖同一实现、配置、随机数状态及确定性执行顺序。
