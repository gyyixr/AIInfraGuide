## 📖 本章概述

预训练教模型预测文本，后训练则利用示范、偏好或可验证反馈塑造模型行为。对 AI Infra 工程师而言，关键变化是：训练数据不再全部提前准备好；模型必须先生成回答、等待评分，再把这些回答送回训练系统更新权重。

因此，一次 RL 迭代同时包含推理、数据整理、模型前向评分、反向训练和权重同步。GPU 利用率、显存峰值和版本一致性，都取决于这些阶段怎样衔接。

本章先建立全局地图，再拆开每条轨迹中的 token、概率和掩码。后面的 PPO、GRPO、分布式系统章节都会沿用这些定义。

## 📑 第一部分：训练阶段与角色（正文 1.1）

### 1. 四种反馈，四种数据契约

| 阶段 | 一条数据的核心内容 | 优化信号 |
|---|---|---|
| 预训练 | 文本 token 序列 | 下一 token 的交叉熵 |
| SFT | 问题与示范回答 | 指定回答位置上的交叉熵 |
| 偏好学习 | 同一问题下的较优/较差回答 | 回答之间的相对偏好 |
| 在线 RL | 当前策略生成的轨迹与评分 | 回报或优势加权的策略梯度 |

RLHF 描述反馈来源，PPO 描述优化方法；RLVR 描述奖励可验证的任务设定，GRPO 描述优势估计与优化方法。它们不在同一个分类层级。

### 2. 五个逻辑角色

- **Actor**：待优化策略，输出 token 分布并接收梯度。
- **Rollout**：执行采样的推理角色，使用某个版本的 Actor 权重。
- **Reference**：固定或按明确规则更新的参考策略，提供偏离约束。
- **Reward**：规则、执行器、人工偏好模型等评分来源。
- **Critic**：预测前缀的未来回报，供 PPO 等方法构造优势。

五个角色不意味着五份等大的模型，也不意味着五台服务器。GRPO 通常没有 Critic；规则奖励不需要神经网络；Actor 与 Rollout 可以分时复用设备。

### 3. 手算一轮数据量

取 8 个 prompt，每个采样 4 个 response，得到 32 条轨迹。若每条最多生成 128 个 token，response 张量形状为 `[32, 128]`，实际参与训练的位置由 mask 决定。不能把 8 个 prompt、32 条轨迹和 4096 个 token 混叫成同一个 batch size。

## 📑 第二部分：轨迹与策略梯度（正文 1.2）

### 4. 语言模型的状态与动作

第 $t$ 步的状态为问题加已生成前缀，动作是下一个 token。语言模型给出的 softmax 分布就是策略；一次完整回答就是一条轨迹。

$$
\pi_\theta(y\mid x)=\prod_{t=1}^{T}\pi_\theta(y_t\mid x,y_{<t})
$$

### 5. 从序列概率到可训练损失

对期望奖励求导，会出现“回答的评分 × 该回答的 log probability 的梯度”。减去合适的基线后，就得到优势加权更新。评分可以来自不可微的程序，Actor 仍能通过自己的 log probability 反向传播。

### 6. 最容易出错的三个位置

1. **shift**：位置 $j$ 的 logits 预测位置 $j+1$ 的 token；第一个回答 token 由最后一个 prompt 位置预测。
2. **mask**：padding 不产生策略梯度；prompt 通常也不在 RL policy loss 内，但仍作为上下文参与前向。
3. **版本**：采样概率、旧策略概率、当前策略概率和参考概率承担不同职责，不能因为形状相同就互换。

## 🎯 学习目标与自测

1. 为什么 RL 训练不能只写一个普通的 `DataLoader → backward` 循环？
2. 对 8 个问题、每题 4 个回答、长度上限 128，分别写出问题数、轨迹数、最大回答 token 数。
3. 在 `prompt=[a,b]`、`response=[c,d]` 中，哪个 logits 位置用于训练 token `c`？
4. 一个 Python 判题函数不可微，为什么仍可用于训练模型？

**参考答案：** 1. 新轨迹依赖策略，必须完成生成、评分、版本标记和回传。2. 分别为 8、32、4096；有效 token 数可能更少。3. token `b` 对应的输出位置。4. 策略梯度通过采样动作的 log probability 传播；判题分数作为数值权重，不必对判题函数求导。
