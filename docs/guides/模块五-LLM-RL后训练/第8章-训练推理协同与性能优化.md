## 📖 本章概述

RL 同时面对两类性能问题：训练端希望大批量、密集矩阵运算和高效梯度通信；采样端希望连续调度、利用 KV cache，并处理长短不一的回答。让两端各自跑得快还不够，阶段切换、权重传输和队列等待也可能占据大部分时间。

本章把性能拆成三本账：**显存账、时间账、有效数据账**。每个优化都必须说明省了什么、增加了什么，以及是否改变采样或训练目标。

## 📑 章节结构

### 8.1 混合部署与权重同步

本节从一个 7B 参数的教学模型出发：

- 将训练参数、梯度、优化器、reference、rollout 权重和 KV cache 分别计账。
- 比较同卡分时、部分共卡与训练/推理分离三种部署。
- 解释 FSDP 分片、Megatron TP/PP/EP 和推理引擎布局之间的差异。
- 计算 14 GB BF16 权重的单次传输下界，并解释广播、bucket 和布局转换成本。
- 建立“停止接单—处理在途请求—加载—确认—发布”的版本协议。

权重同步不是保存一次 checkpoint 后发一个 HTTP 生成请求。它包含模型参数语义和执行一致性，必须作为独立阶段观测。

### 8.2 异步 Rollout 与吞吐优化

本节沿“生成端生产、训练端消费”的队列解释：

- Continuous batching 缩短什么等待，为什么不能自动解决组内长尾。
- 队列容量、生产速率、消费速率和样本年龄之间的关系。
- 行为策略、训练旧策略、当前策略的两段漂移及 importance ratio。
- Token 级和序列级校正的差异、支持集限制、截断偏差与有效样本量。
- 如何在固定 GPU 预算下比较同步和异步，而不是把增加硬件当作免费加速。

## 🔢 三个贯穿案例

| 案例 | 需要算出的量 | 要保留的条件 |
|---|---|---|
| 7B BF16 权重更新 | 14 GB，传输时间由有效带宽决定 | 不包含 optimizer，不假设无布局转换 |
| 16 条 4K 序列的 KV cache | 取决于层数、KV heads、head dim 和 dtype | GQA/MQA、TP 复制和 cache 分配策略 |
| 异步队列积压 | 样本年龄与版本差 | 不能只看 queue length 或 GPU 利用率 |

## 🎯 本章学习目标

- 能解释为什么模型“加载得下”不意味着 RL 全流程显存足够。
- 能分别描述训练更新、权重传输、推理加载、版本发布四个事件。
- 能根据同一模型的不同并行布局推导需要重排的参数分片。
- 能计算权重通信、KV cache 和端到端 GPU 秒。
- 能区分同步版本漂移与训练/推理数值不一致。
- 能给异步队列设样本年龄和策略版本边界，并判断校正是否可靠。

## 🧪 学习练习

有一个任务，生成占 60 秒、评分占 10 秒、训练占 25 秒、权重同步占 5 秒。只把训练从 25 秒优化到 15 秒，整轮加速多少？如果生成的错误样本比例从 10% 升到 30%，tokens/s 上升是否值得？

**参考答案**：同步总时长由 100 秒降到 90 秒，加速约 `1.11×`。第二问必须比较有效样本、验证质量和 GPU 成本；生成更快但丢弃更多样本，甚至使策略偏离目标，可能降低实际训练效率。

## 📚 阅读边界

本章的带宽、耗时和 GPU 划分例子都是可手算的假设。实际性能取决于模型、内核、网络、采样分布、奖励和部署方式。每个实测结论应注明软件版本、设备拓扑、工作负载和计时边界；不要把算术下界当作跑分。
