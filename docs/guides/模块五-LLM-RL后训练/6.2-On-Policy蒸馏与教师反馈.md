传统监督蒸馏常让学生学习教师写好的答案；学生上线后却会进入自己生成的、可能有错误的前缀。On-Policy Distillation（OPD）把训练地点移动到学生自己访问的轨迹上，让教师在这些位置提供反馈。

OPD 首先说明数据来源，不能单凭名称推出它一定用 Reverse KL、PPO、完整词表或某种固定奖励。[GKD 论文](https://arxiv.org/abs/2306.13649) 展示了学生生成轨迹与不同蒸馏损失的结合。

## 1. 谁生成，谁评分

```text
prompt x
   ↓ 学生策略生成
学生回答 y = [y1, y2, ..., yT]
   ├─ 学生/训练端：在 x + y 上重算学生条件概率
   └─ 冻结教师：在同一个 x + y 上计算教师条件概率
                         ↓
             对齐相同位置和相同 token
                         ↓
                  蒸馏 loss / advantage
                         ↓
                   仅更新学生参数
```

关键是教师读取**学生的实际回答**。如果教师重新生成另一条回答，然后拿两条不同前缀上的 logprob 直接相减，这两个概率描述的不是同一个事件。

### 1.1 与其他方法对比

| 方法 | 轨迹主要来自谁 | 反馈形式 |
|---|---|---|
| 教师答案 SFT | 教师或人工 | 硬 token 标签 |
| 固定语料分布蒸馏 | 离线数据 | 教师分布 |
| OPD | 当前或近期学生 | 学生前缀上的教师反馈 |
| 奖励优化 | Actor | 外部任务/偏好奖励 |

OPD 可与任务奖励混合，但教师模仿目标与真实任务目标仍是两项不同信号。教师可能在学生的错误前缀上不可靠，不能把教师概率等同于真值。

## 2. 固定状态上的两种 KL

固定前缀 $s$，定义学生词表分布 $p(v)=\pi_\theta(v\mid s)$，教师分布 $q(v)=\pi_T(v\mid s)$。

**Forward KL，教师到学生：**

$$
D_{\rm F}=D_{\rm KL}(q\|p)=\sum_v q(v)\log\frac{q(v)}{p(v)}.
$$

它要求学生覆盖教师有显著概率的词。教师固定时，与最小化教师软标签交叉熵具有相同学生梯度。

**Reverse KL，学生到教师：**

$$
D_{\rm R}=D_{\rm KL}(p\|q)=\sum_v p(v)\log\frac{p(v)}{q(v)}.
$$

它重点惩罚学生把概率放在教师不支持的位置。对模态覆盖与集中性的影响取决于模型容量和分布结构，不能简单理解成“永远更准确”。

命名以括号中的概率方向为准。不同资料使用“正向/反向”的参照物可能不同，写清 $D(p\|q)$ 最可靠。

## 3. 三词词表手算

设词表为 `[A, B, C]`：

| token | 学生 $p$ | 教师 $q$ | $\log(p/q)$ | $p\log(p/q)$ |
|---|---:|---:|---:|---:|
| A | 0.6 | 0.2 | 1.0986 | 0.6592 |
| B | 0.3 | 0.5 | -0.5108 | -0.1532 |
| C | 0.1 | 0.3 | -1.0986 | -0.1099 |

求和得到：

$$
D_{\rm R}\approx0.3961,\qquad D_{\rm F}\approx0.3653.
$$

每个 token 的贡献可以为负，但完整 KL 非负。学生给 A 的概率过高，它对 Reverse KL 的主要贡献为正。

### 3.1 完整分布的梯度

若学生 logits 为 $z$、$p=\operatorname{softmax}(z)$，教师冻结，则：

$$
\frac{\partial D_{\rm F}}{\partial z_j}=p_j-q_j,
$$

$$
\frac{\partial D_{\rm R}}{\partial z_j}
=p_j\left(\log\frac{p_j}{q_j}-D_{\rm R}\right).
$$

本例 Forward KL 的 logits 梯度为 $(0.4,-0.2,-0.2)$；Reverse KL 约为 $(0.4215,-0.2721,-0.1495)$。两者都降低 A，但 B、C 获得的调整比例不同。

梯度向量和为 0，与 softmax 对所有 logits 同时平移不变相一致。这是一个可手查的正确性条件。

### 3.2 完整分布的 PyTorch 计算

```python
# teacher_logits 和 student_logits: [B, L, V]
# action_mask: [B, L]，这里已对齐到相同的预测位置。
student_logp = student_logits.float().log_softmax(-1)
with torch.no_grad():
    teacher_logp = teacher_logits.float().log_softmax(-1)
p = student_logp.exp()
reverse_kl = (p * (student_logp - teacher_logp)).sum(-1)  # [B, L]
loss = (reverse_kl * action_mask).sum() / action_mask.sum().clamp_min(1)
```

这段计算的是固定输入前缀上的局部 Reverse KL；梯度经过学生的概率权重 $p$ 和 `student_logp` 两条路径。不能把 $p$ detach 后仍称为相同梯度。

## 4. sampled-token 的值与梯度分开看

如果教师接口只返回实际学生 token 的 logprob，可构造：

$$
d(a)=\log p(a)-\log q(a),\qquad a\sim p.
$$

固定状态下，$\mathbb E_{a\sim p}[d(a)]=D_{\rm R}$。但“这个数值是无偏估计”不意味着直接对采到的 `d(a)` 求导就得到完整 KL 梯度。

原因是样本 $a$ 的分布本身也依赖 $\theta$。把离散采样结果视为常量直接反传，只保留 $\nabla\log p(a)$；其 on-policy 期望为 0，缺少概率权重变化那一项。

### 4.1 固定状态上的策略梯度形式

对 KL 求导：

$$
\nabla_\theta D_{\rm R}
=\mathbb E_{a\sim p}\left[
(\log p(a)-\log q(a)+1)\nabla_\theta\log p(a)
\right].
$$

因为 $\mathbb E_p[\nabla\log p(a)]=0$，常数 1 项期望为零。定义反馈：

$$
r(a)=\log q(a)-\log p(a),
$$

就有 $\mathbb E_p[r(a)\nabla\log p(a)]=-\nabla D_{\rm R}$。

因此在固定状态、样本确由当前 $p$ 产生、教师固定等假设下，最大化该反馈的 score-function 梯度与最小化 Reverse KL 对应。

### 4.2 为什么反馈要 stop-gradient

一个最小 surrogate 写为：

```python
# sampled_logp、teacher_sampled_logp: 同一状态、同一实际 token 的 [N] logprob
feedback = (teacher_sampled_logp - sampled_logp).detach()
loss = -(sampled_logp * feedback).mean()
```

`detach()` 表示本次更新将反馈视为系数。若让梯度继续穿过 `feedback`，便额外引入乘积求导项，不再是上式推导的 score-function 梯度。

这段示意不包括 baseline、PPO clipping、离策略校正和多轮回报；不是可直接套到所有 OPD 框架的完整 loss。重复使用旧样本时，需要重新分析行为分布与当前策略的差异。

## 5. 固定前缀目标不等于完整轨迹目标

设学生生成 $y\sim\pi_\theta$，完整序列 Reverse KL 为：

$$
D_{\rm KL}(\pi_\theta(y\mid x)\|\pi_T(y\mid x))
=\mathbb E_{y\sim\pi_\theta}\left[\sum_t
\log\frac{\pi_\theta(y_t\mid x,y_{<t})}{\pi_T(y_t\mid x,y_{<t})}
\right].
$$

它的梯度既涉及当前位置的动作分布，也涉及学生如何进入后续前缀。按固定已采样前缀计算局部 KL，通常把前缀采样视为停止梯度；这是一种明确的训练选择，并不自动等于完整序列目标的全梯度。

如果采用完整轨迹的策略梯度解释，后续教师反馈可以通过 return-to-go 影响早期动作；如果把每个位置的反馈直接当作该位置的 advantage，则改变了信用分配。阅读框架时，应查清它使用的是哪种目标。

因此，“采样 token 的负 log-ratio”可能是奖励、直接注入的优势、独立 KL loss 或日志统计量。名称相似不代表计算图相同。

## 6. Top-k 教师接口丢掉了什么

完整分布传输量约为 $B L V$ 个数；仅实际 token 的 logprob 为 $B L$；Top-k 约为 $B L k$ 个概率值与 token IDs。

以 $B=4,L=1024,V=128000$ 为例，FP32 完整概率需要：

$$
4\times1024\times128000\times4\approx2.10\text{ GB}.
$$

如果只传 $k=32$ 的 FP32 logprob 和 int32 token ID，则约为：

$$
4\times1024\times32\times8\approx1.05\text{ MB}.
$$

这是裸数据量估算，不含 RPC、分片、缓存和计算开销，也不代表实测网络吞吐。

### 6.1 教师覆盖率不等于学生覆盖率

在上面的三词例子里，教师 Top-2 为 B、C：

```text
教师 Top-2 概率质量 = 0.5 + 0.3 = 0.8
学生在同一集合的质量 = 0.3 + 0.1 = 0.4
```

教师覆盖了 80% 自己的质量，却漏掉学生最偏爱的 A，那里恰好是 Reverse KL 的主要问题。只报 teacher mass 会低估风险。

如果分别把集合内概率重新归一化，再计算 KL，求的是条件分布 $p(\cdot\mid S)$ 与 $q(\cdot\mid S)$ 之间的 KL，不是原始全词表 KL。

### 6.2 尾部处理必须定义

常见选择包括保留一个 residual bucket、补查实际采样 token、合并学生与教师 Top-k、或接受明确的截断近似。每种方法都有不同成本和偏差。

如果实际学生 token 不在教师 Top-k，不能随意把教师 logprob 设为 0：logprob 0 表示概率 1。设为负无穷也会制造无限惩罚。应获取该 token 的真实概率或采用有说明的尾部近似。

## 7. tokenizer、温度与上下文契约

逐 token 概率相减要求动作空间和条件事件可比较。学生与教师使用不同 tokenizer 时，相同文本可能拆成不同 token，位置不能直接对齐。

可采用共享 tokenizer、明确的文本级评分或其他跨 tokenizer 蒸馏设计；不能简单按 token 索引 zip 两个 logprob 数组。

还应对齐 BOS/EOS、chat template、位置编码、截断窗口、temperature 与概率归一化。采样时用了 top-p，日志返回的是截断前概率还是实际行为概率，也需要核对。

对于常规教师蒸馏温度，若要讨论 $T^2$ 缩放等规则，必须连同具体目标和梯度定义推导；不要在未知实现中照搬系数。

## 8. 多教师与 privileged context

多教师可以按任务路由，也可以组合分布或损失。两种常见操作并不等价：

$$
q_{\rm mix}=\sum_m w_m q_m,
\qquad
\mathcal L_{\rm sum}=\sum_m w_m D(p\|q_m).
$$

前者在混合分布上计算目标；后者是多个散度的加权和。由于对数的非线性，不能互换后仍声称同一个方法。

教师可以看到额外解答、工具结果或更长上下文，为学生提供 privileged feedback。但必须保存角色可见信息边界：学生训练输入若泄漏了部署时没有的答案，评估就不再测同一个任务。

最后仍需在无教师、无额外答案的独立评测中检查学生能力。教师一致率只能说明模仿程度，不自动说明任务性能更高。

## 🎯 自测与参考答案

**1. OPD 中教师最重要的输入是什么？**

学生实际访问的前缀与实际生成 token。若评分另一条教师轨迹，不能直接逐 token 比较。

**2. sampled log-ratio 的数值无偏，为什么直接 backward 不等于 KL 梯度？**

采样分布也依赖学生参数，直接把采样 token 当常量会漏掉 score-function 项。固定状态下应按明确目标使用完整分布梯度或正确的策略梯度估计。

**3. 教师 Top-k mass 达到 99%，Reverse KL 近似一定好吗？**

不一定。学生可能把大量概率放在那 1% 尾部之外；必须同时检查学生覆盖与实际采样 token 的支持情况。

**4. Full-vocabulary KL 与 sampled-token surrogate 为什么需要分开命名？**

它们需要不同的教师信息，梯度路径与方差也不同；有些设置仅在特定采样与停止梯度假设下具有相同的期望梯度。
