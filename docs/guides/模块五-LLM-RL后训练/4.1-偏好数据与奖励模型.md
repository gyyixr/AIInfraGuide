一个回答“值几分”往往难以绝对判断，但比较同一道题的两个回答，通常容易一些。奖励建模把这种相对判断变成可微的打分函数，使训练系统能够为新生成的回答提供反馈。

本文先定义数据，再推导损失，最后解释怎样防止模型只学到“越长越好”。数学例子是独立教学算例，不代表任何真实模型的质量测量。

## 1. 一条偏好样本究竟包含什么

记 $x$ 为完整上下文，$y_w$ 为更受偏好的回答，$y_l$ 为较差回答。数据单位是：

```json
{
  "prompt_id": "addition-001",
  "prompt": "请用一句话解释 2 + 3 的结果。",
  "chosen": "2 + 3 = 5，因为把两组数量合在一起共有五个。",
  "rejected": "2 + 3 = 6。",
  "criterion": "数学正确且遵循一句话要求",
  "label_source": "human-reviewed",
  "split_group": "addition-family-001"
}
```

其中 `criterion`、`label_source`、`split_group` 是示例流水线的审计字段，不是某个训练框架的强制 API。

`chosen` 仅表示**在当前准则下更好**，不保证完美。两个回答都错时，偏好数据仍可能区分谁更接近目标；若要求训练绝对正确性，必须另有正确性标签。

### 1.1 四个必须一致的条件

| 条件 | 不一致时模型可能学到什么 |
|---|---|
| 相同 prompt 和历史上下文 | 题目难度或话题差异 |
| 相同可用信息和工具权限 | 信息优势而非回答能力 |
| 明确的评价准则 | 标注者风格和个人偏好 |
| 相容的生成与文本格式 | 模板、空白、结束标记等捷径 |

不要把一个问题的 chosen 与另一个问题的 rejected 随意拼成负样本。这样的对比不再是 $P(y_w\succ y_l\mid x)$。

### 1.2 平局与分歧也是信息

假设三名标注者对同一对回答投票为 2:1。硬标签把它压成 1；软标签可以记录 $q=2/3$。但“三票”只是小样本判断，不能当作精确的总体偏好概率。

对事实准确、简洁、礼貌、安全等维度，应先定义评判优先级。两个回答各有长短时，可保留维度标签、平局或复审，而非强行制造绝对赢家。

## 2. 从分数差到 Bradley–Terry 概率

令奖励模型为 $r_\phi(x,y)\in\mathbb R$，参数为 $\phi$。经典的成对偏好模型为：

$$
P_\phi(y_w\succ y_l\mid x)
=\frac{e^{r_\phi(x,y_w)}}{e^{r_\phi(x,y_w)}+e^{r_\phi(x,y_l)}}
=\sigma(\Delta r),
$$

其中 $\Delta r=r_w-r_l$，$\sigma(z)=1/(1+e^{-z})$。

直觉上，分数相等时两者各有一半胜率；分差越大，模型越确信 chosen 更好。这里的“胜率”是模型拟合的偏好概率，不是任务正确率。[InstructGPT](https://arxiv.org/abs/2203.02155) 使用了基于分差的偏好奖励建模。

最大化观察到的赢家概率，相当于最小化负对数似然：

$$
\mathcal L_{\rm RM}(\phi)
=-\frac1B\sum_{i=1}^B\log\sigma(r_w^{(i)}-r_l^{(i)})
=\frac1B\sum_i\operatorname{softplus}(-\Delta r_i).
$$

$B$ 是**偏好对数**，不是候选回答总数；实际需要编码 $2B$ 条序列。

### 2.1 手算三种分差

| $r_w-r_l$ | 预测 chosen 胜率 | 单对 loss |
|---:|---:|---:|
| 0 | 0.5000 | 0.6931 |
| 1 | 0.7311 | 0.3133 |
| 2 | 0.8808 | 0.1269 |

若把 $r_w=2,r_l=0$ 整体改成 $102,100$，以上结果不变。只看 pair loss，奖励的绝对零点不可辨识；不能直接把模型分数映射成百分制分数。

### 2.2 梯度为什么向正确方向移动

对单个偏好对：

$$
\frac{\partial\mathcal L}{\partial\Delta r}=\sigma(\Delta r)-1.
$$

当分差为 0 时，导数为 $-0.5$。梯度下降会增大分差，也就是提高 chosen 相对 rejected 的分数。若标签反了，更新方向同样会反过来，因此数据标签错误直接成为错误训练信号。

有软标签 $q\in[0,1]$ 时，可使用：

$$
\mathcal L=-q\log\sigma(\Delta r)-(1-q)\log(1-\sigma(\Delta r)),
\qquad
\frac{\partial\mathcal L}{\partial\Delta r}=\sigma(\Delta r)-q.
$$

$q=0.5$ 表示希望两者分差接近 0，而不是随机指定一方获胜。实际训练是否使用软标签属于方法选择，要与数据质量一起验证。

## 3. 从 token 序列到一个标量

一种常见实现是在 decoder-only Transformer 的最后一层隐藏状态上接线性标量头：

$$
h\in\mathbb R^{B\times L\times H},\qquad
r_i=w^\top h_{i,t_i}+b.
$$

$H$ 为隐藏维，$t_i$ 是约定的末个有效位置，例如结束 token 的位置。具体 pooling 方式由模型实现决定；不能不看代码就认为所有奖励模型都使用最后 token。

```text
相同 prompt + chosen   → tokenizer → [B, Lw] → backbone → [B, Lw, H] → [B]
相同 prompt + rejected → tokenizer → [B, Ll] → backbone → [B, Ll, H] → [B]
                                                              ↓ 分差
                                                           pair loss
```

训练时奖励模型更新 $\phi$；Actor 的 RL 更新阶段通常冻结奖励模型，只把它的输出当作反馈。冻结模型需要同时考虑参数梯度、训练模式与随机层，不能只省略一次 `optimizer.step()`。

### 3.1 padding 会怎样破坏奖励提取

假设右 padding 的 token 为：

```text
样本 A: [prompt, answer, EOS, PAD, PAD]  mask = [1, 1, 1, 0, 0]
样本 B: [prompt, answer, more, EOS, PAD] mask = [1, 1, 1, 1, 0]
```

如果直接读 `hidden[:, -1]`，两个样本拿到的都是 PAD 位置。对右 padding，末个有效索引可由 `attention_mask.sum(-1) - 1` 得出；对于左 padding，这个公式不成立。

更通用的示意实现是按有效位置取最大索引：

```python
# PyTorch 张量示意；调用方必须保证每条序列至少有一个有效 token。
positions = torch.arange(attention_mask.shape[1], device=hidden.device)
last = positions.expand_as(attention_mask).masked_fill(
    ~attention_mask.bool(), -1
).max(dim=-1).values
assert (last >= 0).all()
pooled = hidden[torch.arange(hidden.shape[0], device=hidden.device), last]
rewards = score_head(pooled).squeeze(-1)  # [B]
loss = torch.nn.functional.softplus(-(rewards_w - rewards_l)).mean()
```

该片段展示 pooling 和损失逻辑，需要调用方提供模型与成对张量；不是完整训练脚本。若模型在每个位置都输出分数，也必须明确最终选取位置和 EOS 约定。

### 3.2 截断不是无害的预处理

两个长回答若在关键结论之前被截断，标签可能不再适用。更隐蔽的情况是它们截断后完全相同，loss 仍在尝试分开相同输入。

应保留截断标记，检测 token 级重复；对于答案被切掉的 pair，可过滤或重新标注。不要为了凑足 batch 静默保留失去比较依据的标签。

## 4. 数据切分与长度偏差

### 4.1 按问题来源分组切分

同一道题的改写版本、同一对话的不同轮次、同一代码题的候选解答应进入相同 split。否则验证集只是在测试“是否记住类似题目”。

可靠的数据清单至少记录：原始数据版本、去重规则、group key、split seed、过滤原因计数、tokenizer 与模板哈希。

### 4.2 一个长度捷径的例子

假设训练集 100 对中，90 对 chosen 都更长。奖励模型可以通过“字数多就加分”达到较高 pair accuracy，却不懂内容。

验证时将题目按回答长度差分桶：

| 验证桶 | 需要单独观察的量 |
|---|---|
| chosen 明显更长 | 是否被长度线索主导 |
| 长度接近 | 内容辨别能力 |
| chosen 更短 | 对简洁正确答案是否系统性低估 |
| 无关内容扩写 | 添加废话是否仍然涨分 |

可以构造保持答案不变的反事实样本，如添加重复解释、无关客套话，观察评分变化。但不要用未经审核的文本变换自动断言两条回答质量完全相同。

### 4.3 排序能力、校准与分布漂移

Pair accuracy 只检查分差符号；pair loss 同时对过度自信的错误预测给予更大惩罚。两者都应记录，并按领域、长度和标签来源切片。

Actor 优化会主动寻找高分区域，生成的分布逐渐偏离最初的 RM 数据。离线验证准确率高，不代表面对策略主动搜索仍可靠。应把训练过程中实际生成的回答抽样送入独立复核。

## 5. 奖励模型与其他标量的区别

| 名称 | 输入 | 目标 | 典型使用阶段 |
|---|---|---|---|
| Reward model | 完整问题与回答 | 拟合偏好或质量 | 为 rollout 打分 |
| Value/Critic | 当前前缀状态 | 预测未来累计回报 | PPO 优势估计 |
| 规则 verifier | 答案、标准或测试 | 检查可验证条件 | RLVR 奖励 |
| Reference logprob | 前缀及实际 token | 给出固定策略概率 | KL 约束或 DPO |

不要把 reward、value、logprob 都放进一个叫 `score` 的字段后依赖位置约定；字段名、shape 和版本应携带语义。

奖励归一化也会改变 Actor 看到的有效尺度。例如把奖励标准差缩小一半但保持 KL 系数不变，相当于增强了 KL 相对约束。应记录归一化统计的估计数据与更新时间。

## 6. 常见故障与排查

| 现象 | 优先检查 | 可做的最小实验 |
|---|---|---|
| 训练 loss 低，验证差 | prompt 泄漏、标签来源偏移 | 按来源与题目家族重新切分 |
| 奖励只随长度增加 | 长度捷径 | 固定内容，增删无关文本 |
| 调换 chosen/rejected 后 loss 不变 | pair 索引错位 | 用一对明显正负样本逐字段打印 |
| padding 数改变分数 | pooling、attention mask | 同样有效 token 用不同 padding 长度 |
| 分数越来越大，排序没变 | 奖励平移或尺度漂移 | 同时看分差与独立质量 |
| RM 高分但人工质量下降 | reward hacking、分布外输入 | 抽查最高分及最异常样本 |

## 🎯 自测与参考答案

**1. $r_w=7,r_l=6$ 与 $r_w=1,r_l=0$ 的 pair loss 是否一样？**

一样，均为 $-\log\sigma(1)\approx0.3133$。只由分差决定。

**2. 把一对样本拆成两行后随机切 train/valid 有什么问题？**

同一 prompt 与相关回答会泄漏到两个集合，而且失去 pair 的基本单元。应先按题目家族分组切分，再生成或组织偏好对。

**3. chosen 更长的比例很高，能否直接把所有长回答扣分？**

不能。长度可能与必要推理信息相关。应先做反事实和分桶评估，确定不合理偏差，再调整数据或目标；简单扣分也会创造新的捷径。

**4. 奖励模型是否必须与 Actor 同样大？**

不必须。它们是不同角色；选择受标注质量、泛化、打分成本和吞吐限制影响。模型大小不能替代独立验证。
