RL 训练时，奖励函数可能只是 `answer == 42`，没有任何可求导的神经网络。模型却仍能学习，原因在于：**我们对“模型选择该回答的概率”求导，而不是对判题程序求导。**

这篇文章从语言模型最熟悉的 next-token prediction 出发，推导它如何变成策略梯度，再把公式准确放回张量位置。

## 1. 自回归生成就是一串决策

给定问题 $x$，模型生成回答 $y=(y_1,\ldots,y_T)$。在第 $t$ 个生成位置：

| RL 概念 | 语言模型中的对应物 |
|---|---|
| 状态 $s_t$ | 问题 $x$ 加已生成前缀 $y_{<t}$ |
| 动作 $a_t$ | 下一个 token $y_t$ |
| 策略 $\pi_\theta(a_t\mid s_t)$ | logits 经过 softmax 得到的分布 |
| 转移 | 把生成 token 接到前缀后面 |
| 即时奖励 $r_t$ | 本 token/步骤奖励，或末尾的整体评分 |
| 终止 | EOS、任务完成，或任务定义中的终止条件 |

对于单轮纯文本任务，转移几乎是确定的拼接。工具调用任务还会把外部观察接回上下文，此时环境转移包含工具执行结果。

状态里必须包含影响未来的上下文。若隐藏了关键工具状态，观察对策略而言可能只是部分可观测信息；下面先讨论完整前缀的简单设定。

序列概率由链式法则分解：

$$
\pi_\theta(y\mid x)=\prod_{t=1}^{T}\pi_\theta(y_t\mid x,y_{<t})
$$

取对数后，乘积变求和：

$$
\log\pi_\theta(y\mid x)=\sum_{t=1}^{T}\log\pi_\theta(y_t\mid x,y_{<t})
$$

这解释了为什么训练代码通常保存 `[batch, response_length]` 的 token logprob。

## 2. 从期望奖励推导 REINFORCE

固定问题 $x$，先只考虑回答末尾给出标量奖励 $R(x,y)$：

$$
J(\theta)=\mathbb{E}_{y\sim\pi_\theta(\cdot\mid x)}[R(x,y)]
=\sum_y\pi_\theta(y\mid x)R(x,y)
$$

假设评分器固定，奖励没有对 $\theta$ 的直接依赖。利用恒等式 $\nabla p=p\nabla\log p$：

$$
\begin{aligned}
\nabla_\theta J
&=\sum_y R(x,y)\nabla_\theta\pi_\theta(y\mid x)\\
&=\sum_y\pi_\theta(y\mid x)R(x,y)\nabla_\theta\log\pi_\theta(y\mid x)\\
&=\mathbb{E}_{y\sim\pi_\theta}\left[R(x,y)\sum_t\nabla_\theta\log\pi_\theta(y_t\mid s_t)\right].
\end{aligned}
$$

词表和回答组合太多，无法枚举所有 $y$。我们采样 $N$ 条回答，用样本平均近似这个期望。

训练库通常执行损失最小化，所以写作：

$$
L_{\mathrm{PG}}=-\frac{1}{N}\sum_i\operatorname{stopgrad}(R_i)\sum_t\log\pi_\theta(y_{i,t}\mid s_{i,t})
$$

这个损失是构造梯度的代理目标。不能把它的数值简单解释成“任务损失”，也不能仅凭它是否接近 0 判断模型是否学会做题。

标准策略梯度推导和 baseline 恒等式可对照 [Spinning Up 的推导](https://spinningup.openai.com/en/latest/spinningup/rl_intro3.html)。下面的数字与张量例子是独立教学算例。

## 3. 一个两动作例子：梯度到底改变了什么

暂时让模型只输出一个 token：正确答案 `A` 或错误答案 `B`。

令两个 logits 为 $[z,0]$，所以：

$$
p=\pi(A)=\sigma(z),\qquad \pi(B)=1-p
$$

设 $R(A)=1,R(B)=0$，则期望奖励 $J=p$，精确梯度为：

$$
\frac{dJ}{dz}=p(1-p)
$$

初始 $z=0$，$p=0.5$，精确梯度为 0.25。

REINFORCE 从采样估计这个梯度：

| 采到的动作 | 采样概率 | 奖励 | $d\log\pi(a)/dz$ | 样本梯度 |
|---|---:|---:|---:|---:|
| A | 0.5 | 1 | $1-p=0.5$ | 0.5 |
| B | 0.5 | 0 | $-p=-0.5$ | 0 |

期望梯度 $0.5\times0.5+0.5\times0=0.25$，与直接求导一致。

若学习率 $\eta=0.1$，使用精确梯度做一次梯度上升：

$$
z_{\mathrm{new}}=0+0.1\times0.25=0.025
$$

$$
\pi_{\mathrm{new}}(A)=\sigma(0.025)\approx0.50625
$$

正确动作概率上升，但不会一次变成 1。真实 LLM 中大量 token 共享参数，某一轨迹的更新还会影响其他上下文，行为会更复杂。

## 4. 为什么减去 baseline 不改变期望梯度

如果基线 $b(s)$ 不依赖当前采样动作：

$$
\begin{aligned}
\mathbb{E}_{a\sim\pi_\theta}[b(s)\nabla_\theta\log\pi_\theta(a\mid s)]
&=b(s)\sum_a\nabla_\theta\pi_\theta(a\mid s)\\
&=b(s)\nabla_\theta 1=0.
\end{aligned}
$$

因此，可以用 $R-b(s)$ 替代 $R$，在保持期望梯度的同时改变方差。

仍用两动作例子，设 $b=0.5$：

| 动作 | $R-b$ | logprob 梯度 | 乘积 |
|---|---:|---:|---:|
| A | 0.5 | 0.5 | 0.25 |
| B | -0.5 | -0.5 | 0.25 |

两个样本都给出 0.25，方差在这个特殊例子里降为 0。它说明了 baseline 的作用，不表示复杂任务中的价值网络能消除所有噪声。

基线若由神经网络预测，Actor loss 中仍应把它当作冻结权重，不沿该分支反向。Critic 用单独的回归目标学习。

如果基线包含当前样本自己的奖励，便不满足上述“独立于当前动作”的简单条件。组均值和 leave-one-out 的区别会在第3章展开。

## 5. Return、Value 与 Advantage

对于每一步都有奖励的轨迹，折扣回报为：

$$
G_t=\sum_{k=t}^{T}\gamma^{k-t}r_k
$$

$\gamma\in[0,1]$ 控制未来奖励的折扣。许多有限长度文本任务采用 $\gamma=1$，但它不是由 LLM 架构自动决定的。

价值函数与优势定义为：

$$
V^\pi(s_t)=\mathbb{E}[G_t\mid s_t],\qquad A^\pi(s_t,a_t)=Q^\pi(s_t,a_t)-V^\pi(s_t)
$$

在采样训练中，常用 $G_t-V_\phi(s_t)$ 或 GAE 近似优势。

例如三个位置奖励为 $[0,0,1]$，$\gamma=1$，则每个位置的 Monte Carlo return 都是 1。若预测价值为 $[0.2,0.4,0.7]$，优势为 $[0.8,0.6,0.3]$。

同一个末尾奖励不意味着每个前缀都同样“出乎预期”：越接近确定正确答案的位置，原先预测越高，意外程度可能越小。

## 6. logits 与 token 必须错开一位

取一个已经完成 tokenization 的序列：

```text
位置 j       0    1    2    3      4     5
input_ids   p0   p1   y0   y1    EOS   PAD
角色        prompt   response---------- padding
```

Causal LM 的 `logits[:, j, :]` 预测下一个 token，也就是 `input_ids[:, j+1]`。

因此：

| 被评分 token | 从哪个 logits 取概率 |
|---|---|
| `y0`，位置 2 | 位置 1，也就是最后一个 prompt token |
| `y1`，位置 3 | 位置 2 |
| `EOS`，位置 4 | 位置 3 |
| `PAD`，位置 5 | 不纳入有效回答损失 |

如果 prompt padding 区占 $P$ 个位置，response 区占 $T$ 个位置，且回答紧接在固定 prompt 区之后，则用于回答评分的 logits 切片是 `[P-1:P+T-1]`。

这是张量布局约定。对 variable-length packing 或其他布局，要依据真实位置映射重建索引，不能机械套切片。

### 6.1 一个形状明确的评分函数

```python
import torch
import torch.nn.functional as F


def response_logprobs(logits, response_ids, prompt_width):
    """logits: [N, P+T, V], response_ids: [N, T]."""
    response_width = response_ids.shape[1]
    assert prompt_width >= 1
    start = prompt_width - 1
    response_logits = logits[:, start:start + response_width, :]
    assert response_logits.shape[:2] == response_ids.shape
    # 在 FP32 中做 log_softmax；避免先 softmax 再 log 的下溢风险。
    all_logprobs = F.log_softmax(response_logits.float(), dim=-1)
    return all_logprobs.gather(-1, response_ids[..., None]).squeeze(-1)
```

该函数展示索引契约，完整词表 `log_softmax` 会占较多显存；真实训练可使用 fused/chunked logprob kernel，但必须保持相同数学语义。

## 7. attention mask 与 response loss mask 不能互换

`attention_mask` 决定哪些 token 是可参与注意力的上下文。`response_mask` 决定哪些生成动作对 RL loss 有贡献。

一个 prompt token 可以满足 `attention_mask=1`、`response_mask=0`：模型需要读它，但不优化“生成这个 prompt”的概率。

对上述序列：

```text
attention_mask       [1, 1, 1, 1, 1, 0]
response_mask        [1, 1, 1, 0]       # 仅对应 response 区
```

通常真实生成的 EOS 也属于一个动作，应纳入 policy loss。若 tokenizer 把 PAD 与 EOS 配成同一个 ID，就不能简单用 `token_id != eos_id` 构造 mask；应保存真实生成长度或首次终止位置。

多轮工具任务还要排除由环境返回的观察 token。它们属于上下文，却不是 Actor 采样的动作。

## 8. 求和、按 token 平均与按回答平均

设 $\ell_{i,t}$ 为一个 token 的损失，$m_{i,t}$ 为 mask，$T_i=\sum_t m_{i,t}$。

按回答先平均，再对回答平均：

$$
L_{\mathrm{seqmean}}=\frac1N\sum_i\frac{\sum_t m_{i,t}\ell_{i,t}}{T_i}
$$

全局 token 平均：

$$
L_{\mathrm{tokenmean}}=\frac{\sum_{i,t}m_{i,t}\ell_{i,t}}{\sum_{i,t}m_{i,t}}
$$

两条回答长度为 2 和 8 时，前者让每条回答总权重相同；后者给每个 token 相同权重，所以长回答的总权重更大。

最初从序列期望奖励推导的 REINFORCE 是“序列内求和，再对轨迹平均”。额外除以随机长度会改变目标的权重，不能仅当作数值稳定技巧。

在分布式和梯度累积场景，若每个 microbatch 的有效 token 数不同，直接平均 microbatch loss 也不等于全局 token 平均。必须按目标分母加权，并考虑 DDP 对梯度执行的平均。

## 9. detach 与数值检查

```python
# logp, advantage, mask 都是 [N, T]。
valid = mask.bool()
assert valid.any(), "本批没有可训练 token"
assert torch.isfinite(logp[valid]).all()
assert torch.isfinite(advantage[valid]).all()
loss = -(logp[valid] * advantage.detach()[valid]).mean()
```

这里明确采用有效 token 平均。padding 位置通过布尔选择排除；简单把 NaN 乘以 0 仍然是 NaN，不能替代有效性检查。

常见错误包括：

- 把 rollout 返回的 detached logprob 直接用于 Actor loss，导致没有梯度。
- 更新 Actor 时让 old logprob 分支也保留计算图，破坏固定基准。
- 未区分策略奖励与价值预测，把 Critic loss 混进不该更新的网络。
- 在所有 token 上平均，导致 padding 长度改变实际梯度尺度。

## 10. 自测与参考答案

**题 1：奖励全是正数，是否每条回答都应该增大概率？**

答：不必。减去 baseline 后，低于预期的回答可得到负优势；概率是归一化分布，一个动作增大还会挤压其他动作。

**题 2：为什么同一回答的当前 logprob 要重新前向？**

答：当前模型参数可能已经更新，而且策略梯度需要连接到当前参数的计算图。保存的旧数值只用作基准。

**题 3：回答长度 2 和 8，按回答平均时每个 token 的权重各是多少？**

答：两条回答组成一个 batch 时，短回答每个 token 权重 $1/(2\times2)=1/4$，长回答每个 token 权重 $1/(2\times8)=1/16$；全局 token 平均均为 $1/10$。

**题 4：prompt 没有 policy loss，是否就不需要计算 prompt 的前向？**

答：仍需要。回答概率依赖 prompt 的上下文表示；不对某位置监督，不代表它不影响受监督位置。
