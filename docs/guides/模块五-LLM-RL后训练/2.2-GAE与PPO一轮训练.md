PPO 的公式只有几行，但一次真实更新需要来自不同阶段的多组数值。最容易犯的错，往往不是公式记错，而是把“采样时的 value”和“当前 Critic 的 value”混起来，或者让 padding 位置参与了递推。

本篇用一条长度为 3 的回答，从奖励一路算到 Actor 与 Critic 的损失。所有数字都可用纸笔或文中的纯 Python 程序检查。

## 1. 先声明这一轮的配置

为避免隐藏假设，使用以下教学设置：

| 项目 | 本文设定 |
|---|---|
| 任务 | 一个 prompt，生成三个有效动作，最后正常结束 |
| Reward | 最后一个有效动作得到任务奖励 1 |
| 参考惩罚 | 每 token 减去 $\beta\log(\pi_{\mathrm{old}}/\pi_{\mathrm{ref}})$ |
| KL 系数 | $\beta=0.1$ |
| 折扣率 | $\gamma=1$ |
| GAE 参数 | $\lambda=0.9$ |
| PPO clip | $\epsilon=0.2$ |
| reduction | 有效 token 平均 |
| 标准化 | 算例不做优势标准化，方便逐项复核 |
| Critic loss | 均方误差乘 $1/2$，不启用 value clipping |

如果项目使用“KL 独立加到 loss”，或者使用其他奖励归一化，那么得到的数组会不同。应先固定配置，再比较数值。

## 2. 状态价值对齐到哪个位置

令 $s_t=(x,y_{<t})$，$y_t$ 是从该状态采样的动作。$V_t=V_\phi(s_t)$ 预测**生成 $y_t$ 之前**的未来回报。

| $t$ | 状态 | 动作 | 旧价值 $V_t$ |
|---:|---|---|---:|
| 1 | 问题 $x$ | $y_1$ | 0.2 |
| 2 | $x,y_1$ | $y_2$ | 0.4 |
| 3 | $x,y_1,y_2$ | $y_3$ | 0.6 |
| 4 | 回答已经结束 | 无 | 0 |

终止状态的未来价值置 0，是因为任务在这里结束，之后没有奖励。若只是被采样预算截断，就不能在未声明任务规则时直接套这个结论。

实现中 value head 的输出位置必须与这个状态定义一致；和 logprob 一样，也要关注自回归 shift。

## 3. 第一步：把参考约束变成 token 奖励

假设同一条轨迹上的旧策略与参考策略 logprob 之差为：

$$
d_t=\ell_t^{\mathrm{old}}-\ell_t^{\mathrm{ref}}=[0.1,0.2,0.3]
$$

参考惩罚为：

$$
r_t^{\mathrm{KL}}=-0.1d_t=[-0.01,-0.02,-0.03]
$$

把末尾任务奖励 1 加到最后一个有效动作：

$$
r=[-0.01,-0.02,1-0.03]=[-0.01,-0.02,0.97]
$$

总奖励为 $0.94$。这里的 $d_t$ 是样本 log-ratio；不能把三个正值当作“每个 token 都计算了完整词表 KL”。

若回答实际长度小于 padding 宽度，任务奖励应该放到 `length - 1` 的有效动作位置，而不是张量的最后一列。

## 4. 第二步：先算 TD 残差

一步时间差分残差定义为：

$$
\delta_t=r_t+\gamma V_{t+1}-V_t
$$

它比较“一步真实奖励加下一步预测”与“当前预测”的差距。

逐项代入：

| $t$ | $r_t$ | $V_t$ | $V_{t+1}$ | $\delta_t$ |
|---:|---:|---:|---:|---:|
| 1 | -0.01 | 0.2 | 0.4 | $-0.01+0.4-0.2=0.19$ |
| 2 | -0.02 | 0.4 | 0.6 | $-0.02+0.6-0.4=0.18$ |
| 3 | 0.97 | 0.6 | 0 | $0.97+0-0.6=0.37$ |

残差为正，表示这一步观察到的结果比原先预测更好。

## 5. 第三步：用 GAE 向前传播误差

GAE 把未来 TD 残差按指数权重累加：

$$
\hat A_t=\sum_{l=0}^{T-t}(\gamma\lambda)^l\delta_{t+l}
$$

实际程序通常从后向前递推：

$$
\hat A_t=\delta_t+\gamma\lambda\hat A_{t+1}
$$

正常终止后设 $\hat A_{T+1}=0$。于是：

$$
\hat A_3=0.37
$$

$$
\hat A_2=0.18+0.9\times0.37=0.513
$$

$$
\hat A_1=0.19+0.9\times0.513=0.6517
$$

最终优势为：

$$
\hat A=[0.6517,0.513,0.37]
$$

前面的动作接收到后续结果带来的学习信号；但信号衰减由 $\gamma\lambda$ 控制。这是 GAE 的信用分配机制，不是把末尾奖励简单复制三次。

[GAE 原论文](https://arxiv.org/abs/1506.02438) 将这一估计描述为偏差与方差之间的可调折中。这里的短轨迹把该递推具体化。

### 5.1 $\lambda=0$ 与 $\lambda=1$

$\lambda=0$ 时，优势就是一步 TD 残差 $[0.19,0.18,0.37]$，更依赖价值网络的局部预测。

$\lambda=1,\gamma=1$ 且正常终止时，递推中的中间 value 项望远镜式抵消：

$$
\hat A_t=G_t-V_t
$$

本例完整回报为 $G=[0.94,0.95,0.97]$，因此优势变为 $[0.74,0.55,0.37]$。

这种 Monte Carlo 形式减少了对中间 value 预测的依赖，但回报噪声也会更直接地传回前面的动作。

## 6. 第四步：构造 Critic 的回归目标

常见做法是用旧价值加上原始 GAE：

$$
\hat R_t=\hat A_t+V_t^{\mathrm{old}}
$$

得到：

$$
\hat R=[0.8517,0.913,0.97]
$$

这是本次数据对应的 $\lambda$-return target，不一定等于无折扣 Monte Carlo return。

这些 target 在本批多轮更新中保持固定。Critic 更新时重新预测当前值 $V_\phi(s_t)$，通过回归靠近 target。

若 Actor 使用优势标准化，应先保存原始优势构造 $\hat R$，再另建一份标准化后的 Actor advantage。否则 Critic 会被迫拟合一个改变过尺度的目标。

## 7. 第五步：手算一个 Actor minibatch

假设训练前向算出的 token ratio 为：

$$
\rho=[1.1,0.8,1.3]
$$

优势全为正，第三个 ratio 超过上界 1.2：

| token | $A_t$ | $\rho_t$ | 使用的 surrogate |
|---:|---:|---:|---:|
| 1 | 0.6517 | 1.1 | $1.1\times0.6517=0.71687$ |
| 2 | 0.513 | 0.8 | $0.8\times0.513=0.4104$ |
| 3 | 0.37 | 1.3 | $1.2\times0.37=0.444$ |

于是：

$$
L_{\mathrm{policy}}=-\frac{0.71687+0.4104+0.444}{3}
\approx-0.5237567
$$

这个标量只用于检查目标计算；它不是模型正确率，也不等于本轮奖励 0.94。

所有 logprob 必须来自同一组实际 token。若 current forward 又随机生成了一条新回答，便不能与旧回答的 logprob 逐位置组成 ratio。

## 8. 第六步：手算 Critic loss

假设当前 Critic 预测为 $[0.25,0.45,0.65]$：

$$
L_{\mathrm{value}}=\frac{1}{2T}\sum_t(V_\phi(s_t)-\hat R_t)^2
$$

$$
L_{\mathrm{value}}=\frac{(0.25-0.8517)^2+(0.45-0.913)^2+(0.65-0.97)^2}{6}
\approx0.1131353
$$

部分实现使用 value clipping：限制当前价值相对旧价值的移动，再比较未裁剪和裁剪的回归误差。它与 policy clipping 是不同机制，阈值也不能混用。

若 Actor 与 Critic 共享骨干，两种损失会共同影响共享参数；若它们是独立模型，就分别更新各自优化器。仅看一个总 loss 公式无法推断部署方式。

## 9. 纯 Python 复核程序

以下代码仅依赖标准库，输入是前面定义的数组，不会加载模型或使用 GPU：

```python
import math


def gae(rewards, values, gamma=1.0, lam=0.9, bootstrap_value=0.0):
    assert len(rewards) == len(values) and len(values) > 0
    advantage = [0.0] * len(rewards)
    next_advantage = 0.0
    next_value = bootstrap_value
    for t in reversed(range(len(rewards))):
        delta = rewards[t] + gamma * next_value - values[t]
        next_advantage = delta + gamma * lam * next_advantage
        advantage[t] = next_advantage
        next_value = values[t]
    targets = [a + v for a, v in zip(advantage, values)]
    return advantage, targets


rewards = [-0.01, -0.02, 0.97]
old_values = [0.2, 0.4, 0.6]
advantage, targets = gae(rewards, old_values)
assert all(math.isclose(a, b) for a, b in
           zip(advantage, [0.6517, 0.513, 0.37]))
ratio = [1.1, 0.8, 1.3]
surrogates = [min(r * a, min(max(r, 0.8), 1.2) * a)
              for r, a in zip(ratio, advantage)]
policy_loss = -sum(surrogates) / len(surrogates)
new_values = [0.25, 0.45, 0.65]
value_loss = sum((v - target) ** 2 for v, target in
                 zip(new_values, targets)) / (2 * len(targets))
print("advantages:", advantage)
print("targets:", targets)
print("policy_loss:", policy_loss)
print("value_loss:", value_loss)
```

期望输出约为：`[0.6517, 0.513, 0.37]`、`[0.8517, 0.913, 0.97]`、`-0.5237567`、`0.1131353`。

这里把一条有效轨迹单独传入函数。批量实现要用真实长度和 episode boundary 重置递推，不能跨 padding 或跨样本串接优势。

## 10. EOS、截断与 bootstrap

正常 EOS 终止意味着任务结束，$V_{T+1}=0$。采样长度到上限则可能是两种不同情形：

1. **预算耗尽就是任务终止**：定义明确的终止奖励或失败规则，随后不 bootstrap。
2. **只是训练采样被截断，任务仍可继续**：需要利用截断处的下一状态 value bootstrap，并标记这是非终止截断。

第二种情形若末尾 $r_T=0,V_T=0.6,V_{T+1}=0.8,\gamma=1$，则 $\delta_T=0.2$；误把它当终止会得到 $-0.6$，学习信号连方向都变了。

多轮 Agent 环境还要区分工具调用结束与整个任务结束。一次工具返回不一定对应 episode terminal。

LLM RLVR 的长回答处理可能选择屏蔽过长样本、给予长度相关惩罚或定义预算终止。这些都是任务/算法决策，不应由 padding 代码默默决定。

## 11. 一轮数据中，什么冻结、什么重算

| 内容 | 收集/准备阶段 | 每个训练 minibatch |
|---|---|---|
| response IDs、mask、版本 | 写入并校验 | 保持不变 |
| old logprob、old value | 用旧快照计算 | 保持不变 |
| 参考 logprob、奖励 | 对同一轨迹计算 | 通常保持不变 |
| advantage、value target | 一次构造 | 通常保持不变 |
| current logprob | 不沿用 rollout 的计算图 | Actor 重新前向 |
| current value | 不沿用 old value | Critic 重新前向 |
| 模型参数、优化器状态 | 当前轮起始状态 | 按 optimizer step 更新 |

“通常”表示这里描述经典同步流程；如果框架刻意重算优势或更新奖励模型，应把这一算法变化单独写进配置。

## 12. 排障顺序与自测

遇到 PPO 不稳定，先检查原始轨迹，再看 loss：

- 第一 token 的 logprob 是否来自最后一个 prompt 位置。
- 末尾奖励是否落在真实最后动作上。
- old/current 在首次更新前是否基本一致。
- GAE 是否跨过 padding 或 episode 边界。
- 优势与 target 是否在正确阶段 detach。
- 全局 batch 的归一化是否与 microbatch/DP 的归约一致。

**题 1：本例 $\lambda=1$ 时，第一个 value target 是多少？**

答：$0.94$，等于三项奖励之和。

**题 2：本例 $\lambda=0.9$ 的第一个 target 为什么小于 0.94？**

答：它混合了多步回报与旧价值预测；旧价值偏低且 $\lambda<1$，所以不等于完整 Monte Carlo return。

**题 3：如果对优势做白化，是否应该重新计算任务奖励？**

答：不用。应保留奖励和原始 target；只对 Actor 使用的优势副本按明确 mask 与统计范围变换。

**题 4：重复训练三轮数据，是否要用新的 Critic 值替换 old value？**

答：经典固定目标 PPO 不这么做。新的 Critic 值是回归预测，旧 value 与 target 仍是本批采样快照的参照。
