## 📖 本章概述

PPO 的 Critic 要预测每个前缀的未来回报，而在可验证的数学、代码等任务里，我们往往更容易回答另一件事：同一个问题的几个回答，哪个结果更好？GRPO 利用这个组内比较，减少对独立价值网络的依赖。

它并没有让 RL 训练只剩一个模型，也没有消除采样成本。同题生成多个回答会放大推理负担；若所有回答都得到同一个分数，组内比较还可能没有有效信号。

本章先完整解释基础 GRPO，再把常见改进拆成优势、归约、裁剪和样本选择四个独立维度。

## 📑 第一部分：组相对优势（正文 3.1）

### 1. 一个问题对应一组回答

设 $B$ 个问题，每题采样 $G$ 个回答，轨迹数为 $BG$。组内奖励写成 `[B, G]`，生成 token 和 mask 可写成 `[B, G, T]`。

分布式打乱、动态过滤和 token packing 不能破坏 `group_id`：只有同一个问题的回答才在这里互相比较。

### 2. 数值推导

使用总体标准差，奖励 $[0,0,1,1]$ 的均值为 0.5、标准差为 0.5，因此优势为 $[-1,-1,1,1]$。

$$
A_i=\frac{R_i-\bar R}{\sqrt{\frac1G\sum_j(R_j-\bar R)^2}+\varepsilon_{\mathrm{std}}}
$$

对 outcome reward，基础 GRPO 把同一回答的这个标量广播到其所有有效动作上，再用 token 级 old/current ratio 构造裁剪目标。

### 3. 优势为零不等于训练完成

全对和全错的组都可能产生零优势。前者说明题目对当前模型过易，后者可能意味着探索不足、题目过难或验证器有问题。两者需要分开统计。

## 📑 第二部分：改进方法与稳定性（正文 3.2）

### 4. 四个可以独立改变的部件

| 部件 | 基础问题 | 代表性调整 |
|---|---|---|
| Baseline / scale | 比谁好、奖励如何缩放 | RLOO、取消组内标准差缩放 |
| Loss reduction | 长短回答如何加权 | token mean、固定分母 |
| Clip | 有利方向能走多远 | DAPO 非对称上下界 |
| Sampling | 哪些问题提供有效信号 | 动态补采样、难度与预算控制 |

不同论文或框架可能只使用其中一些变化。配置名相同，不保证完整复现原论文的训练配方。

### 5. 预算与诊断

假设每题 8 个回答、平均 1024 个生成 token，64 题就需要 524288 个生成 token。提高组大小通常增加候选多样性，也增加 KV Cache、解码时间与奖励评估成本。

应同时监控有效组比例、任务成功率、回答长度、截断率、entropy、采样与训练的 logprob 差异，而不是只看平均 reward。

## 🎯 自测与参考答案

1. GRPO 必须使用可验证规则奖励吗？
2. 奖励 $[1,1,1,1]$ 与 $[0,0,0,0]$ 的基础组优势有什么区别？
3. RLOO 为什么把当前回答排除出 baseline？
4. 把 loss 分母改成固定最大长度，是否就自动取消了 reward 标准差缩放？

**参考答案：** 1. 不是，组内评分也可来自奖励模型。2. 两者优势都为 0，但任务表现相反。3. 同题独立采样时，其他回答的均值不依赖当前动作，可保持对应 baseline 的无偏性质。4. 不是，优势构造和 loss 归约是两个独立开关。
