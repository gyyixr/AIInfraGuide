DPO 的核心问题是：既然偏好奖励与最优策略有确定关系，能否直接用语言模型的概率比表示奖励？这样就能用偏好对训练策略，省去经典 RLHF 中独立训练奖励模型和反复在线采样的环节。

这并不意味着数据、模板和概率定义变得不重要。恰恰相反，DPO 只有一个简洁 loss，许多实现错误会隐藏在 loss 之前。

## 1. 先固定符号与优化问题

| 符号 | 含义 |
|---|---|
| $x$ | prompt 或完整对话前缀 |
| $y$ | 整条回答序列，包含约定的结束 token |
| $\pi_\theta(y\mid x)$ | 当前可训练策略的序列概率 |
| $\pi_{\rm ref}(y\mid x)$ | 固定参考策略的序列概率 |
| $r(x,y)$ | 概念上的标量奖励 |
| $\beta>0$ | KL 约束系数 |

固定 $x$，考虑：

$$
J(\pi)=\sum_y\pi(y\mid x)r(x,y)
-\beta\sum_y\pi(y\mid x)\log\frac{\pi(y\mid x)}{\pi_{\rm ref}(y\mid x)}.
$$

约束是 $\sum_y\pi(y\mid x)=1$。假设参考策略在所考虑的支持集上为正，归一化常数有限；下述闭式解是对所有分布优化的理想解，不保证有限参数模型能精确实现。

## 2. 推导最优策略

引入归一化约束的拉格朗日乘子 $\lambda$，对 $\pi(y\mid x)$ 求导：

$$
r(x,y)-\beta\left(\log\frac{\pi(y\mid x)}{\pi_{\rm ref}(y\mid x)}+1\right)+\lambda=0.
$$

移项并指数化：

$$
\pi^*(y\mid x)=\frac1{Z(x)}\pi_{\rm ref}(y\mid x)\exp\left(\frac{r(x,y)}{\beta}\right),
$$

$$
Z(x)=\sum_y\pi_{\rm ref}(y\mid x)\exp\left(\frac{r(x,y)}{\beta}\right).
$$

含义很直观：参考策略提供起点，奖励越高的回答获得越大的相对放大倍数；$\beta$ 越大，给定奖励下最优分布越接近参考分布。

反解奖励：

$$
r(x,y)=\beta\log\frac{\pi^*(y\mid x)}{\pi_{\rm ref}(y\mid x)}+\beta\log Z(x).
$$

看似需要枚举所有回答来求 $Z(x)$，但偏好模型只用两个回答的**奖励差**。

## 3. 归一化常数如何相消

对相同 $x$ 的 chosen 和 rejected：

$$
r(x,y_w)-r(x,y_l)
=\beta\left[
\log\frac{\pi^*(y_w\mid x)}{\pi_{\rm ref}(y_w\mid x)}
-\log\frac{\pi^*(y_l\mid x)}{\pi_{\rm ref}(y_l\mid x)}
\right].
$$

两个 $\beta\log Z(x)$ 抵消。用可训练策略 $\pi_\theta$ 参数化这个关系，并代入 Bradley–Terry 模型，得到经典 DPO：

$$
\mathcal L_{\rm DPO}
=-\mathbb E_{(x,y_w,y_l)\sim\mathcal D}
\log\sigma(\beta\Delta_\theta),
$$

$$
\Delta_\theta=
[\log\pi_\theta(y_w\mid x)-\log\pi_\theta(y_l\mid x)]
-[\log\pi_{\rm ref}(y_w\mid x)-\log\pi_{\rm ref}(y_l\mid x)].
$$

这是 [DPO 原论文](https://arxiv.org/abs/2305.18290) 的基本目标。它把成对偏好作为监督，直接更新策略；不需要在每个 optimizer step 新生成回答。

### 3.1 为什么必须是同一个 prompt

如果两个回答来自不同 prompt，抵消的将是 $Z(x_w)$ 和 $Z(x_l)$，一般并不相等。随意跨题拼接偏好对，会破坏这个推导基础。

### 3.2 “隐式奖励”不是独立奖励模型

常写：

$$
\hat r_\theta(x,y)=\beta[\log\pi_\theta(y\mid x)-\log\pi_{\rm ref}(y\mid x)].
$$

它方便记录 chosen/rejected 的相对变化。但它随 Actor 更新，不应被误当成独立、固定、经过正确性校准的评估器。

## 4. 手算一对样本与梯度

为便于计算，假设一个玩具问题只有两个候选：

```text
参考模型：P(chosen) = 0.5，P(rejected) = 0.5
当前模型：P(chosen) = 0.75，P(rejected) = 0.25
beta = 0.2
```

则：

$$
\Delta_\theta=\log(0.75/0.25)-\log(0.5/0.5)=\log3\approx1.0986,
$$

$$
z=\beta\Delta_\theta\approx0.2197,\qquad
\sigma(z)\approx0.5547,\qquad
\ell=-\log\sigma(z)\approx0.5893.
$$

初始策略等于参考策略时，$z=0$，loss 为 $\log2\approx0.6931$。当前 loss 更低，说明相对偏好方向已经得到改善。

对策略参数求导：

$$
\nabla_\theta\ell
=-\beta\sigma(-z)
[\nabla_\theta\log\pi_\theta(y_w\mid x)
-\nabla_\theta\log\pi_\theta(y_l\mid x)].
$$

本例系数 $\beta\sigma(-z)\approx0.0891$。当模型非常确信 chosen 更好时，这个 pair 的梯度逐渐变小；明显预测反的 pair 获得更强纠正。

### 4.1 beta 的两个层面

在理想奖励优化问题里，$\beta$ 控制偏离参考策略的代价。在实际固定数据、有限步数的 DPO 中，$\beta$ 同时改变分类 logit 和梯度尺度。

因此不能简单把“beta 减半”理解成“实际 KL 必定翻倍”。学习率、训练时长、标签噪声与数据覆盖也会影响结果。应测量实际策略偏移，而不是仅凭超参数名字推断。

## 5. 序列概率怎样从 logits 提取

对长度 $T$ 的回答：

$$
\log\pi_\theta(y\mid x)
=\sum_{t=1}^{T}\log\pi_\theta(y_t\mid x,y_{<t}).
$$

若模型输出 logits 为 `[2B, L, V]`，$V$ 为词表大小，必须先对词表维做 `log_softmax`，再按实际下一个 token `gather`，最后按回答 mask 求和。

```python
# 教学片段：input_ids 和 answer_mask 都是 [2B, L]。
# answer_mask 在要训练的回答 token（包括约定的 EOS）处为 1。
logits = model(input_ids, attention_mask=attention_mask).logits
next_logp = logits[:, :-1].float().log_softmax(dim=-1)
labels = input_ids[:, 1:]
token_logp = next_logp.gather(-1, labels.unsqueeze(-1)).squeeze(-1)
mask = answer_mask[:, 1:].to(token_logp.dtype)
sequence_logp = (token_logp * mask).sum(dim=-1)  # [2B]
```

`logits[:, t]` 预测 `input_ids[:, t+1]`。若 mask 没有一起右移对齐，模型可能在优化 prompt 的最后一个 token，或漏掉回答的第一 token。

### 5.1 求和与平均不是同一个目标

经典 DPO 用序列 logprob 求和。若将它改成回答长度上的平均，长短回答的相对贡献发生变化，已经是修改后的目标，不能仍声称逐式复现原始 DPO。

例如回答 A 两个 token，logprob 都为 $-1$，总和为 $-2$；回答 B 四个 token，logprob 都为 $-0.75$，总和为 $-3$。求和与平均给出的排序相反。

长度 bias 应通过数据与明确的方法修正分析，不能在 loss 里随手加一个 `.mean()`。

### 5.2 padding 与 EOS

Prompt token 和 PAD 通常不进入回答 logprob；EOS 是否计入必须与序列定义一致。若 PAD 和 EOS 使用相同 ID，不能仅按 `id != pad_id` 构造 mask，否则真实 EOS 也会被删除。

对偏好对的两条回答，模板、prompt 前缀、tokenizer 版本必须一致。尤其注意拼接后的 tokenization 不一定等于两段分别 tokenize 再连接。

## 6. 参考策略、缓存与显存

Reference 提供固定基线，不参与反向传播。在一个示意训练步中：

```python
# 以下四个张量均为 [B]，来自相同 token IDs 与 mask。
policy_gap = policy_chosen_logp - policy_rejected_logp
reference_gap = ref_chosen_logp.detach() - ref_rejected_logp.detach()
z = beta * (policy_gap - reference_gap)
loss = torch.nn.functional.softplus(-z).mean()
```

Reference 的前向计算可预计算缓存，但缓存键不能只有数据行号。至少应绑定参考权重版本、tokenizer、chat template、截断规则、精确 token IDs、answer mask 与 logprob 归约约定。

LoRA 场景可能通过禁用 adapter 获得参考分布，但只有在基座、adapter 初始化和参考定义符合预期时才成立。不要假设“只用一个模型对象”就自动等于正确 reference。

DPO 没有生成 KV cache 和 Critic 的强制需求，但仍要处理 chosen/rejected 双序列的激活、Actor 优化器状态及 Reference 权重/缓存。它不是零显存成本的 SFT 替代品。

## 7. 离线优化的能力边界

| 维度 | 经典离线 DPO | 在线 PPO/GRPO |
|---|---|---|
| 训练样本 | 固定偏好对 | 当前或近期策略生成的轨迹 |
| 训练时新采样 | 不必 | 核心环节 |
| 反馈来源 | 已有 chosen/rejected 标签 | 奖励模型、规则或环境 |
| 探索新回答 | 不在基本训练循环中 | 通过 rollout 发生 |
| 主要系统压力 | 双序列训练、Reference 评估 | 生成、打分、更新、同步 |

DPO 只能从给定偏好覆盖中学习。如果数据中从未出现某类工具使用或新的推理路径，loss 下降不能证明模型学会了相关行为。

也不能要求每个 chosen 的绝对概率必定上涨：目标关注相对 reference 的 chosen/rejected **差值**，其他词汇、其他样本和共享参数耦合都可能使两者概率同时下降，而 rejected 下降更多。

在线采样后构造新偏好对再训练 DPO 是另一种工作流；是否在线，应由实际数据生成流程判断，而不是仅看 loss 名称。

## 8. 实施前的检查顺序

1. 人工检查 10 对文本，确认 prompt 与标签语义。
2. 打印 token IDs、shift 后的 target 和回答 mask。
3. 令 Actor 等于 Reference，检查所有 pair 的 $z$ 接近 0。
4. 交换一对 chosen/rejected，确认 $z$ 符号反转。
5. 用独立 prompt 集评估质量、长度和参考偏移。
6. 记录数据版本、tokenization 规则与缓存来源。

具体训练器可参考 [TRL DPO 文档](https://huggingface.co/docs/trl/dpo_trainer)。本文中的数学目标固定为基本 sigmoid DPO；文档中的其他 loss 类型不应在未核对配置时套用相同解释。

## 🎯 自测与参考答案

**1. Actor 与 Reference 完全一样时，DPO loss 必须为 0 吗？**

不是，为 $\log2$。模型尚未表达偏好，分类概率为 0.5。

**2. 为什么可以不计算 $Z(x)$？**

相同 prompt 的两条回答做奖励差时，prompt 级归一化常数抵消。

**3. 只提高 rejected 的负对数似然，能降低 DPO loss 吗？**

能。只要 chosen 相对 rejected 的 logprob 差增大。因此还要独立检查 chosen 的绝对 logprob 与真实生成质量。

**4. 如果换了 chat template，缓存的 Reference logprob 能否复用？**

通常不能。输入 token 与条件概率已改变；必须验证精确 token IDs、mask 和参考权重完全一致，否则重算。
