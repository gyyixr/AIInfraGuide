想让高分回答更容易出现，只需要提高它的概率；但如果同一批回答被训练很多次，策略可能迅速偏向少数样本。PPO 的核心是让训练看到：这个动作相对采样时已经改变了多少，以及这个改变是否仍值得继续鼓励。

本文讨论 **PPO-Clip**。PPO 是一组近端策略优化方法，原论文还讨论 KL penalty 形式；不要把所有带 KL 的损失都叫作同一种 PPO 实现。

## 1. 从一次采样到多次更新

设 rollout 时的策略为 $\pi_{\mathrm{old}}$，训练中的策略为 $\pi_\theta$。采样得到动作 $y_t$ 后，保存：

$$
\ell_t^{\mathrm{old}}=\log\pi_{\mathrm{old}}(y_t\mid s_t)
$$

当前模型每次训练前向重新计算 $\ell_t^\theta$，概率比为：

$$
\rho_t=\frac{\pi_\theta(y_t\mid s_t)}{\pi_{\mathrm{old}}(y_t\mid s_t)}
=\exp(\ell_t^\theta-\ell_t^{\mathrm{old}})
$$

若某 token 的旧概率为 0.2，新概率为 0.3，ratio 为 1.5，表示其概率变为原来的 1.5 倍。

在同一状态下，重要性采样满足：

$$
\mathbb{E}_{a\sim\pi_\theta}[f(a)]
=\mathbb{E}_{a\sim\pi_{\mathrm{old}}}[\rho(a)f(a)]
$$

前提包括支持集覆盖等条件。PPO 对旧轨迹上的状态与固定优势使用这种 ratio 构造**局部代理目标**；它不是完整消除新旧轨迹分布差异的精确校正。

## 2. 最先区分三个对象

| 对象 | 作用 | 更新频率 |
|---|---|---|
| Current Actor | 当前要训练的策略 | 每个 optimizer step |
| Old policy | 本批样本的采样基准 | 一轮新 rollout 时刷新 |
| Reference | 约束策略长期偏移的参照 | 常在一个训练阶段内冻结 |

Old policy 未必需要一份始终常驻 GPU 的完整模型。若采样和重算流程一致，存下所需的 old logprob 即可服务后续 ratio 计算。

但“省掉一份模型”不能省掉版本与概率语义。采样引擎返回的概率经过何种温度或过滤处理，必须与 ratio 分母的定义匹配。

## 3. PPO-Clip 的目标

先不考虑 KL、value loss 和 entropy，定义一个有效 token 的代理收益：

$$
s_t(\theta)=\min\left(\rho_t A_t,\operatorname{clip}(\rho_t,1-\epsilon,1+\epsilon)A_t\right)
$$

训练最小化其负值。若采用全局有效 token 平均：

$$
L_{\mathrm{policy}}=-\frac{\sum_t m_t s_t}{\sum_t m_t}
$$

$A_t$ 是固定优势，$m_t$ 是有效动作 mask，$\epsilon$ 是裁剪阈值。本节取 $\epsilon=0.2$，上下界为 0.8 和 1.2。

[PPO 原论文](https://arxiv.org/abs/1707.06347) 提出了这种 clipped surrogate。理解它的最快方法，是分别看正优势与负优势的分段函数。

### 3.1 正优势：限制继续放大奖励方向

当 $A_t>0$：

$$
s_t=A_t\min(\rho_t,1+\epsilon)
$$

取 $A=2$：

| $\rho$ | $\rho A$ | $\operatorname{clip}(\rho)A$ | 最小值 |
|---:|---:|---:|---:|
| 0.7 | 1.4 | 1.6 | 1.4 |
| 1.0 | 2.0 | 2.0 | 2.0 |
| 1.4 | 2.8 | 2.4 | 2.4 |

在 ratio 超过 1.2 后，继续提高该 token 概率不再增加这一项的代理收益。

若 ratio 掉到 0.7，说明一个好动作的概率反而降低。目标仍保留梯度，促使它恢复；不是只要越界就把梯度统统关掉。

### 3.2 负优势：限制继续降低概率的收益

当 $A_t<0$，乘以负数会反转大小关系：

$$
s_t=A_t\max(\rho_t,1-\epsilon)
$$

取 $A=-2$：

| $\rho$ | $\rho A$ | $\operatorname{clip}(\rho)A$ | 最小值 |
|---:|---:|---:|---:|
| 0.7 | -1.4 | -1.6 | -1.6 |
| 1.0 | -2.0 | -2.0 | -2.0 |
| 1.4 | -2.8 | -2.4 | -2.8 |

负优势回答的概率已经降低很多时，进一步降低不再获得额外收益；若它的概率反而上升，仍要继续惩罚。

### 3.3 为什么一定是 min

PPO 最大化一个相对保守的代理收益，所以取两个候选收益中较小的那个。实现成 loss 后可以写 `maximum`，但那是先对候选项取了负号。

```python
surrogate = torch.minimum(ratio * advantage, clipped_ratio * advantage)
loss = -surrogate.mean()
```

如果只写 `-clipped_ratio * advantage`，有害方向的梯度也可能被截掉，语义就变了。

## 4. 裁剪不是概率硬约束

PPO 并不把模型概率投影回某个集合。即使某 token 的 policy 项进入平坦区域，其他 token、KL 项、共享参数的更新仍可能让它的 ratio 继续变化。

所以：

- $\epsilon=0.2$ 不等于每个 token 概率最多变化 20%。
- `clip_fraction` 高不能直接推出学习率过大，还需结合优势、epoch 数和采样版本。
- 稀有 token 的 ratio 可以很大，必须检查分位数与极值。

实践中常搭配更新 KL 监测、学习率控制或提前停止；具体方案由实现决定。

## 5. token ratio 与 sequence ratio

回答长度为 $T$ 时，整条回答的概率比是：

$$
\rho_{\mathrm{seq}}=\prod_{t=1}^{T}\rho_t
=\exp\left(\sum_t\ell_t^\theta-\ell_t^{\mathrm{old}}\right)
$$

若每个 token 的 ratio 都是 1.01，1000 个 token 的 sequence ratio 约为 $1.01^{1000}\approx20959$。

常见 LLM PPO 使用 token 级 surrogate，避免直接采用这个高方差乘积。token ratio 与 sequence ratio 对应不同的优化设计，不能只更换 reduction 就宣称等价。

sequence-level importance sampling、几何平均 ratio 等方法属于其他明确设计，阅读实现时应看 ratio 是在 `exp` 前还是后沿序列维归约。

## 6. KL 有两个参照对象

### 6.1 参考 KL：限制偏离 reference

在固定前缀状态 $s$ 下：

$$
D_{\mathrm{KL}}(\pi_\theta\Vert\pi_{\mathrm{ref}})
=\sum_a\pi_\theta(a\mid s)\log\frac{\pi_\theta(a\mid s)}{\pi_{\mathrm{ref}}(a\mid s)}
$$

它描述当前分布相对参考分布的偏离。RLHF 常把参考约束加入 token 奖励，也可单独加入可微的 KL loss；应先确认框架实际走哪条路径，避免无意重复惩罚。

若奖励整形采用 $r_t^{\mathrm{KL}}=-\beta(\ell_t^{\mathrm{old}}-\ell_t^{\mathrm{ref}})$，它在采样评分阶段形成数值奖励，随后参与优势计算。Actor 更新时不会通过这份冻结奖励直接反向。

### 6.2 更新 KL：监测 old 与 current 的变化

它描述一次 rollout 到后续更新之间策略移动了多远，常用于观察样本复用程度和是否需要提前停止。

一个模型可能距离 old 很近，却已距离初始 reference 很远；两个 KL 不能互相替代。

### 6.3 一个采样 log-ratio 不保证非负

单个动作上的 $k_1=\log\pi_\theta(a)-\log\pi_{\mathrm{ref}}(a)$ 可以为负。只有按当前策略对动作求期望，才得到上述非负 KL。

令 $d=\log\pi_{\mathrm{ref}}(a)-\log\pi_\theta(a)$，另一种常见采样估计为：

$$
k_3=e^d-d-1\ge0
$$

在动作确实从当前策略采样、概率归一化且支持集满足要求时，其期望也等于对应 KL。旧策略样本上直接平均 $k_3$，不自动具备对当前 KL 的无偏性；多轮复用和采样过滤都要单独分析。

“估计值无偏”和“把该表达式直接反向得到精确 KL 梯度”还是不同问题：采样分布随参数变化时，梯度还涉及分布依赖。生产实现通常使用明确的代理形式，而不能仅凭公式名字判断。

## 7. 一个最小 policy loss 核心

下面函数明确采用有效 token 平均，不包括 KL、Critic 或 entropy：

```python
import torch


def ppo_policy_loss(new_logp, old_logp, advantage, mask, epsilon=0.2):
    """所有张量形状为 [N, T]；new_logp 连接当前 Actor 的计算图。"""
    valid = mask.bool()
    if not valid.any():
        raise ValueError("没有有效动作")
    log_ratio = new_logp[valid] - old_logp.detach()[valid]
    ratio = log_ratio.exp()
    adv = advantage.detach()[valid]
    if not torch.isfinite(ratio).all() or not torch.isfinite(adv).all():
        raise ValueError("ratio 或 advantage 出现非有限值")
    clipped = ratio.clamp(1 - epsilon, 1 + epsilon)
    surrogate = torch.minimum(ratio * adv, clipped * adv)
    return -surrogate.mean()
```

不要为了压住溢出而随意 clamp log-ratio，却不记录这会改变梯度。先定位非有限值来自错误 mask、错版本、极低旧概率，还是数值精度问题。

生产实现还需要按全局有效 token 数正确加权，以及处理空 microbatch、分布式同步和混合精度。这段代码只展示目标函数。

## 8. 总损失与监控量

一个可能的总损失组合是：

$$
L=L_{\mathrm{policy}}+c_vL_{\mathrm{value}}+\beta L_{\mathrm{KL}}-c_H H
$$

这里 $c_v,\beta,c_H$ 都需要明确；若 KL 已放入奖励，是否再保留 $L_{\mathrm{KL}}$ 应由算法设计决定。

Entropy $H=-\sum_a\pi(a)\log\pi(a)$ 描述词表分布多样性。单个 sampled token 的 $-\log\pi(a)$ 只有在相应采样分布下才是 entropy 的估计，直接对该标量求导也不自动等于完整 entropy 梯度。

建议至少同时查看：

| 指标 | 它能帮助发现什么 |
|---|---|
| 原始奖励与验证集质量 | 是否在任务上进步 |
| old/current ratio 分位数 | 是否严重偏离采样策略 |
| clip fraction | 有多少动作进入裁剪区域 |
| 参考 KL 与更新 KL | 长期偏移与单轮移动 |
| entropy 与回答长度 | 探索坍塌、长度漂移 |
| advantage 均值/方差 | 奖励尺度和有效信号 |

指标应先按相同 mask 与 reduction 统一口径，否则两份日志可能描述不同 token 集合。

## 9. 一个反直觉现象：loss 为 0，梯度不为 0

首个更新前，若 old 与 current 一致，则 ratio 都为 1。若优势做了零均值标准化，policy loss 的数值可以恰好为 0。

但梯度包含各 token 的 $A_t\nabla\log\pi_\theta(y_t\mid s_t)$。不同 token 的导数并不相同，优势数值相加为零不意味着加权导数相加也为零。

这也是为什么不能用 policy loss 单独作为收敛或任务质量指标。

## 10. 自测与参考答案

**题 1：$A=-3,\rho=0.5,\epsilon=0.2$，surrogate 是多少？**

答：未裁剪项 -1.5，裁剪项 -2.4，取最小值 -2.4。该单项对继续降低 ratio 已无激励。

**题 2：$A=3,\rho=0.5$ 时是否裁剪掉纠正梯度？**

答：不会。未裁剪项 1.5 小于裁剪项 2.4，保留未裁剪分支。

**题 3：为什么一个 batch 内不能每次 optimizer step 后覆盖 old logprob？**

答：会把同一批轨迹的采样参照不断改写，ratio 不再衡量相对真实采样策略的累计变化。

**题 4：采样得到负的 log-ratio 是否说明 KL 实现必然错误？**

答：不一定。单个样本 log-ratio 可以为负；需要确认估计器、采样分布、平均方式和参考方向。
