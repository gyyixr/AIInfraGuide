## 本章解决的问题

一个长Agent轨迹既是模型输入，也是一系列有状态环境交互。

其中只有部分token由Actor采样，工具观测却可能占据绝大部分上下文。

轨迹跨越多次生成、工具等待、奖励和训练更新，策略与环境版本也可能变化。

因此长上下文RL同时包含目标正确性、数值稳定性和平台供给问题。

本章把三者连接起来。

## 11.1 长轨迹Mask与分布式Loss归一化

从一条带两轮assistant动作和工具观测的短轨迹开始。

逐位置标注token作者、采样来源、target shift与有效mask。

再把同一轨迹切到多个CP分片，计算正确全局numerator与denominator。

最后从实际梯度reducer推导本地backward缩放。

关键结论是：不能不看SUM/AVG协议就机械乘world size。

本篇提供两个CPU oracle，覆盖移位、局部均值陷阱和两级归约。

## 11.2 GSPO序列比率与离策略校正

本篇固定Qwen原论文v2与官方介绍的定义。

GSPO使用token log-ratio的平均值经exp得到序列ratio。

它是联合概率比率的长度归一化幂，不是联合密度比本身。

正文推导优势符号与clip分支、未裁剪梯度及GSPO-token的stop-gradient构造。

两个数例分别验证ratio与梯度，并反证几何平均不能直接套标准无偏IS恒等式。

异步行为分布q与训练old不同的问题仍需独立处理。

## 11.3 Agent环境吞吐与训练稳定性

把prompt、生成、工具、环境、奖励、完整组和trainer分成有界队列。

手算环境服务需求、reward瓶颈和实际可接受动作吞吐。

再用Little定律解释等待轨迹为何持续占内存。

取消、超时、幂等、奖励版本与迟到结果都进入状态协议。

最后检查平台选择偏差是否让模型只学习容易且快完成的任务。

## 三条贯穿全章的不变量

第一，Actor真正采样的动作与训练目标mask一致。

第二，记录的logprob对应相同token、相同历史与明确的行为分布。

第三，进入一次更新的数据、奖励和归约权重属于同一个可解释目标。

任何吞吐优化都应保持这些不变量，或明确说明改变了什么目标。

## 状态生命周期

```mermaid
flowchart LR
  A[带版本的prompt与环境] --> B[Actor动作与行为概率]
  B --> C[工具观测与状态]
  C --> B
  B --> D[终局与奖励版本]
  D --> E[轨迹mask与组有效性]
  E --> F[CP与DP目标归约]
  F --> G[策略更新与发布]
```

图中的工具观测是模型上下文，不自动成为policy动作。

图中的奖励完成也不代表整组已经满足入队条件。

图中的策略发布必须能与下一批行为版本关联。

## 两种分布式计数不要混用

独立数据副本增加样本数量。

CP切片拆开同一轨迹的目标位置。

TP与PP协作完成同一逻辑模型计算。

这些角色在world中都占rank，但不具有相同的loss分母语义。

归约应从数学目标和参数复制域推导。

## 研究与工程边界

GSPO论文的经验结果只属于其报告的模型、任务和配方。

不能由“序列级更稳定”推出任意推理引擎概率都可直接替用。

也不能由一个归一化ratio推出完整离策略校正无偏。

DSec与RobustRL提供环境和恢复研究案例。

本章借鉴其问题分解，不声称复现其部署规模或内部实现。

## 建议的阅读与实验顺序

1. 在纸上标注一条多轮轨迹的每个token作者。
2. 执行11.1两个oracle，理解日志loss与backward缩放的区别。
3. 执行11.2 ratio与无偏反例，区分surrogate和标准IS。
4. 执行11.3容量与选择偏差例子。
5. 在目标框架中建立固定小batch的单步对照。
6. 再逐项加入CP、异步队列与环境故障。

每一步保留输入、版本、mask、分母和参数变化。

只有这样，质量下降时才能区分数学、数据与平台原因。

## 学习验收

- 能解释工具观测末token为何可以预测下一段有效Actor动作。
- 能从实际reducer推导本地loss缩放，而不盲目使用world size。
- 能区分GSPO几何平均、算术平均和联合概率比率。
- 能按优势符号判断clip是否进入零梯度分支。
- 能给出几何权重不是标准IS密度比的有限反例。
- 能解释reward版本混用如何制造伪组内优势。
- 能用服务需求与接受比例估算trainer的有效数据供给。
- 能定义取消、迟到结果与重复消息的处理边界。
