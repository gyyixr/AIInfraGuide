“DeepSeek开放了什么”不能只用一个是或否回答。
论文、权重、推理参考代码、训练组件和生产服务核心，开放程度与可复现能力各不相同。

本页的核对日为2026-11-07。
许可证部分只记录官方原文指向和artifact归属，不替代具体使用场景的法律判断。

## 1. 从交付物而不是宣传词开始

先把一次模型发布拆成具体artifact：

| artifact | 解决的问题 |
|---|---|
| 技术报告 | 解释设计与实验结论 |
| 模型权重 | 提供训练后的参数 |
| config | 确定结构和部分超参数 |
| tokenizer/encoding | 定义文本和消息到token的映射 |
| 推理参考源码 | 表达数学前向与加载方式 |
| 高性能kernel | 在目标设备执行某些操作 |
| 训练脚本 | 组织某些训练步骤 |
| 数据与处理链 | 决定模型看到什么 |
| 完整训练状态 | 支持精确继续运行 |
| 服务系统 | 提供调度、存储、容错和API |

有一行不意味着其他行自动存在。

## 2. 一个模型“能跑”需要哪些东西

最小离线生成至少需要兼容的权重、结构、tokenizer和执行实现。
还要满足dtype、设备内存和并行方式。

如果消息编码错误，模型可能仍输出文本，但工具调用、思考模式和视觉span语义会变。
如果cache布局错误，shape也可能正常，而输出完全错误。

因此“成功import”“生成了几个字”与“兼容该模型”之间仍有验证距离。

## 3. 完整从零训练需要更多信息

即使有论文和推理代码，还缺少：

- 精确语料快照与数据许可。
- 去重、过滤、质量判定、混合比例及采样顺序。
- 初始化、随机种子、优化器状态与精度策略。
- 分布式分片、流水线计划与动态负载策略。
- checkpoint恢复、失败重试与异常处理。
- 后训练奖励、工具环境与数据合成流程。
- 完整实验配置、算力资源与评估脚本。

其中一些细节在论文中披露，并不意味着全部以可运行代码和数据发布。

## 4. 开放状态矩阵

以下是本次实际检索的范围，不宣称已证明所有未找到的材料永远不存在。

| artifact | V3/R1路线 | V4/V4.1路线 |
|---|---|---|
| 论文/报告 | 有官方报告 | 有官方报告 |
| 权重 | 有对应公开模型 | 有对应公开模型，需区分版本 |
| 配置/tokenizer | 有 | 有 |
| 最小推理参考 | V3官方inference等 | HF inference目录 |
| 特定高性能kernel | FlashMLA/DeepGEMM等 | 当前库与新模型专用路径 |
| 完整原始预训练语料 | 本次未找到完整可下载复现包 | 本次未找到完整可下载复现包 |
| 全量生产训练框架 | 组件和报告可见，不能等同全量 | 组件和报告可见，不能等同全量 |
| 后训练全部数据/环境 | 未形成全部可复现闭环 | 未形成全部可复现闭环 |
| 在线完整服务控制面 | 公开材料和部分核心 | DeepInfer公开offline core有明确边界 |

结论应写“已公开A、B；复现C仍缺D”，比“完全开源”或“什么都没开源”准确。

## 5. 论文披露不等于代码开放

论文可能给出公式、伪代码、超参数与实验表。
这足以学习方法、实现小规模原型。

但生产实现可能包含大量未写在公式中的布局、状态机、容错和特殊边界处理。
这些细节对吞吐和可靠性很重要。

反过来，未公开完整生产代码也不妨碍已公开公式提供真实研究价值。
判断应按具体复现目标进行。

## 6. 代码开放不等于训练数据开放

一个训练脚本可能接受任意本地数据路径。
如果真实训练数据、混合顺序和过滤规则没有发布，就不能仅凭脚本复现同等能力。

数据规模“45T tokens”不是数据集本身。
“合成agent环境”也不等于全部环境镜像、验证器和任务快照公开。

将这种缺口明确记录，有助于读者区分学习实验与模型复刻。

## 7. 权重开放不等于训练过程可复现

权重提供训练后的函数，可以用于推理、分析和适配。
但仅靠最终权重通常无法恢复训练数据顺序、优化器轨迹或失败恢复过程。

这与拿到编译后二进制不能完整还原开发过程有类似之处，但权重仍是可操作的重要artifact。

“开放权重”是具体描述，不应被当作否认其他贡献的贬义词。

## 8. 先区分代码许可证与模型许可证

早期DeepSeek模型仓库常把两者分开。
例如V3固定README说明：代码使用MIT，Base/Chat模型适用单独的Model License。

因此不能看到仓库右侧MIT标识，就推断其中每个权重和所有派生数据均受同一许可证覆盖。

[DeepSeek-V3固定许可证说明](https://github.com/deepseek-ai/DeepSeek-V3/blob/9b4e9788e4a3a731f7567338ed15d3ec549ce03b/README.md#7-license)是这里的直接证据。

## 10. R1与蒸馏模型的来源链

[R1官方README](https://github.com/deepseek-ai/DeepSeek-R1#7-license)说明其代码和模型权重使用MIT，并另行列出蒸馏模型的底座来源。

R1-Distill-Qwen来自对应Qwen模型。
R1-Distill-Llama来自对应Llama版本。

一个蒸馏模型既有DeepSeek发布说明，也有底座模型来源。
不能因为文件名包含R1，就假设它使用V3的MLA+MoE架构或忽略底座许可文件。

## 13. 许可证记录应保存哪些字段

```yaml
artifact: deepseek-ai/DeepSeek-V4.1-Flash
revision: 314113f8a7dadb388215396ba5fbee2c610a04d6
checked: 2026-11-07
license_file: LICENSE
model_card_scope: repository and model weights
upstream_dependencies: inspect separately
```

这种记录比只写“可商用”更可审计。
“可商用”不是对保留版权声明、再分发条件和上游依赖等具体条款的完整描述。

## 14. 参考实现与生产核心的差别

V4.1的 `inference/README.md`将其定位为可读参考实现。
它包含主要架构前向，但普通生成路径并不是完整生产DSpark调度。

DeepInfer的公开范围更靠近高性能计算核心。
其README也明确区分offline core与未包含的服务层功能。

“这两份代码都能运行模型”不意味着它们开放同一层级的系统能力。

## 15. DeepInfer当前公开范围的例子

固定 [DeepInfer README](https://github.com/deepseek-ai/DeepInfer/blob/a679bb86ce36e883a98a97733492b686e5b9a08e/README.md)说明公开offline inference core。

其中不包含全部在线KV cache服务、VE/P/D分离控制和跨DP副本负载均衡等服务管理部分。

因此可以说“公开核心展示了特定模型的高性能执行”。
不能说“下载仓库即得到DeepSeek线上服务的所有控制、可靠性和存储能力”。

## 16. 公开库与内部部署有时间差

同一项目可能经历接口删除、架构迁移和目标设备变化。
FlashMLA的2026-09-30更新就是明确例子。

旧论文性能图对应旧代码、旧GPU和旧cache格式。
当前HEAD支持新模型并不意味着能直接复现那张旧图。

复现性能首先需要找出原实验版本，而不一定是checkout最新main。

## 17. 证据等级

| 等级 | 可以说什么 | 不足以说明什么 |
|---|---|---|
| E1 论文/README | 作者提出或报告了某结果 | 本地已经复现 |
| E2 固定源码/配置 | 指定版本实现了某路径 | 目标硬件一定高效 |
| E3 小张量数学实验 | 某公式、shape或数值性质成立 | 完整模型质量 |
| E4 单机真实设备 | 指定设备和工作负载实测 | 多机生产吞吐 |
| E5 多机端到端 | 指定规模与负载下系统结果 | 任意业务长期收益 |

本专题每个结论应落在具体等级，不用“已验证”掩盖验证对象。

## 18. 用一个例子区分四种结论

对于MLA矩阵吸收，可以分别写：

1. V2论文提出该设计。
2. V3固定源码包含naive/absorb两条路径。
3. 一个FP64小矩阵实验核对二者输出一致。
4. 某GPU上的kernel benchmark测得给定shape下的时延。

前三项不能替代第四项。
第四项也不保证完整请求延迟同比改善。

## 19. 性能报告最少需要哪些字段

| 字段 | 示例问题 |
|---|---|
| 模型 | 哪个权重revision，Base还是Instruct |
| 硬件 | GPU/NPU型号、数量、显存与互联 |
| 软件 | driver、CUDA/CANN、库commit |
| dtype | 权重、激活、KV、scale分别是什么 |
| shape | batch、输入长度、输出长度、top-k |
| 阶段 | prefill、decode、rollout还是端到端 |
| 指标 | TFLOPS、GB/s、TTFT、TPOT、吞吐 |
| 方法 | warm-up、重复次数、同步和统计分位数 |

缺少其中关键字段时，应保留结论范围，而不是补上猜测。

## 20. 吞吐与延迟不是同一个指标

每秒总输出token增加，可能来自更大batch。
每个用户的TPOT可能同时变差。

prefill吞吐高，也不保证第一个token快速到达，因为队列等待和调度会进入TTFT。

因此agent场景还要测工具执行、重试、总token与最终任务成功率。
仅看一个离线tokens/s不能判断用户体验。

## 21. 字节数也需要标明统计边界

“890 bytes/token”指V4.1特定格式的全局main KV加index K。
不是整个服务总显存除以token数。

逻辑字节数、实际allocated memory、峰值reserved memory与磁盘持久化容量是不同指标。

scale、页对齐、碎片和副本复制都可能使物理占用大于逻辑数据。
本专题2.9给出了这890字节的完整可复核算术。

## 22. 一次模型复现的缺口清单

假设已有权重、tokenizer、推理参考与论文，想复现训练后的任务成功率。
还需要确认：

- prompt编码是否匹配模型版本。
- reasoning effort与输出token预算。
- temperature、top-p及停止条件。
- benchmark任务快照与污染检查。
- 工具权限、网络和运行环境。
- harness版本和系统提示。
- 多次采样数与统计方式。

“同一模型名”远远不足以定义相同评估。

## 23. 一个基准比较反例

模型A用1次采样、无工具，模型B用8次采样、允许测试和修复。
即使任务名称相同，B的成功率也不能直接证明其单次纯模型能力更高。

同理，给B更长输出预算会改变推理成本。
比较时至少给出质量与资源消耗两个维度。

这里不是否认工具增强结果，而是要求把结果归属于正确的系统配置。

## 24. 不把API别名当权重证据

官方API的模型名可能在版本更新时路由到新模型。
历史发布公告与后续更新日志也可能出现不同阶段的迁移安排。

分析一次实验时应记录调用日期、返回模型标识与当时官方映射。
离线权重实验则记录仓库revision与文件校验。

不要用今天别名指向的模型，反推几个月前实验实际使用的版本。

## 25. 如何表达未公开和未核验

以下表述分别适用于不同证据情况：

- “官方仓库明确说明不包含该服务部分。”
- “在本次检索的官方材料中未找到完整训练包。”
- “论文披露方法，但本仓库未运行该规模实验。”
- “参考实现包含语义路径，生产优化细节仍需单独核对。”

不要把没有找到升级为永远不存在。
也不要把论文提到升级为已经公开全部代码。

## 26. 本专题采用的复现目标

本专题优先完成可学习与可审阅的闭环：

1. 官方来源确认机制和版本。
2. 固定源码确认shape与数据流。
3. 独立数例解释公式。
4. 小规模实验验证数学与状态边界。
5. 明确写出未进行的硬件和生产验证。

大型模型训练、在线服务以及数千GPU部署不能用教学模拟冒充。

## 27. 自测与答案

**问题1：仓库标MIT，是否能断言所有模型和数据都是MIT？**

答案：不能，必须按artifact检查，早期V3就区分代码与模型许可证。

**问题2：有最终权重，能否恢复完整训练过程？**

答案：不能，训练数据、优化器轨迹、随机状态和系统行为仍可能缺失。

**问题3：论文中报告性能是否算本地验证？**

答案：不算，应标为团队报告并保留实验条件。

**问题4：DeepInfer公开是否代表完整线上服务开源？**

答案：当前README明确其offline core范围，部分服务系统不包含。

**问题5：R1-Distill-Llama是否使用V3的MoE结构？**

答案：不能从R1名称推断；它继承对应Llama底座架构。

**问题6：小矩阵FP64等价能否证明FP4质量无损？**

答案：不能，量化和完整模型分布需分别验证。

**问题7：为什么最新HEAD可能不适合复现旧benchmark？**

答案：支持设备、接口、内核与cache格式都可能改变。

## 28. 新补充组件的开放边界

| 对象 | 本次确认 | 不据此推断 |
|---|---|---|
| HAI Platform | HFAiLab独立源码，固定LICENSE为GNU LGPL v3 | 全部HFReduce/HaiScale生产代码开放 |
| DSec | 官方作者系统论文 | 完整sandbox server与内部部署已公开 |
| VL2/Janus | 推理代码、模型与研究材料；代码和模型协议分别检查 | 全量原始训练数据和集群可复刻 |
| OCR/OCR2 | 官方模型、推理路径与论文 | 任意文本无损压缩或任意设备同吞吐 |
| Harness | 插件与agent执行代码 | LLM梯度训练与DSec完整后端 |
| Recipe | 协议、模板、tokenizer接口与mock示例 | 模型推理、工具执行和HTTP由库自动完成 |

[HAI固定LICENSE](https://github.com/HFAiLab/hai-platform/blob/f9119b1f437039e3969a1dd5beaa8898a1cb6b02/LICENSE)与DeepSeek MIT库不同，应按artifact保留真实许可入口。
这张表同时记录“确实公开”与“公开范围”，避免把两者混成单一标签。
