## 1. 技术谱系不能只从 V3/R1 开始

DeepSeek 后来的 MLA、MoE、RL 与系统优化，建立在较早的通用预训练、代码数据与专业化训练研究之上。本节补齐这些在总览中容易只剩名称的技术。

我们关注可迁移的机制：如何构造任务与数据、如何区分 base 与 chat、代码补全为什么需要 FIM、稀疏模型怎样选择一部分专家微调。

## 2. DeepSeek LLM：预训练与对齐的分工

早期公开路线包含7B/67B级base和chat模型，以及中英文大规模语料训练研究。base模型学习语言分布；SFT与DPO等后训练再改变指令跟随和偏好行为。

需要区分三个不同结果：

- 预训练loss或困惑度改善。
- 固定任务集上的准确率或代码通过率。
- 对话偏好与指令行为改善。

它们有关联，却不是可以互相替代的指标。一个chat模型更符合偏好，不代表同条件下其基础语言建模loss一定更低。

### 2.1 为什么 Scaling 研究与 Infra 有关

给定近似训练预算 $C\approx6ND$，选择更大模型N或更多token D，会改变状态显存、通信、数据吞吐和最终能力。

例如预算为 $6\times7\times10^9\times2\times10^{12}$ FLOPs 的示意训练，若模型参数翻倍且保持其他近似成立，可用token预算减半。是否更划算需要实验拟合与任务评估，不能只看模型更大。

这个简式忽略长序列Attention、重计算等；它用于建立预算约束，完整模型见分布式训练第15章。

## 3. Coder 的核心首先是数据和任务

DeepSeek-Coder论文与官方仓库报告从头训练代码模型，包含项目级语料、较长窗口和代码填空任务。具体报告规模与配比属于该版本的数据条件，不能当成所有代码模型的通用配方。

代码数据与普通网页文本有几个特殊点：

- 文件之间通过import、调用和类型关联。
- 很多生成任务要同时满足前缀与后缀。
- 缩进、空白、分隔符和特殊token可能改变语法。
- 仓库重复、模板代码和benchmark污染会使评估偏乐观。
- 能执行的程序与“看起来像代码”的文本不同。

因此，训练数据管线与评价方法必须围绕这些特点设计。

## 4. 项目级上下文怎样组织

一个项目可能含有工具函数、类型定义与入口文件。如果完全独立地采样每个文件，模型更难学习跨文件依赖。

项目级构造通常需要维护文件边界、相对路径、依赖关系和总窗口预算。关键不是把整个仓库无条件拼进一个超长字符串，而是保留可解释的结构。

| 数据字段 | 用途 |
|---|---|
| repository/version | 去重、切分和来源追踪 |
| file path | 同名符号与模块归属 |
| language | 解析、过滤和采样配比 |
| dependency/context | 决定可见上下文 |
| split label | 防止训练/评估仓库泄漏 |
| transformation version | 复现FIM、过滤与tokenization |

同一仓库的近重复版本若分别进入训练与评估，可能让“项目级补全能力”变成对已有代码的记忆。切分单位应与预期泛化单位匹配。

## 5. FIM：预测中间段，而非只续写尾部

设原代码分为前缀 P、中间段 M、后缀 S。普通自回归目标主要学习按原顺序续写：

$$
P\to M\to S.
$$

FIM 将训练输入改造成带明确分隔的序列，使模型在看到P和S后生成M。概念格式可写成：

```text
[PREFIX] P [SUFFIX] S [MIDDLE] M
```

这些标签只是本节的说明符号，实际模型的特殊token必须使用对应tokenizer和公开模板，不应跨模型抄字符串。

### 5.1 “看到后缀”为什么不违反自回归

自回归的因果性针对**变换后的训练序列**。S被放到M之前，模型生成M时看到S正是任务定义；这并不允许模型看到尚未生成的M答案。

若在原顺序里直接把未来答案token放进attention mask，则是另一回事。数据重排、特殊token、loss mask和实际采样条件需要一起定义。

### 5.2 一个代码插入例子

```python
prefix = "def add(a, b):\n    return "
middle = "a + b"
suffix = "\n"
reconstructed = prefix + middle + suffix

import ast
ast.parse(reconstructed)
assert reconstructed == "def add(a, b):\n    return a + b\n"
```

这个例子只检查拼接与语法。真实评估还需测试行为、边界输入和环境；通过AST解析不等于程序正确。

## 6. FIM 数据生成的工程细节

选择切分点时应考虑：

1. 字节、字符与token边界是否一致。
2. 是否保留真实空白与换行。
3. P/M/S总长度及特殊token占用。
4. 同一原始样本的多个变体是否被错误跨split使用。
5. loss到底计算整条变换序列，还是仅指定目标区域。
6. 训练FIM混合比例与实际线上插入任务是否匹配。

tokenizer不一定满足“分别编码各段后拼接”等于“拼接文本后一次编码”。特殊分隔符和边界空格都可能改变token ID。

因此应保留最终实际token序列与mask，而不只保留原始三段字符串。

## 7. Code benchmark 的三个层次

| 检查 | 能证明 | 不能证明 |
|---|---|---|
| 语法/编译 | 程序被解析器接受 | 逻辑正确或安全 |
| 单元测试 | 给定测试输入上的行为 | 未覆盖输入和环境 |
| 仓库级任务 | 一定工程上下文中的修改能力 | 任意生产项目可靠性 |

代码执行需使用受控环境和资源预算。评估还应固定语言运行时、依赖、超时、重试、采样与pass@k口径。

只报告一条最高分，无法区分模型提升、测试泄漏、采样次数增加或执行环境变化。后续Agent评价还要计入工具调用成本和任务完成时间。

## 8. Coder-V2：在通用稀疏骨干上继续训练

官方报告将Coder-V2描述为从DeepSeek-V2中间checkpoint出发继续预训练，强化代码与数学能力，同时评估通用能力保持。

公开模型表列出两组规模：

| 版本 | 总参数报告值 | 每token激活参数报告值 | 需区别的含义 |
|---|---:|---:|---|
| Lite | 16B | 2.4B | 权重容量与活动计算不同 |
| 完整版 | 236B | 21B | 低激活量不等于只需保存21B权重 |

官方还描述了更大的代码语种覆盖和128K上下文设置。它们是该模型训练与评估条件，不能推出所有语言、任意长度的任务都同样有效。

### 8.1 持续预训练不是重新初始化

从中间checkpoint继续，会继承已有表示、优化器/训练阶段选择和数据历史。复现实验应记录初始化权重、是否恢复optimizer、学习率重设、数据混合及总消费token。

“继续训练了6T token”的报告值，不等于完整模型只见过这6T，也不等于任意拿一个最终chat权重继续训练就得到同一路径。

## 9. ESFT 为什么与 MoE 结构有关

不同任务可能持续激活不同专家子集。ESFT研究利用这种专门化，仅调整与目标任务相关的部分参数，而保留其他部分。

它与LoRA的切分轴不同：LoRA通常在选定矩阵上引入低秩更新；ESFT利用已有稀疏专家结构选择要训练的模块。两者并非天然互斥，也不能仅凭“都少训参数”视作同一方法。

其公开工作流包括采样任务数据、统计专家分数、生成每层专家配置、训练和评估。

## 10. 专家相关性怎样统计

固定脚本提供token与gate两类统计：一类更接近专家被选择的频率，另一类累加路由权重。它们衡量不同侧面。

| 统计量 | 直觉 | 潜在问题 |
|---|---|---|
| Token相关统计 | 有多少任务token访问专家 | 高频不一定代表对任务最不可替代 |
| Gate相关统计 | 被选择时权重有多大 | 分数尺度与router规则有关 |
| 层内累计覆盖 | 选中专家覆盖多少统计质量 | 不等于选中多少百分比参数 |

公开脚本中还存在针对示例模型的专家数、MoE层数与top-k常量。迁移到另一个MoE结构时，不能只换模型路径而忽略这些假设。

## 11. `top_p` 不是“训练 p 比例的专家”

配置脚本按分数降序加入专家，直到累计分数达到阈值。它是统计质量覆盖阈值，不是固定专家数量比例。

假设归一化分数为 `[0.5,0.3,0.15,0.05]`，阈值0.7：

- 加入专家0后累计0.5，尚未达到。
- 再加入专家1后累计0.8，停止。

结果训练2/4个专家，但覆盖0.8统计质量。不能称为“训练70%专家”。

```python
def select_by_mass(scores, threshold):
    selected, mass = [], 0.0
    for expert, score in sorted(enumerate(scores), key=lambda x:x[1], reverse=True):
        if mass >= threshold:
            break
        selected.append(expert)
        mass += score
    return selected, mass

selected, mass = select_by_mass([0.5,0.3,0.15,0.05],0.7)
assert selected == [0,1] and abs(mass-0.8)<1e-12
```

如果输入分数未归一化或被四舍五入改变了总质量，阈值的解释也应重新检查。

## 12. 冻结参数不等于删除前向或反向路径

即使某个专家参数不更新，它仍可能被router选中参与前向。更重要的是，冻结模块的输入梯度可能需要传回上游可训练模块。

标量例子：$y=w_2w_1x$，固定 $w_2=2,x=3$，训练 $w_1=1$，损失 $L=y^2/2$。

$$
y=6,\qquad\frac{\partial L}{\partial w_1}=y\,w_2x=36.
$$

虽然w2不需要梯度，链式法则仍要经过它。把包含w2的整个计算包在`no_grad()`中，可能切断w1的梯度，而不是实现正确冻结。

参数的 `requires_grad=False`、不把参数交给optimizer、跳过整个模块，分别是不同操作。

## 13. ESFT 的显存与存储收益怎样估算

设总参数P、可训练参数比例f。一个简化账本是：

$$
M\approx M_{frozen\ weights}+M_{trainable\ weights}
+fP(b_g+b_{optimizer})+M_{activation}+M_{temporary}.
$$

梯度和优化器状态可能随f缩小，但完整前向权重、路由和相当一部分激活仍存在。因此总显存或总时间不一定按f线性下降。

保存增量时也需记录基座权重版本、专家选择配置、参数名称和量化方式。只拿一份专家文件，没有相容基座和映射，不能还原完整模型。

## 14. shared 与 non-expert 模块需要明确开关

公开配置脚本包含是否训练shared experts与non-expert modules的选项。不能仅凭ESFT名称推断所有attention、norm、embedding或共享专家必然冻结/训练。

可审查配置应列出实际可训练参数名、元素数、每层专家集合及optimizer参数组；保存一张布尔开关表比口头说“只训练专家”更可靠。

## 15. 专业化以后怎样评估遗忘

任务得分提高同时通用能力下降，是可能发生的。应保留：

- 目标任务独立测试集。
- 与专家选择统计不同来源的数据。
- 通用语言、代码或数学保留集。
- 训练参数量、存储量、wall time及峰值显存。
- 与全量微调、低秩方法及不同专家阈值的对照。

专家选择本身也使用数据，不能在最终测试集上探测最优专家再把同一测试分数当作无偏泛化结果。

## 16. 复现边界

上述公开仓库提供模型、示例和不同程度的训练/评估代码，但不等于完整原始预训练语料、清洗系统和大规模训练集群全部开放。

代码许可与模型许可分开阅读。早期DeepSeek-LLM/Coder相关仓库可能分别提供代码LICENSE与模型协议；不能把仓库元数据中的MIT标签自动套给所有权重和数据。

本节执行的是FIM拼接/语法、专家质量阈值等小例子的数学层，不宣称重训Coder或复现ESFT论文性能。真实模型实验还需检查硬件、依赖、数据和对应版本。

## 17. 自测与参考答案

**1. 为什么FIM看到suffix不一定是标签泄漏？** suffix在变换后的任务中就是给定条件，真正要预测的middle仍不可见；需要检查最终token顺序和mask。

**2. 语法解析通过是否说明代码正确？** 不说明，仍需行为测试、边界输入、依赖和资源预算。

**3. MoE激活参数2.4B是否只需存2.4B权重？** 不是，总模型权重和按需活动计算是不同口径。

**4. ESFT的top_p=0.7是否训练70%专家？** 不一定，它按累计分数质量选择，专家数量取决于分布。

**5. 冻结专家为什么仍可能需要输入梯度？** 上游可训练参数的梯度要穿过该专家函数，冻结权重不等于断开计算图。

**6. 专家选择应该用最终测试集吗？** 不应，否则选择过程已经使用测试信息，应另设选择/训练与独立测试集合。

**7. 专业化checkpoint为什么需要基座身份？** 只保存部分参数时，恢复依赖精确基座、专家映射与其他未更新模块。
