后训练要把预训练模型的能力转化为更好的回答、推理和工具行为。
它既是目标函数问题，也是数据、验证器、环境与模型版本协同的问题。

核对日期：2026-11-07。
本章从R1首版路线讲起，再进入V3.2、V4、V4.1和1017更新，避免将历史配方当成当前全部实现。

## 1. 后训练的数据闭环

```text
任务与环境
  -> 当前策略生成回答/工具动作
  -> 验证结果与行为
  -> 奖励、偏好或教师分布
  -> 训练更新
  -> 新策略
  -> 独立评估
```

每轮闭环都应能回答：数据由谁生成、反馈由谁给、哪些token参与loss、参数何时更新。

## 2. 四个专题

| 页面 | 重点 |
|---|---|
| 4.1 GRPO与R1 | 同题多答案、组优势、裁剪与阶段转换 |
| 4.2 Agent RL系统 | off-policy、sampling mask、routing replay与异步环境 |
| 4.3 Math与自验证 | 答案、形式化证明、verifier与meta-verifier |
| 4.4 蒸馏与1017 | 多教师OPD、全词表KL、合成数据与证据边界 |

数学细节与运行状态交替阅读，能避免只会写loss却无法正确组织训练数据。

## 3. 三类反馈来源

| 反馈 | 例子 | 主要风险 |
|---|---|---|
| 规则或执行结果 | 数学答案、代码测试 | 规则漏洞与覆盖不足 |
| 学习型评价器 | 偏好、证明分析 | 判断误差与奖励迎合 |
| 教师分布 | 每个prefix的logits | 教师偏差与状态失配 |

没有一种反馈天然适用于所有任务。
需要根据任务目标组合并验证。

## 4. R1-Zero与R1区别

R1-Zero从预训练Base直接进入推理RL实验。
R1增加冷启动和多阶段SFT/RL，使输出与能力更适合广泛使用。

Zero不意味着没有预训练。
R1也不等于只运行一次GRPO公式就能复现全部能力。

## 5. 一个始终要保留的版本账本

每条轨迹至少关联：

- prompt与数据版本。
- rollout checkpoint及采样参数。
- old logprob和有效动作mask。
- reward/teacher版本。
- 工具事件与环境快照。
- 训练使用的current checkpoint。

对于MoE和异步任务，还需要路由与分段版本信息。

## 6. 同一算法名可能有不同实现

原始GRPO常使用组均值和std进行标准化。
V3.2报告的优势采用减均值形式。

长度归一化、KL估计、mask范围和采样支持集也可能改变。
因此阅读时要记录具体公式，而不只写“使用GRPO”。

## 7. Agent轨迹比单轮回答多了什么

工具输出是环境观察，通常不是策略动作。
环境可能延迟、失败、超时或需要恢复。

模型更新后，一条长轨迹可能跨多个checkpoint继续生成。
这些状态让off-policy程度、样本长度偏差和恢复语义更加复杂。

4.2会用具体token和概率例子解释这些边界。

## 8. 验证也需要验证

最终答案对了，过程仍可能有漏洞。
verifier评分对了，理由仍可能是编造的。

Math-V2通过meta-verification和忠实自评奖励处理这一问题。
但学习型评价仍不等于形式化证明检查，需要独立质量核对。

## 9. 蒸馏不是只压缩参数

教师可以提供高质量轨迹，也可以在学生生成的prefix上给出全词表分布。
多教师系统可以把不同领域能力迁移给统一学生。

这要求处理教师选择、版本、词表、logits成本与异步数据生命周期。
4.4把这些问题连接到V4/V4.1公开配方。

## 10. 1017公开信息如何使用

官方公告确认自反馈RL与完整项目开发能力改进，并提供权重与模型卡。

公告没有公开完整内部loss、环境与训练数据。
本章会说明已知事实与合理教学抽象的分界，不把推测写成源码事实。

## 11. 学习验收

应能独立完成：

- 手算一组reward的优势。
- 分别解释正负优势的clip方向。
- 区分old policy与reference。
- 枚举验证重要性修正后的KL期望。
- 计算相同sampling mask下的概率比。
- 解释跨checkpoint routing replay。
- 手算Math-V2的忠实自评reward。
- 区分reverse KL与forward KL。
- 计算缓存teacher hidden相比logits的容量差。

每项都有对应专题中的数例与答案。
