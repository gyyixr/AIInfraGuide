模型架构规定计算图，预训练系统负责让这个图在有限显存、带宽和时间内可靠更新。
本章围绕一个训练step，连接低精度、流水调度、优化器和辅助预测目标。

核对日期：2026-11-07。
内容同时保留V3的FP8与DualPipe历史背景，并覆盖V4/V4.1的Muon、视觉训练与DSpark变化。

## 1. 一个训练step的主线

```text
读取样本并构造token/mask
  -> 按microbatch执行前向
  -> 主loss与辅助loss
  -> 反向dgrad/wgrad
  -> 跨microbatch与跨设备聚合
  -> optimizer更新
  -> 刷新计算副本
  -> 保存必要训练状态
```

每个箭头都可能有精度、通信和版本边界。
不能只看最终loss公式就认为训练实现已经明确。

## 2. 四个专题

| 页面 | 核心问题 |
|---|---|
| 3.1 FP8数值链路 | 哪些值量化，scale如何进入GEMM，哪些状态保留高精度 |
| 3.2 DualPipe/DualPipeV | forward、backward、wgrad和通信怎样合法交错 |
| 3.3 Muon与训练配方 | 矩阵更新如何计算，参数怎样分组，课程如何推进 |
| 3.4 MTP与DSpark | 多步预测监督如何对齐，draft如何单独训练 |

先读3.1与3.2，再读优化器和多目标训练，更容易理解系统约束。

## 3. 本章的统一小例子

一个线性层：

$$
Y=XW^\top.
$$

前向用到X和W。
反向需要计算dX与dW。
optimizer再把dW转换成参数更新。

FP8关心各次矩阵乘的数据格式。
流水调度关心这些运算何时执行。
Muon关心梯度矩阵如何变成更新矩阵。
MTP/DSpark关心梯度由哪些预测目标产生。

## 4. 四种状态不要混淆

| 状态 | 用途 |
|---|---|
| 计算副本 | 当前前向/反向使用的低精度参数 |
| master weight | 保留参数更新的高精度状态 |
| gradient buffer | 聚合当前step的梯度 |
| optimizer state | 记录跨step的动量等统计 |

一种状态使用FP8，不表示另外三种也应FP8。
一种优化器减少状态数量，也不自动减少所有通信。

## 5. 流水线不改变更新语义

可以重排互不依赖的工作。
可以延后wgrad以填补空闲。
可以用重计算换activation容量。

但当前step需要的梯度仍必须完整、正确聚合，optimizer边界不能任意提前。
重叠必须遵守数据就绪与buffer生命周期。

## 6. 数值与性能同时考虑

更小位宽减少传输和存储，可能增加量化与反量化工作。
更细scale改善数值范围，增加元数据与GEMM复杂性。
更多pipeline重叠减少空闲，可能增加参数与activation占用。

每个设计都有需要一起核算的资源维度。
本章会用明确的shape和算术展示这些交换。

## 7. V3、V4与V4.1不能合并成一套配方

V3报告以FP8混合训练和AdamW相关状态设计为重要部分。
V4使用Muon，并有dense到sparse的训练课程及联合MTP。
V4.1从较长序列的稀疏训练起步，引入head-wise Muon和大表Sinkhorn-balanced更新。

V4.1主干预训练后再训练DSpark，不沿用联合MTP描述。
每个版本的参数组、课程和辅助loss要单独记录。

## 8. 可以在本地验证什么

可以验证scale求和、梯度shape、矩阵归一化、优势权重和辅助目标shift。
也可以用小网络检查不同调度得到相同梯度。

这些都是有价值的正确性证据。
但不能把小实验称为复现32T或45T训练，也不能把逻辑调度图称为多机实测。

## 9. 阅读源码的顺序

先看配置与张量类型。
再看前向、反向和参数更新边界。
最后看通信、融合、编译和benchmark。

如果公开的是推理参考源码，应只把它用于解释对应数值与前向语义。
没有公开的训练控制部分保持论文级证据标注。

## 10. 学习验收

完成本章后，应能解释：

- 为什么不同K块的scale不能在GEMM最后统一乘一次。
- 为什么低精度计算还可能需要FP32 master。
- 为什么F&B不是F+B。
- 为什么DualPipe减少bubble也可能增加单卡容量压力。
- 为什么Muon不是只除一个整体norm。
- 为什么优化器Sinkhorn和mHC Sinkhorn不同。
- 为什么MTP目标必须按位置shift。
- 为什么DSpark置信度不是事实正确率。

每个问题都能在专题中的数例和答案里核对。
