模型计算之外，数据必须按时到达，训练状态必须可靠保存，agent环境必须可恢复。
本章把存储、数据处理、集群通信与sandbox放进同一条生命周期。

核对日期：2026-11-07。
3FS和smallpond以固定代码为主，Fire-Flyer与DSec的系统机制保留论文披露范围。

## 1. 四类长期或短期状态

| 状态 | 典型访问方式 | 重要要求 |
|---|---|---|
| 训练语料 | 大批读取、预处理与shuffle | 吞吐和数据版本 |
| checkpoint | 分片写入、恢复读取 | 一致快照与可验证提交 |
| 前缀KV | 请求相关的复用与逐出 | 版本、布局与恢复成本 |
| Agent环境 | 小文件、进程、cache与快照 | 隔离、状态和资源回收 |

它们可以共享底层资源，但不能用同一吞吐数字代表所有场景。

## 3. 从原始数据到训练样本

```text
原始文本/文档
  -> 解析与OCR等处理
  -> 过滤、去重与分区
  -> shuffle和物化结果
  -> 训练数据加载
  -> 模型更新与checkpoint
```

smallpond负责其中的数据计算与任务组织。
3FS提供共享文件和数据访问能力。

计算框架与存储系统相互配合，但不是同一个软件层。

## 4. 强一致不等于任意POSIX语义完整

3FS需要按具体对象与操作解释一致性。
文件长度、并发修改、metadata和数据访问路径仍有接口细节。

不能从“强一致”三个字推断任意应用的全部文件系统假设都成立。
7.1用chunk与chain状态解释实际读取和恢复行为。

## 5. 异步I/O需要足够在途数据

如果单次请求太小、并发太低，设备和网络可能无法饱和。
提高并发又需要更多buffer与请求状态。

例如32个在途请求，每个4MiB，单是数据buffer就是128MiB。
实际还可能有副本、对齐和metadata。

这连接吞吐、延迟与内存预算，而不是只追求最大队列深度。

## 6. 分区决定聚合语义

相同key是否被送到同一分区，影响group-by和join结果。
局部统计是否可合并，也要看保存了哪些充分信息。

例如两组大小分别1和9，其均值不能直接再平均得到总体均值。
需要同时保留sum和count，按总count聚合。

7.2通过无依赖例子先验证这些数学，再解释执行计划。

## 7. 恢复要知道重跑哪一层

任务级恢复可能重新执行某个分区任务。
训练恢复需要模型、optimizer和数据进度一致。
Agent恢复还涉及命令副作用与进程状态。

这些不是同一个checkpoint接口。
只保留最终输出文件名，通常不足以重建完整执行历史。

## 8. 共享网络会出现跨层争用

训练通信、数据读取和checkpoint写入可能竞争同一链路。
Fire-Flyer论文把PCIe、CPU、RDMA、并行策略与存储一起设计。

该经验绑定其10000张PCIe A100的历史环境。
不能直接当作V4.1当前推理集群的硬件配置。

## 9. 历史profile怎样使用

profile-data能展示指定设置下的计算通信重叠。
但其中MoE路由被人为平衡，训练片段还省略PP通信。

因此它适合学习时间线，不足以代表完整生产负载。
旧decode通信释放SM的描述，也不能倒用到当前DeepEP V2.5。

## 10. DSec关注环境生命周期

Agent等待模型时，CPU可能空闲，内存、文件cache和工作区仍然驻留。
DSec通过可组合镜像、按需读取、内存共享与回收提高环境密度。

训练被抢占时，还需要暂停和恢复agent执行状态。
只暂停进程不一定释放内存，只保存磁盘也不一定能恢复进程位置。

## 12. 三个问题与答案

**问题：磁盘顺序读很快，为什么sandbox首次命令仍慢？**

答案：metadata、小随机读取、冷缺页、镜像组合和进程初始化都可能成为瓶颈。

**问题：CPU利用率低，是否可以无限增加sandbox？**

答案：不能，内存、cache、磁盘和长期状态可能先达到上限。

**问题：HAI Platform源码公开，是否说明HFReduce和DSec都完整开放？**

答案：不说明，HAI位于HFAiLab组织，各组件的代码与论文范围必须单独核对。
