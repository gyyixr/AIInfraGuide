## 1. 实验目录与三种执行层次

配套文件位于 `labs/deepseek/`：

| 文件 | 作用 | 依赖 |
|---|---|---|
| `numerics.py` | 数学与状态oracle，打印/保存结果 | Python标准库 |
| `test_numerics.py` | 14项语义与数值检查 | Python标准库 |
| `mla_torch.py` | 完整投影与吸收路径的前向/梯度对照 | PyTorch |
| `verify_eplb.py` | 验证源码摘要后执行固定EPLB规划 | PyTorch与对应eplb.py |
| `results/` | 本次保留的实测JSON | 可直接阅读 |

标准库脚本不是官方GPU kernel的移植；MLA脚本使用普通PyTorch算子；只有EPLB实验直接执行了固定官方规划程序。它们的证据范围分别记录。

## 2. 第一步：运行不依赖 GPU 的检查

```bash
python3 -m unittest discover -s labs/deepseek -p 'test_*.py' -v
python3 labs/deepseek/numerics.py \
  --output labs/deepseek/results/latest-numerics.json
```

也可使用 `npm run test:deepseek`、`npm run lab:deepseek`。`latest-*.json` 是个人重跑输出，参考结果单独保留，便于对照而不相互覆盖。

下面解释这些检查为何有必要，而不只给一个“14 tests passed”。

## 3. 分块 scale：先恢复每个 K 块的贡献

输入矩阵与 scale 对应第6.1节。程序将分块乘法结果与“先完整反量化，再普通矩阵乘”的独立路径比较。

预期输出：

$$
D=\begin{bmatrix}10&15.5\\9.5&5\end{bmatrix}.
$$

这个对照能发现错误地将一个全局scale乘到所有K块的实现。它没有模拟FP8编码误差或GPU内部累积精度。

如果想扩展，先加入不同scale粒度和不整除块长的mask，再加入真实编码；不要一开始同时改变scale、dtype与布局。

## 4. Expanded layout：padding 与真实 token 数

给定 `psum=[3,9,12,14]`、alignment=4，输出有效区间：

```text
[0,3), [4,9), [12,12), [12,14)
```

对应真实计数 `[3,5,0,2]`。检查还包含不合法的倒退边界，避免静默把负区间传给下游。

它验证当前DeepEP expanded计数的解释方式，不执行真实dispatch或容量分配。真实系统还要检查tensor地址、stream、物理专家映射和句柄版本。

## 5. MoE：gate 的位置与输入梯度

第6.2节的两个token例子输出 `[5,7.2]`，对输入的导数为 `[2.5,2.4]`。

测试既检查最终输出，也检查每个展开任务中的专家和gate。这样能区分：

- 路由到了错误专家。
- gate没有应用或应用两次。
- combine没有恢复原token。
- 前向看似正确，但反向少合并了一条专家路径。

这些只是标量专家函数；完整MLP专家还要加入激活、矩阵梯度、共享专家和router参数的反向。

## 6. TopK：遍历全部块顺序

输入三个块有六种排列，脚本对全部排列检查选中值/索引集合相同。两种示例顺序的额外压缩工作量分别为17和11。

这说明随机块顺序改变执行工作，不改变该有限输入的正确TopK结果。

测试还拒绝NaN输入。这里是教学oracle主动定义的边界，不模拟DeepSelect设备kernel的trap行为，也不保证重复值的索引排序与任意GPU实现一致。

## 7. Sinkhorn：检查行、列与有界混合

对一个正方阵反复做行归一化、列归一化，测试检查最终行和、列和接近1。

进一步对向量 `[-3,1,2]` 做混合，结果的最大绝对值不超过3。这来自非负、行和为1的凸组合性质。

需要分清：

- 有限次Sinkhorn只能近似满足约束，容差和输入条件重要。
- 这不是完整mHC训练，未包含所有动态系数、残差流和梯度。
- 数值约束通过不等于模型质量或长期训练稳定性已经证明。

## 8. 物理页索引与 FP4 字节

页表 `[2,5]`、page size=4，逻辑token `[1,4,5]` 应转换成 `[9,20,21]`。

FP4例子检查低/高nibble顺序、符号和负零。`0x62` 在scale=0.5时得到 `[0.5,2]`，`0xF9`在scale=1时得到 `[-0.5,-6]`。

这些检查能帮助发现“整数合法但地址语义错误”与“字节长度正确但packing顺序错误”。真实kernel仍需对齐scale区域、stride和所选cache参数位置。

## 9. Attention sink 与 LSE

两项普通权重为1与3，value为2与6时，普通输出是5；加权重为2的零值sink后，输出变为 $10/3$。

测试确认返回的普通候选LSE不因sink缩放改变，符合本章所讨论接口的数学解释。

空集合时本脚本返回数学上的 `lse=-inf`；它刻意不将此混同于FlashMLA某路径的 `+inf` sentinel。测试真实接口时，需要额外的适配层解释有效计数和特殊返回值。

## 10. 投机采样与选择偏差

测试逐动作计算接受质量和残差质量，验证它们相加恢复目标分布，包括 p=q、目标含零概率等边界。

另一个测试保留错误调度的反例：

```text
target p = [0.6,0.4]
draft q  = [0.5,0.5]
错误规则：见A就接纳；见B就改成target重抽
最终分布 = [0.8,0.2]
```

这个反例说明不能在看到当前候选及其未来影响后，回头决定是否进入验证，而仍沿用原proposal概率。

生产异步历史confidence定容量的方案是另一种信息组织，见第5.3节；这里没有把所有动态调度都判为有偏。

## 11. Prefix 预算、缓存键与存储状态

### 11.1 验证预算

固定两请求confidence与假设容量曲线，因果前沿规划选择 `[1,1]` 个草稿位置，预计吞吐为288。它不是实际服务测量，SPS曲线是显式输入。

### 11.2 缓存键

测试确认编译flags顺序或ABI身份改变会改变教学key。使用SHA-256只是为了构造清楚的独立例子，不等于DeepJIT实际FNV摘要实现。

### 11.3 版本可见性

在三副本状态示意中，尾部已提交、前部仍有pending时，前部严格读取返回重试状态；确认回传后再读到新版本。

这个单进程状态模型没有模拟网络分区、lease、磁盘持久化和全部并发交错，不能作为3FS一致性协议的证明。

## 12. 第二步：PyTorch MLA 前向与反向

执行方式：

```bash
# 在能够import torch的解释器环境中
python labs/deepseek/mla_torch.py --device cpu \
  --output labs/deepseek/results/latest-mla-cpu.json

python labs/deepseek/mla_torch.py --device cuda \
  --output labs/deepseek/results/latest-mla-cuda.json
```

如果PyTorch安装在Conda等环境中，要用该环境的解释器；系统python没有torch不代表机器不能运行实验。

### 12.1 模型张量

| 张量 | Shape | 含义 |
|---|---|---|
| C | `[2,8,4]` | batch、历史序列、latent维 |
| Wk | `[2,4,6]` | head、latent、非RoPE key维 |
| Wv | `[2,4,5]` | head、latent、value维 |
| Q | `[2,3,2,6]` | batch、query、head、非RoPE维 |
| QR | `[2,3,2,4]` | 独立query RoPE分支 |
| KR | `[2,8,4]` | 历史RoPE key分支 |

Query位置为历史序列末尾三个位置，使用因果mask。随机输入在CPU由固定seed生成，再复制到所选设备。

### 12.2 两条独立计算路径

完整路径先构造 $K=CW_K$、$V=CW_V$，然后做attention。

吸收路径先构造 $QW_K^T$，直接与C点乘；attention对latent做加权，最后通过 $W_V$ 得到输出。

两条路径都保留单独的RoPE分支。损失取输出平方的均值，并比较对全部输入/权重张量的梯度。

只比较输出可能遗漏反向问题，因此这里将logits、output与grad分别记录。

## 13. 本次 CPU 与 RTX 3090 结果

使用PyTorch 2.13.0+cu132、float64，GPU为RTX3090/SM86，结果如下：

| 指标 | CPU | RTX3090 |
|---|---:|---:|
| logits最大绝对差 | $1.67\times10^{-16}$ | $1.11\times10^{-16}$ |
| output最大绝对差 | $1.11\times10^{-16}$ | $5.55\times10^{-17}$ |
| gradient最大绝对差 | $2.60\times10^{-18}$ | $2.60\times10^{-18}$ |
| 错误省略RoPE的输出差 | 约0.03613 | 约0.03613 |

负对照说明这组数据确实能识别漏掉位置分支的错误，而非两个空路径碰巧相等。

该实验规模极小，使用普通PyTorch算子，没有报告TFLOPS或模型吞吐；它证明的是指定合成计算图的数值关系。

## 14. 第三步：运行固定官方 EPLB 规划

准备官方仓库中固定commit的 `eplb.py` 后：

```bash
python labs/deepseek/verify_eplb.py \
  --source /path/to/pinned/EPLB/eplb.py \
  --output labs/deepseek/results/latest-eplb.json
```

脚本会先验证规范化源码的SHA-256，避免误将不同版本当作本节结果。它不自动下载或安装代码。

输入是逻辑负载 `[120,60,30,30]`，8个物理槽位、一个模拟节点、四个模拟GPU。实际规划在CPU执行，得到副本数 `[4,2,1,1]` 与预测负载 `[60,60,60,60]`。

“四个GPU”在这里是规划参数，不是启动了四块实际GPU；这种区分直接写入输出记录。

## 15. 怎样扩展而不混淆结论

| 下一步 | 新增检查 | 不能省略 |
|---|---|---|
| MLA换FP32/BF16 | 误差增长、梯度尺度、极端输入 | 不沿用float64容限 |
| 稀疏Attention | 选择集、mask、物理页和空行 | 与同一稀疏目标比较 |
| 官方kernel | ABI/layout/设备及完整测试 | 匹配目标架构 |
| 多进程EP | 前后向、事件、路由与buffer | collective顺序和故障边界 |
| 模型级 | PPL、任务质量、采样与模板 | 固定权重/tokenizer/数据 |

每一步保留最小失败输入。一次只引入一个新的变化，才能解释失败来自数学、数值、布局还是系统执行。

## 16. 自测与参考答案

**1. 为什么EPLB脚本传num_gpus=4却仍叫CPU实验？** 这个值描述规划目标拓扑，实际执行的是CPU算法，没有进行专家GPU计算。

**2. 为什么MLA梯度检查比只比输出更强？** 错误的detach、转置或梯度路径可能不影响某次前向值，却会改变训练更新。

**3. 为什么必须有省略RoPE等负对照？** 它确认给定输入和断言能区分重要错误，降低测试过于宽松或退化的风险。

**4. 14项测试通过能否证明新FlashMLA支持3090？** 不能，当前官方kernel支持矩阵独立于这些数学检查。

**5. 为什么结果记录写具体shape和dtype？** 数值容差和性能都依赖这些条件，不能从小float64例子推出大BF16模型结论。

**6. 如果CPU通过GPU失败，应该先改公式吗？** 先固定输入、dtype、后端和错误位置，检查设备访问、环境与数值差异；不能未定位就同时修改多个因素。
