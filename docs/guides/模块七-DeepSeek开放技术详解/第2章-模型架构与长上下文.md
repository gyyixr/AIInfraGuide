本章研究一个token如何进入DeepSeek模型、访问历史、选择专家、经过残差通路并产生下一token分布。
理解架构的目标，是能算清张量、缓存、依赖和边界，而不是记住缩写。

核对日期：2026-11-07。
历史机制以对应论文与固定源码为准；当前更新覆盖V4.1-Flash与1017参考配置。

## 1. 一条贯穿全章的数据流

```text
输入文本/图像
  -> embedding与视觉投影
  -> 残差流
  -> query与KV生成
  -> 历史选择与attention
  -> 专家路由与MoE
  -> 下一层残差
  -> 词表logits
```

跨token保存的状态主要包括KV、局部窗口和某些增量状态。
跨层共享的状态还包括CSA2全局KV、index K与top-k结果。

## 3. 本章统一符号

| 符号 | 含义 |
|---|---|
| B | batch或并发序列数 |
| S | 当前处理的新token数量 |
| T | 当前可见历史长度 |
| D | 主干hidden维 |
| H | query头数量 |
| r | latent低秩维 |
| W | sliding window大小 |
| k | 精读的top-k条目数 |
| m | 序列压缩比 |
| n | mHC残差流数量 |

不同论文的同一字母可能含义不同。
每节都重新给出shape，避免只按符号名字猜测。

## 4. 四种“压缩”不可混淆

MLA压缩每个位置的表示。
CSA/HCA压缩长期位置数量。
CSA2压缩层间重复状态。
FP4/FP8压缩每个数值的存储位宽。

这些维度可以组合，但副作用不同。
低秩与池化改变模型参数化，量化引入数值误差，跨层共享改变表示依赖。

## 5. 两种执行阶段

Prefill一次处理很多已知输入，形成后续生成要用的状态。
Decode每次只生成少量新token，并不断读取已有状态。

相同数学模型可能在两个阶段使用不同内核和计算布局。
例如MLA的展开路径与吸收路径，具有不同的矩阵形状和带宽需求。

## 6. 三种关键数量

**持久保存多少。**
决定KV或权重容量。

**每步读取多少。**
影响带宽需求。

**每步计算多少。**
影响FLOPs，但还要看算子形状与设备利用率。

少保存并不必然少计算，少计算也不必然低延迟。
每节会把这几项分别讨论。

## 7. 本章的数值实验是什么

小矩阵吸收检查、路由手算、softmax归一化、Sinkhorn迭代和字节账本，都属于数学与状态语义验证。

它们不要求下载数百GB权重。
也不能因此声称复现了大模型训练质量或多GPU服务性能。

## 8. 两个必须记住的反例

稀疏attention只保留部分位置后，需要重新归一化softmax，输出一般会改变。

SWA Bounded Replay只重放窗口长度，截断跨层局部依赖，通常不等价于完整prefill。

把这些近似当成严格恒等变换，会使后续缓存和质量分析出错。

## 9. 源码阅读方法

先读实际模型config，不把dataclass小模型默认值当正式模型。
再按输入shape逐行追踪投影、reshape、mask、缓存写入和输出。

最后才看kernel融合、并行分片和性能benchmark。
如果不知道一个cache由哪一层产生、何时能被读取，很难判断优化是否正确。

## 10. 学习验收

读完应能独立完成：

- 算出V3经典MLA的每层latent缓存维度。
- 手算带负载校正bias的top-k专家选择与输出权重。
- 解释DSA为何仍有indexer全历史扫描。
- 画出V4-Flash的CSA/HCA与局部窗口关系。
- 证明双随机矩阵不等于单位矩阵。
- 解释图像1344×1344如何得到1024个视觉特征。
- 区分CED encoder与decoder的SWA回放。
- 算出Engram每token查表向量数量。
- 从Full层与FP4格式推导890 bytes/token。

这些任务都在对应专题中有逐步答案。
